# 第2章 架构级低功耗设计策略

## 2.1 引言

架构级低功耗设计是指在芯片的系统架构规划阶段，通过合理的架构选择和设计策略来降低整体功耗。架构级决策对芯片最终功耗的影响可达50%以上，远大于后续门级和物理级优化的贡献。因此，在芯片架构定义阶段就充分考虑功耗优化，是低功耗设计成功的关键。

本章从处理器架构、存储子系统、互连架构、数据通路和系统级电源管理五个维度，系统性地介绍架构级低功耗设计策略。

## 2.2 处理器架构的低功耗策略

### 2.2.1 大小核异构架构 (big.LITTLE / Heterogeneous)

异构多核架构是当前移动SoC最主流的低功耗策略之一，由ARM big.LITTLE架构首先推广。

**核心思想：**
- 将不同微架构复杂度的处理器核心集成在同一SoC中
- 高性能大核（Big Core）处理计算密集型任务
- 高能效小核（LITTLE Core）处理轻量级日常任务
- 根据负载动态调度任务到合适的核心

**典型配置示例：**

| 配置方案 | 大核 | 小核 | 应用场景 |
|----------|------|------|----------|
| 4+4 | 4× Cortex-A78 | 4× Cortex-A55 | 旗舰手机SoC |
| 2+6 | 2× Cortex-A78 | 6× Cortex-A55 | 中端手机SoC |
| 1+3 | 1× Cortex-A76 | 3× Cortex-A55 | IoT网关芯片 |
| 4+4+4 | 4× X4 | 4× A720 + 4× A520 | 三丛集架构 |

**功耗收益分析：**
- 轻量负载场景下，使用小核可节省60%~80%的功耗
- 小核面积仅为大核的1/3~1/5，漏电功耗相应更低
- 任务迁移的开销远小于持续使用大核的功耗损失

**调度策略：**

```
工作负载分析
    │
    ├── CPU利用率 < 30% ──→ 仅小核运行
    │
    ├── 30% < CPU利用率 < 70% ──→ 小核满载 + 部分大核
    │
    └── CPU利用率 > 70% ──→ 全部核心运行
```

### 2.2.2 流水线深度优化

流水线深度直接影响处理器的频率和功耗特性。

**深流水线 vs 浅流水线：**

| 特性 | 深流水线 (>15级) | 浅流水线 (<10级) |
|------|-----------------|-----------------|
| 最大频率 | 高 | 低 |
| 单周期功耗 | 低（每级逻辑少）| 高（每级逻辑多）|
| 总功耗(同性能) | 较高（流水线开销）| 较低 |
| 分支惩罚 | 大 | 小 |
| 面积开销 | 大（更多寄存器）| 小 |
| 适用场景 | 高频高性能 | 低功耗嵌入式 |

**低功耗流水线设计原则：**

1. **避免过深流水线**：流水线寄存器本身消耗功耗，级数过多时寄存器功耗可占总功耗的15%~25%
2. **平衡各级延迟**：各级延迟不均衡会导致频率受限于最慢级，其余级能量浪费
3. **适当的转发路径**：减少流水线停顿，避免因停顿导致的无效功耗消耗
4. **推测执行的功耗代价**：深流水线依赖推测执行，分支预测失败时的冲刷浪费大量能量

### 2.2.3 指令级功耗优化

#### (1) 操作数隔离 (Operand Isolation)

当功能单元在某些周期不需要工作时，冻结其输入以避免无效翻转：

```
// 未优化：ALU每个周期都接收新输入并计算
always @(posedge clk) begin
    alu_result <= alu_op(operand_a, operand_b);
end

// 优化后：仅在需要时让ALU计算
always @(posedge clk) begin
    if (alu_enable) begin
        alu_result <= alu_op(operand_a, operand_b);
    end
end
```

**功耗节省**：对不活跃的功能单元可节省30%~50%的动态功耗。

#### (2) 数据编码优化

数据总线的翻转率直接影响动态功耗，合适的数据编码可降低翻转：

| 编码方案 | 原理 | 适用场景 | 翻转率改善 |
|----------|------|----------|-----------|
| 格雷码 (Gray Code) | 相邻值仅1位翻转 | 计数器、地址 | 大幅改善 |
| 总线反转编码 (Bus-Invert) | 翻转超半数位时取反 | 数据总线 | ~25%改善 |
| 字典编码 (Dictionary) | 高频模式用短码 | 压缩接口 | 可变 |
| 差分编码 | 传输差值而非绝对值 | 连续数据流 | 显著改善 |

#### (3) 指令融合与宏操作

- 将多条简单指令融合为一条宏操作执行
- 减少指令解码和执行的次数，降低动态功耗
- 例如：比较+分支融合、加载+运算融合

### 2.2.4 推测执行的功耗管理

推测执行（Speculative Execution）是现代高性能处理器的关键技术，但也是重要的功耗来源。

**功耗浪费来源：**
- 分支预测失败时，已推测执行的指令全部作废
- 高端处理器中，推测执行可能浪费10%~20%的总功耗
- 预取的无用缓存行消耗存储器带宽和功耗

**优化策略：**

1. **置信度估计器**：仅对高置信度分支进行推测执行
2. **受限推测深度**：限制推测执行的最大指令数
3. **选择性推测**：仅对关键路径进行推测，非关键路径等待确认
4. **动态调整**：根据分支预测准确率动态调整推测策略

## 2.3 存储子系统的低功耗策略

存储子系统（缓存、内存控制器、片上SRAM等）通常占芯片总功耗的30%~50%，是功耗优化的重点区域。

### 2.3.1 缓存架构优化

#### (1) 缓存分级与容量选择

```
                    ┌──────────────────────┐
                    │   处理器核心 (Core)    │
                    └──────────┬───────────┘
                               │
                    ┌──────────▼───────────┐
                    │   L1 Cache (32~64KB) │  ← 最快，功耗最高/访问
                    │   延迟: 1~4 cycles   │
                    └──────────┬───────────┘
                               │
                    ┌──────────▼───────────┐
                    │  L2 Cache (256KB~1MB) │  ← 中等速度和功耗
                    │   延迟: 8~15 cycles   │
                    └──────────┬───────────┘
                               │
                    ┌──────────▼───────────┐
                    │  L3 Cache (2MB~32MB)  │  ← 较慢，共享，功耗分摊
                    │   延迟: 20~40 cycles  │
                    └──────────┬───────────┘
                               │
                    ┌──────────▼───────────┐
                    │   主存储器 (DRAM)      │  ← 最慢，功耗最高/总量
                    │   延迟: 80~200 cycles │
                    └──────────────────────┘
```

**缓存容量的功耗权衡：**
- 更大缓存 → 更高命中率 → 减少高功耗的外部存储访问
- 更大缓存 → 更大面积 → 更高漏电功耗
- 最优缓存容量取决于工作负载的数据集大小和访问模式

#### (2) 路预测与部分标签比较

传统组相联缓存每次访问需要读取所有Way的Tag和Data，功耗较大。

**Way Prediction（路预测）：**
- 预测最可能命中的Way，仅读取该Way的Data
- 预测正确时节省约60%~75%的缓存读取功耗
- 预测失败时增加1个周期延迟，读取其余Way

**分步访问 (Phased Access)：**
- 第一步：读取所有Way的Tag进行比较
- 第二步：仅读取命中Way的Data
- 相比并行读取所有Way的Data，可节省约50%~70%的Data Array功耗

#### (3) 缓存行大小优化

| 缓存行大小 | 优势 | 劣势 |
|------------|------|------|
| 小 (32B) | 减少无用数据预取 | 空间局部性利用不足 |
| 中 (64B) | 平衡点，最常用 | — |
| 大 (128B) | 空间局部性好 | 可能预取大量无用数据 |

**自适应缓存行大小：**
- 根据数据访问模式动态选择缓存行大小
- 流式数据访问使用大行，随机访问使用小行

### 2.3.2 Scratchpad Memory (SPM) 架构

与缓存不同，SPM是软件显式管理的片上存储器。

**SPM vs Cache 功耗对比：**

| 特性 | Cache | Scratchpad Memory |
|------|-------|-------------------|
| 管理方式 | 硬件自动 | 软件显式 |
| Tag存储 | 需要（额外面积和功耗）| 不需要 |
| 功耗效率 | 低（Tag比较、替换策略）| 高（直接地址访问）|
| 面积效率 | 低 | 高（无Tag开销）|
| 编程复杂度 | 低（透明）| 高（需DMA管理）|
| 适用场景 | 通用处理器 | DSP、AI加速器 |

**SPM在AI加速器中的应用：**
- 权重和激活值通过DMA显式加载到SPM
- 消除了缓存Tag比较的功耗开销
- 可精确控制数据复用，最大化数据局部性
- 功耗可比等效缓存降低40%~60%

### 2.3.3 DRAM访问优化

外部DRAM访问是最耗能的存储操作之一，一次DRAM读取的能量约为L1 Cache访问的100~200倍。

**优化策略：**

1. **访问合并 (Access Coalescing)**
   - 将多次对同一DRAM行的访问合并
   - 减少DRAM行激活/预充电的次数

2. **DRAM Bank交织 (Bank Interleaving)**
   - 连续地址分布在不同Bank中
   - 允许一个Bank预充电时访问另一个Bank
   - 提高带宽利用率，减少等待功耗

3. **刷新优化**
   - 部分刷新 (Partial Refresh)：仅刷新使用中的Bank/Row
   - 温度补偿刷新：低温时降低刷新频率
   - 自刷新模式：空闲时进入低功耗自刷新状态

4. **低功耗DRAM模式**
   - LPDDR标准专为低功耗优化
   - 支持多种低功耗状态（Deep Power Down, Self Refresh等）
   - LPDDR5相比LPDDR4功耗降低约20%

## 2.4 互连架构的低功耗策略

片上互连网络（NoC/Bus）负责各模块间的数据传输，其功耗在大型SoC中可占总功耗的10%~30%。

### 2.4.1 总线架构优化

#### (1) 分层总线 (Hierarchical Bus)

```
           ┌──────────────────────────────────────┐
           │        高速主总线 (High-Speed Bus)      │
           │   CPU, GPU, DMA ← → 内存控制器          │
           └──────┬───────────────┬────────────────┘
                  │               │
        ┌─────────▼─────┐  ┌─────▼──────────┐
        │  外设子总线 1   │  │  外设子总线 2    │
        │  UART,SPI,I2C │  │  USB,SDIO,ETH  │
        └───────────────┘  └────────────────┘
```

**功耗优势：**
- 低速外设不加载高速主总线
- 各子总线可独立时钟门控
- 跨层桥接器可缓冲速度差异

#### (2) 总线宽度与频率权衡

```
相同带宽: 128-bit × 500MHz = 64-bit × 1GHz
```

| 方案 | 频率 | 位宽 | 动态功耗 | 面积 |
|------|------|------|----------|------|
| 宽总线 | 低 | 宽 | 较低(f低) | 大 |
| 窄总线 | 高 | 窄 | 较高(f高) | 小 |

低功耗场景通常选择较宽的总线配合较低的频率，因为动态功耗与频率成线性关系。

### 2.4.2 片上网络 (NoC) 功耗优化

对于大型SoC（多核处理器、AI芯片），NoC取代传统总线成为主流互连方案。

#### (1) 拓扑选择

| 拓扑结构 | 功耗特点 | 适用规模 | 示例 |
|----------|---------|---------|------|
| 环形 (Ring) | 低功耗，延迟随节点数增加 | 小规模(<8核) | Intel Ring Bus |
| Mesh | 功耗中等，可扩展性好 | 中大规模(8~64核) | Tile-based AI芯片 |
| 树形 (Tree) | 根节点瓶颈 | 层次化设计 | 缓存一致性互连 |
| 交叉开关 (Crossbar) | 高功耗，无阻塞 | 小规模(<16端口) | 共享缓存互连 |

#### (2) NoC功耗优化技术

1. **虚拟通道优化**
   - 减少不必要的虚拟通道数量
   - 每个虚拟通道的缓冲区都消耗功耗
   - 根据实际流量模式调整虚拟通道配置

2. **路由器微架构优化**
   - 推测性路由 (Speculative Routing)：减少路由器流水线级数
   - Bypass路径：低负载时跳过缓冲区直接转发
   - 路由器电源关断：空闲路由器进入低功耗模式

3. **链路功耗优化**
   - 低摆幅信号传输 (Low-Swing Signaling)
   - 串行化链路 (SerDes)：减少线数，降低线电容
   - 链路编码：减少翻转率

### 2.4.3 AXI/ACE总线协议的低功耗特性

ARM AMBA协议族提供了多种低功耗机制：

| 协议特性 | 低功耗机制 | 说明 |
|----------|-----------|------|
| AXI QoS | 带宽控制 | 限制非关键传输带宽，降低总线活动 |
| AXI Low-Power IF | 时钟/电源控制 | CSYSREQ/CSYSACK握手进入低功耗 |
| ACE Snoop Filter | 减少侦听 | 避免不必要的缓存一致性广播 |
| AXI Outstanding | 乱序完成 | 减少总线空闲等待时间 |

## 2.5 数据通路的低功耗架构策略

### 2.5.1 计算精度自适应

不同应用场景对计算精度有不同需求，过高的精度意味着不必要的功耗浪费。

**混合精度计算架构：**

| 精度 | 位宽 | 功耗比(相对FP32) | 应用场景 |
|------|------|-----------------|----------|
| FP32 | 32-bit | 1.0× | 训练、高精度推理 |
| FP16 | 16-bit | ~0.25× | 推理、部分训练 |
| BF16 | 16-bit | ~0.25× | 训练（范围大）|
| INT8 | 8-bit | ~0.06× | 量化推理 |
| INT4 | 4-bit | ~0.02× | 极致低功耗推理 |

**自适应精度策略：**
- 训练阶段使用FP32/BF16混合精度
- 推理阶段使用INT8/INT4量化
- 同一芯片支持多精度模式，按需切换
- 精度降低带来近似平方级的功耗降低（位宽减半，乘法器面积约为1/4）

### 2.5.2 数据复用与计算调度

减少数据搬运是降低功耗的核心策略之一。在AI加速器中，数据搬运的能耗远大于计算本身。

**数据搬运 vs 计算的能耗对比（45nm工艺参考值）：**

| 操作 | 能耗 (pJ) | 相对倍数 |
|------|----------|---------|
| INT8 乘法 | 0.2 | 1× |
| INT8 加法 | 0.03 | 0.15× |
| 读 SRAM (8KB) | 5 | 25× |
| 读 SRAM (32KB) | 20 | 100× |
| 读 DRAM | 640 | 3200× |

**数据流架构优化：**

1. **权重固定 (Weight Stationary)**
   - 权重驻留在PE（处理单元）内部寄存器
   - 输入数据和部分和在PE间流动
   - 适合权重复用率高的场景（如全连接层）

2. **输出固定 (Output Stationary)**
   - 部分和累积在本地寄存器
   - 权重和输入数据流入
   - 减少部分和的搬运，适合卷积层

3. **行固定 (Row Stationary)**
   - 将卷积行映射到PE阵列的行
   - 最大化所有类型数据的复用
   - 如MIT Eyeriss架构，能效比传统架构提升2~3倍

### 2.5.3 近似计算架构

在可容忍一定精度损失的应用中，近似计算可显著降低功耗。

**近似计算策略：**

| 策略 | 原理 | 功耗节省 | 精度损失 |
|------|------|---------|---------|
| 截断乘法器 | 截断低位乘积 | 30~50% | <2% |
| 近似加法器 | 限制进位传播距离 | 20~40% | <1% |
| 存储器近似读取 | 降低读放大器灵敏度 | 15~25% | 可控 |
| 神经网络剪枝 | 移除冗余连接 | 40~60% | <1% (经微调) |

## 2.6 系统级电源管理策略

### 2.6.1 电源状态机设计

系统级电源管理需要定义清晰的电源状态和转换关系。

**典型电源状态定义：**

```
┌─────────┐     ┌──────────┐     ┌──────────┐     ┌──────────┐
│  Active  │────▶│  Idle    │────▶│  Sleep   │────▶│  Deep    │
│  (全速)   │◀────│ (空闲)   │◀────│  (浅睡)  │◀────│  Sleep   │
│          │     │          │     │          │     │  (深睡)   │
└─────────┘     └──────────┘     └──────────┘     └──────────┘
  功耗:高          功耗:中         功耗:低           功耗:极低
  延迟:无          延迟:ns级       延迟:μs级         延迟:ms级
```

**各状态特征对比：**

| 状态 | 时钟 | 电源 | 状态保持 | 典型功耗 | 唤醒延迟 |
|------|------|------|----------|---------|---------|
| Active | ON | ON | 完整 | 100% | 0 |
| Idle | 门控 | ON | 完整 | 30~50% | ~ns |
| Sleep | OFF | 降低/部分ON | 保持寄存器 | 5~15% | ~μs |
| Deep Sleep | OFF | OFF (部分) | 仅关键状态 | 1~5% | ~100μs |
| Power Off | OFF | OFF | 无 | <1% | ~ms |

### 2.6.2 工作负载预测与自适应管理

智能电源管理需要预测未来的工作负载，提前进行电源状态调整。

**预测算法分类：**

1. **基于历史的预测**
   - 最近空闲周期长度预测下一次空闲长度
   - 指数移动平均 (EMA) 平滑预测
   - 简单有效，硬件开销小

2. **基于阈值的策略**
   - 空闲超过阈值T1 → 进入Sleep
   - 空闲超过阈值T2 → 进入Deep Sleep
   - 阈值需考虑状态转换的能量开销（Break-even时间）

3. **基于机器学习的预测**
   - 使用轻量级神经网络预测工作负载模式
   - 可学习复杂的周期性和突发性模式
   - 适合软件层面的电源管理器（如Linux CPUFreq Governor）

**Break-even时间计算：**

```
T_break_even = E_transition / (P_active - P_sleep)
```

- E_transition：进入和退出低功耗状态消耗的总能量
- P_active 和 P_sleep：两种状态的功耗
- 仅当预计空闲时间 > T_break_even 时，才值得进入低功耗状态

### 2.6.3 任务调度与功耗感知

操作系统和固件层面的任务调度对系统功耗有显著影响。

**功耗感知调度策略：**

1. **任务合并 (Task Consolidation)**
   - 将任务集中到少数核心上执行
   - 空闲核心可完全关断，最大化节能
   - 需平衡性能和功耗

2. **Race-to-Idle**
   - 以最高性能尽快完成任务
   - 然后尽快进入深度睡眠状态
   - 适合突发性任务场景（如手机屏幕刷新）

3. **DVFS协同调度**
   - 根据任务需求动态调整频率和电压
   - 计算密集型任务：高频高压
   - I/O密集型任务：低频低压（CPU大部分时间在等待）

4. **热感知调度 (Thermal-Aware Scheduling)**
   - 监控各核心温度
   - 将任务迁移到温度较低的核心
   - 避免热点，减少因温度导致的漏电增加

## 2.7 架构级功耗评估方法

### 2.7.1 早期功耗建模

在架构定义阶段，需要快速评估不同架构选择的功耗影响。

**常用建模方法：**

| 方法 | 输入 | 精度 | 速度 | 典型工具 |
|------|------|------|------|----------|
| 分析模型 | 架构参数 | ±30~50% | 秒级 | 自研Excel/Python |
| McPAT/CACTI | 架构配置 | ±20~30% | 分钟级 | 开源学术工具 |
| IP目录功耗数据 | IP规格书 | ±15~20% | 分钟级 | IP供应商提供 |
| 虚拟平台仿真 | SystemC模型 | ±15~25% | 小时级 | Synopsys Platform Architect |
| FPGA原型验证 | FPGA映射 | ±10~15% | 实时 | FPGA板级测量 |

### 2.7.2 架构设计空间探索 (DSE)

架构级设计空间探索通过参数化扫描找到功耗最优的架构配置。

**关键探索维度：**

```
架构设计空间
├── 核心数量与类型 (1~16核, 大/小核比例)
├── 缓存层次 (L1/L2/L3大小, 相联度)
├── 互连拓扑 (Bus/Ring/Mesh)
├── 存储带宽 (LPDDR4/5, 通道数)
├── 计算精度 (FP32/FP16/INT8)
├── 电压域划分 (单域/多域)
└── 频率范围 (最大频率, DVFS档位)
```

**探索流程：**

1. 定义设计约束（功耗预算、性能目标、面积限制）
2. 参数化架构模板
3. 运行工作负载Benchmark
4. 收集PPA数据
5. Pareto最优分析
6. 选择最优架构配置

## 2.8 实际案例分析

### 2.8.1 移动SoC低功耗架构设计案例

**设计目标：** 面向智能手机的应用处理器，功耗预算3W (TDP)

**架构决策：**

| 决策项 | 选择 | 功耗考量 |
|--------|------|----------|
| CPU配置 | 1×A78 + 3×A55 | 覆盖高低负载，小核处理日常任务 |
| GPU | Mali-G78 MP4 | 支持DVFS，游戏时满载 |
| NPU | 2TOPS INT8 | 专用加速器替代CPU/GPU处理AI任务 |
| L2 Cache | 512KB/核 | 平衡命中率和漏电 |
| L3 Cache | 2MB 共享 | 减少DRAM访问 |
| 内存 | LPDDR5 双通道 | 低功耗DRAM标准 |
| 互连 | NoC (Ring) | 核数少，Ring延迟可接受 |
| 电压域 | 5个独立域 | CPU/GPU/NPU/IO/Always-on |

**功耗分布估算：**

```
总功耗预算: 3W (TDP)
├── CPU (1×A78): 0.8W (27%)
├── CPU (3×A55): 0.5W (17%)
├── GPU: 0.7W (23%)
├── NPU: 0.3W (10%)
├── 内存控制器: 0.3W (10%)
├── NoC + 其他: 0.2W (7%)
└── IO + PLL: 0.2W (7%)
```

### 2.8.2 AI推理加速器低功耗架构案例

**设计目标：** 边缘AI推理芯片，功耗预算500mW

**关键架构策略：**
- 使用INT8/INT4混合精度计算，避免FP32的高功耗
- 采用SPM替代Cache，消除Tag开销
- Row Stationary数据流最大化数据复用
- 片上SRAM容量设计覆盖典型模型的权重
- 支持模型稀疏化，跳过零值计算

## 2.9 本章小结

本章系统性地介绍了架构级低功耗设计策略，核心要点包括：

1. **处理器架构**：异构多核是最有效的系统级低功耗策略；流水线深度、推测执行等微架构特征对功耗有显著影响
2. **存储子系统**：缓存层次优化和DRAM访问优化是功耗关键；SPM在专用加速器中比Cache更节能
3. **互连架构**：分层总线和NoC设计需要平衡带宽需求和功耗；总线宽度和频率的权衡影响功耗
4. **数据通路**：混合精度计算可带来显著功耗降低；数据复用策略（Weight/Output/Row Stationary）是AI加速器节能的核心
5. **系统级管理**：多级电源状态、工作负载预测和功耗感知调度是系统级功耗优化的关键手段
6. **早期评估**：架构级功耗建模和设计空间探索帮助在早期做出最优的PPA决策
