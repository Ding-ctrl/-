# 第36章 嵌入式固件级低功耗编程

## 概述

硬件做好了低功耗设计，固件写得不好同样会让电池续航大打折扣。本章深入嵌入式固件层，从裸机编程到RTOS优化，系统讲解固件工程师在低功耗领域必须掌握的技能——这是硬件低功耗设计与实际产品功耗表现之间的关键桥梁。

## 36.1 微控制器低功耗模式的深度理解

### 36.1.1 睡眠模式的层次结构

以ARM Cortex-M系列为例，睡眠模式从浅到深：

```
┌──────────────────────────────────────────────────────────┐
│ 模式         │ 唤醒时间  │ 典型功耗    │ 保持状态          │
├──────────────┼──────────┼───────────┼──────────────────┤
│ Run          │ N/A      │ 10-50mA   │ 完整             │
│ Sleep        │ 1-5μs    │ 1-10mA    │ CPU停止，外设运行 │
│ Stop/Deep    │ 10-100μs │ 10-100μA  │ RAM保持，时钟停止 │
│ Standby      │ 100μs-5ms│ 1-10μA    │ 仅RTC/WKUP引脚   │
│ Shutdown     │ 1-10ms   │ 0.1-1μA   │ 仅唤醒引脚       │
└──────────────┴──────────┴───────────┴──────────────────┘
```

**关键认识：** 唤醒时间和功耗之间存在根本性权衡。选择睡眠深度必须基于应用的实际唤醒频率和延迟容忍度。

### 36.1.2 功耗模式的实际编程

**STM32 Stop模式示例（HAL库）：**
```c
// 进入Stop模式前的准备工作（关键步骤）
void enter_stop_mode(void) {
    // 1. 确保所有DMA传输完成
    while (HAL_DMA_GetState(&hdma_usart1_tx) == HAL_DMA_STATE_BUSY);
    
    // 2. 禁用不需要的外设时钟
    __HAL_RCC_USART1_CLK_DISABLE();
    __HAL_RCC_SPI1_CLK_DISABLE();
    
    // 3. 配置唤醒源（RTC闹钟或外部中断）
    HAL_RTCEx_SetWakeUpTimer_IT(&hrtc, 0x1000, RTC_WAKEUPCLOCK_RTCCLK_DIV16);
    
    // 4. 配置GPIO为模拟模式（减少漏电）
    GPIO_InitTypeDef GPIO_InitStruct = {0};
    GPIO_InitStruct.Mode = GPIO_MODE_ANALOG;
    GPIO_InitStruct.Pull = GPIO_NOPULL;
    GPIO_InitStruct.Pin = GPIO_PIN_ALL;
    HAL_GPIO_Init(GPIOB, &GPIO_InitStruct);
    
    // 5. 进入Stop模式（REGULATOR_LOWPOWER = 使用低功耗稳压器）
    HAL_PWR_EnterSTOPMode(PWR_LOWPOWERREGULATOR_ON, PWR_STOPENTRY_WFI);
    
    // ↑ 执行到这里时CPU挂起，直到唤醒事件发生
    
    // 6. 唤醒后恢复系统时钟（Stop模式会关闭PLL）
    SystemClock_Config();
}
```

**常见错误：** 忘记在进入低功耗模式前将未使用的GPIO设为模拟输入模式，导致GPIO的输入施密特触发器持续漏电（每个IO引脚约2-5μA，32个引脚累计超过100μA）。

### 36.1.3 漏电的隐藏来源

```
GPIO漏电排查清单：
□ 悬空输入引脚（无上下拉）→ 在高低电平之间浮动 → 内部施密特触发器持续漏电
□ 上拉电阻接到断电的外设VCC → 电流从MCU流向外设的GND
□ SPI/I2C总线悬空 → 外设不响应，总线维持在未定义状态
□ 晶振负载电容的漏电（关闭晶振后必须同时关闭负载电容的供电路径）

典型量化（STM32L4系列，Shutdown模式）：
理论最低功耗：0.2μA
GPIO处理不当实测：15-50μA（超出理论值100倍以上）
```

## 36.2 RTOS的低功耗Tickless机制深度解析

### 36.2.1 传统Tick的功耗代价

标准RTOS（如FreeRTOS）使用SysTick定时器产生周期性中断：
```
默认配置：1ms Tick（1000Hz）
每秒中断次数：1000次
每次中断：CPU必须退出Sleep → 处理中断 → 返回Sleep
过程耗时：~10μs（取决于上下文切换时间）

实际等效：
1ms周期中，10μs处于Run模式，990μs理论上可睡眠
占空比：1% Run + 99% Sleep
但频繁的唤醒切换导致MCU无法进入深度睡眠（Stop/Standby）
实测：Sleep模式功耗 vs 能进入Stop模式的功耗差距达10倍以上
```

### 36.2.2 FreeRTOS Tickless Idle实现原理

```c
/* FreeRTOS Tickless Idle Hook（需要在FreeRTOSConfig.h中启用）*/
#define configUSE_TICKLESS_IDLE    2  // 2 = 使用用户自定义的低功耗方案

/* 在port.c或单独的low_power_port.c中实现 */
void vPortSuppressTicksAndSleep(TickType_t xExpectedIdleTime) {
    // 计算实际可睡眠时长（考虑下一个任务唤醒时间）
    uint32_t sleep_ms = xExpectedIdleTime * portTICK_PERIOD_MS;
    
    // 配置RTC唤醒定时器替代SysTick
    uint32_t rtc_reload = ms_to_rtc_ticks(sleep_ms - 1); // -1为唤醒裕量
    HAL_RTCEx_SetWakeUpTimer_IT(&hrtc, rtc_reload, RTC_WAKEUPCLOCK_RTCCLK_DIV16);
    
    // 挂起SysTick（进入睡眠前必须停止）
    portNVIC_SYSTICK_CTRL_REG &= ~portNVIC_SYSTICK_ENABLE_BIT;
    
    // 进入Stop模式
    HAL_PWR_EnterSTOPMode(PWR_MAINREGULATOR_ON, PWR_STOPENTRY_WFI);
    
    // 唤醒后：补偿OS时间（更新Tick计数）
    TickType_t elapsed = rtc_get_elapsed_ticks();
    vTaskStepTick(elapsed);
    
    // 重新使能SysTick
    portNVIC_SYSTICK_CTRL_REG |= portNVIC_SYSTICK_ENABLE_BIT;
}
```

### 36.2.3 Tickless模式的常见陷阱

**陷阱1：定时器精度损失**
```
Stop模式下LSE晶振精度：±20ppm
睡眠10秒后，时间误差：10s × 20×10⁻⁶ = 200μs
对于需要精确时序的应用（如Bluetooth连接间隔），200μs误差可能导致连接断开

解决：使用更高精度的外部晶振，或在唤醒后通过网络时间同步校正
```

**陷阱2：串口数据丢失**
```
UART接收数据时进入Stop模式：
如果UART RX引脚已经开始接收字节但Stop模式关闭了时钟
→ 当前字节的剩余bit无法被采样
→ 数据损坏

解决：使用能从Stop模式唤醒的LPUART（低功耗UART），
      它内部有独立的16MHz时钟运行，不受Stop模式影响
```

**陷阱3：任务重入问题**
```
Tickless睡眠时，多个任务同时到期（Timer Group到期）
→ 唤醒后，vTaskStepTick补偿的Tick数跨越多个任务到期点
→ 所有到期任务会在同一时刻被调度
→ 若这些任务竞争同一资源，可能死锁

解决：确保任务优先级分配合理，避免多高优先级任务同时到期
```

## 36.3 低功耗应用设计模式

### 36.3.1 事件驱动架构（Event-Driven Architecture）

低功耗应用的黄金法则：**CPU只在有事情做的时候才醒来**

```c
// 反模式：轮询（Polling）—— 高功耗
void bad_pattern(void) {
    while (1) {
        if (sensor_data_ready()) {
            process_sensor_data();
        }
        // CPU持续在Run模式运行，大量时间在"等待"
    }
}

// 正确模式：中断驱动 + WFI
void good_pattern(void) {
    // 配置传感器数据就绪中断
    configure_sensor_irq(sensor_data_ready_callback);
    
    while (1) {
        // 处理所有待处理事件
        while (event_pending()) {
            process_next_event();
        }
        
        // 没有事情做 → 进入睡眠，等待中断
        __WFI();  // Wait For Interrupt
    }
}

void sensor_data_ready_callback(void) {
    // 中断服务：仅发布事件，不做复杂处理
    post_event(EVENT_SENSOR_DATA_READY);
}
```

### 36.3.2 功耗状态机设计

为复杂应用设计明确的功耗状态机：

```
┌───────────────────────────────────────────────────────┐
│                     功耗状态机                         │
│                                                        │
│  ┌─────────┐  数据处理完成  ┌──────────┐              │
│  │  ACTIVE  │──────────────>│  IDLE    │              │
│  │  ~20mA   │<──────────────│  ~2mA    │              │
│  └─────────┘  中断/事件到来 └────┬─────┘              │
│                                  │ 30秒无活动          │
│                                  ▼                     │
│                            ┌──────────┐               │
│  ┌─────────┐  长时间无连接  │  SLEEP   │               │
│  │SHUTDOWN │<──────────────│  ~50μA   │               │
│  │  ~1μA   │  按键/传感器  └──────────┘               │
│  └─────────┘──────────────────────────>ACTIVE         │
└───────────────────────────────────────────────────────┘
```

### 36.3.3 无线通信协议栈的低功耗配置

BLE（蓝牙低功耗）连接参数优化：

```c
// BLE连接参数：直接影响平均功耗
ble_gap_conn_params_t conn_params = {
    .min_conn_interval = MSEC_TO_UNITS(100, UNIT_1_25_MS),  // 100ms最小间隔
    .max_conn_interval = MSEC_TO_UNITS(200, UNIT_1_25_MS),  // 200ms最大间隔
    .slave_latency     = 4,     // 允许跳过4个连接事件（无数据时）
    .conn_sup_timeout  = MSEC_TO_UNITS(4000, UNIT_10_MS),   // 4秒超时
};

// 计算理论平均电流：
// 连接间隔200ms，每次连接事件持续~1ms，工作电流~15mA，睡眠电流~3μA
// 平均电流 = (1/200) × 15mA + (199/200) × 3μA ≈ 75μA + 2.97μA ≈ 78μA
```

## 36.4 固件级功耗调试工具

### 36.4.1 硬件辅助功耗分析

**方法一：串联精密电阻+示波器**
```
VDD ──── 1Ω精密电阻 ──── MCU VCC
            ↑
         示波器CH1测量两端电压
         V = I × R → I = V/1Ω
         分辨率：1mV/格 = 1mA/格
         带宽限制：无（适合毫秒级功耗变化）
```

**方法二：专业功耗分析仪（Nordic PPK2, Otii Arc）**
```
优点：
- 动态范围：100nA到500mA（单仪器覆盖）
- 采样率：100ksps（可捕获10μs级功耗脉冲）
- 软件可标注代码执行段（通过GPIO触发）
- 可直接计算平均功耗和电池寿命预测

使用示例（Otii Arc）：
1. 将Otii Arc的电源输出连接到目标板
2. 在代码中用GPIO标记关键代码段的开始/结束
3. 实时查看每个代码段的功耗曲线和积分能量
```

### 36.4.2 软件层面的功耗追踪

```c
// 使用SWO/ITM输出功耗追踪信息（ARM Cortex-M）
#ifdef POWER_DEBUG
    #define POWER_MARKER_ENTER(id)   ITM->PORT[id].u8 = 0xAA
    #define POWER_MARKER_EXIT(id)    ITM->PORT[id].u8 = 0x55
#else
    #define POWER_MARKER_ENTER(id)   do {} while(0)
    #define POWER_MARKER_EXIT(id)    do {} while(0)
#endif

void sensor_read_task(void) {
    POWER_MARKER_ENTER(0);      // 标记：传感器读取开始
    i2c_read(SENSOR_ADDR, buf, len);
    POWER_MARKER_EXIT(0);       // 标记：传感器读取结束
    
    POWER_MARKER_ENTER(1);      // 标记：数据处理开始
    process_sensor_data(buf);
    POWER_MARKER_EXIT(1);       // 标记：数据处理结束
}
```

## 36.5 实战案例：IoT传感器节点的功耗优化

### 目标
将BLE传感器节点的平均电流从500μA降至100μA以下，实现1年以上的CR2032电池续航。

### 优化前分析

```
功耗分解（优化前）：
睡眠期间：
  MCU Stop模式：25μA（GPIO未配置）→ 应为1μA
  传感器待机电流：50μA → 应为5μA（使用EN引脚关断）
  BLE SoC睡眠：10μA

连接事件（200ms间隔，1ms活跃）：
  BLE通信：15mA × (1ms/200ms) = 75μA等效

传感器采样（每5秒一次，持续50ms）：
  ADC+传感器：2mA × (50ms/5000ms) = 20μA等效

总计：约180μA
```

### 优化措施

```c
// 优化1：修复GPIO配置（停止模式前）
void configure_gpio_for_stop(void) {
    // 将所有未使用GPIO设为模拟输入（最低漏电）
    GPIO_InitTypeDef GPIO_InitStruct = {GPIO_PIN_ALL, GPIO_MODE_ANALOG, 
                                         GPIO_NOPULL, GPIO_SPEED_FREQ_LOW, 0};
    HAL_GPIO_Init(GPIOA, &GPIO_InitStruct);
    HAL_GPIO_Init(GPIOB, &GPIO_InitStruct);
    // ... 其他端口
}

// 优化2：传感器使用EN引脚控制（彻底断电）
void sensor_power_down(void) {
    HAL_GPIO_WritePin(SENSOR_EN_GPIO, SENSOR_EN_PIN, GPIO_PIN_RESET);
    // 等待传感器完全断电（确保电容放电）
    HAL_Delay(1);
}

// 优化3：减少BLE广播包大小（减少每次广播时间）
// 原始广播数据：30字节 → 传输时间2ms
// 优化后：12字节（仅关键传感器数据）→ 传输时间0.8ms
```

### 优化结果

```
优化后功耗分解：
睡眠期间：
  MCU Stop模式：1μA（GPIO正确配置）
  传感器：0.5μA（通过EN引脚完全断电）
  BLE SoC睡眠：3μA

连接事件（200ms间隔，0.8ms活跃）：
  BLE通信：15mA × (0.8ms/200ms) = 60μA等效

传感器采样（每5秒一次，持续30ms）：
  ADC+传感器：2mA × (30ms/5000ms) = 12μA等效

总计：约77μA（从500μA降至77μA，降低85%）

CR2032容量：225mAh
理论续航：225mAh / 77μA = 2922小时 = 4个月
```

> 进一步将BLE连接间隔从200ms增加到500ms，可再将平均电流降至约40μA，实现超过8个月的续航。

## 本章小结

固件层低功耗是硬件低功耗设计发挥作用的关键环节：
- **GPIO配置**是最容易忽视、收益最高的单项优化（正确配置可减少100μA+漏电）
- **Tickless Idle**是RTOS平台必不可少的优化，错误实现有多个常见陷阱
- **事件驱动架构**是低功耗应用设计的根本原则
- **量化测量工具**是发现功耗问题的必要手段，靠猜测无法有效优化
