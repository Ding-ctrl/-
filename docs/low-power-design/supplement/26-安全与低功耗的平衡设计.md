# 第26章 安全与低功耗的平衡设计

## 26.1 引言

随着芯片在物联网、汽车电子、金融支付、医疗设备等安全敏感场景中的大规模部署，**硬件安全**已成为现代SoC不可或缺的核心能力。然而，安全机制几乎无一例外地带来额外的功耗代价：加密运算消耗算力、随机数生成需要高熵源、侧信道防护引入冗余操作、安全监控需要常开电路。

**安全与功耗的根本矛盾：**

```
安全性 ↑
  └─ 更强加密（AES-256 vs AES-128）    → 功耗 ↑
  └─ 更多防护（掩码、随机化、噪声）    → 功耗 ↑
  └─ 持续监控（篡改检测、安全启动）    → 功耗 ↑
  └─ 物理隔离（TrustZone、TEE）        → 面积/功耗 ↑

低功耗约束 ↓
  └─ 电池供电IoT设备（毫瓦级预算）     → 安全妥协 ?
  └─ 快速休眠（安全上下文保存/恢复）   → 延迟↑或功耗↑
  └─ 工作电压降低（近阈值计算）        → 安全漏洞↑（可靠性）
```

本章系统介绍密码算法硬件加速与低功耗优化、侧信道攻击防护与功耗代价、安全启动与信任根设计、物理不可克隆函数（PUF）、安全元件（SE）架构，以及轻量级密码的能效特征，帮助读者在安全性与功耗之间找到最优平衡点。

## 26.2 密码算法的功耗特征

### 26.2.1 主流密码算法计算量对比

```
常用密码算法的计算复杂度与功耗:

对称加密:
  算法        │ 分组/密钥 │ 轮数 │ 操作类型   │ 相对功耗
  ────────────┼──────────┼──────┼───────────┼──────────
  AES-128     │ 128/128  │ 10   │ S盒+线性变换│ 1×（基准）
  AES-256     │ 128/256  │ 14   │ 同上       │ 1.4×
  ChaCha20    │ 流密码   │ 20轮 │ ARX（无S盒）│ 0.8×（软件）
  PRESENT     │ 64/80    │ 31   │ 超轻量S盒  │ 0.15×（硬件）
  SIMON       │ 32-128   │ 可变 │ AND/XOR/循环│ 0.1×（轻量）
  SPECK       │ 32-128   │ 可变 │ ARX        │ 0.08×（轻量）

非对称加密（典型128bit安全级别）:
  算法        │ 操作         │ 相对功耗（vs AES-128）
  ────────────┼─────────────┼────────────────────────
  RSA-2048    │ 模幂运算     │ ~10000×（软件实现）
  ECC-256     │ 标量乘法     │ ~500×（软件实现）
  ECC-256     │ 硬件加速     │ ~50×
  Ed25519     │ 签名/验签    │ ~200×（软件）/ ~20×（硬件）
  CRYSTALS-Kyber│ 格密码（PQC）│ ~100×（软件）/ ~10×（硬件）

哈希函数:
  SHA-256     │ ~0.3× vs AES（软件）│ ~0.1×（硬件）
  SHA-3/Keccak│ ~0.5×（软件）       │ ~0.15×（硬件）
  BLAKE3      │ ~0.15×（软件，并行优化）
```

### 26.2.2 AES硬件加速能效

```
AES加密的硬件实现策略对比:

1. 软件实现（MCU, 32位 Cortex-M4, 120MHz）:
   AES-128加密一块（16字节）：~240周期
   吞吐：~8 Mbps
   功耗：~30mW → 能效：~0.27 Mbps/mW

2. 查表实现（T-table）:
   利用预计算查找表减少操作
   速度：~2× 软件实现
   代价：需要4KB查找表（缓存命中率影响功耗）
   侧信道风险：查表时序依赖于数据（易受缓存攻击）

3. 硬件AES加速器（28nm CMOS）:
   面积：~12,000 GE（门等效）
   AES-128加密：1块/周期（完全流水线）
   吞吐：10Gbps@1GHz
   功耗：~5mW → 能效：~2000 Mbps/mW
   与软件相比：7000× 能效提升

4. 轻面积AES加速器（IoT优化版）:
   面积：~3,400 GE（串行架构）
   吞吐：1块/320周期（串行）
   功耗：< 1mW@100MHz
   能效：低于流水线版，但面积小8×

AES轮密钥扩展的功耗优化:
  传统：每次加密重新扩展密钥（11×128bit = 176字节）
  预计算：密钥固定时，提前展开并存储
  收益：消除密钥扩展功耗（约占总加密功耗15%）
```

### 26.2.3 椭圆曲线密码（ECC）低功耗实现

```
ECC标量乘法（kP运算）的低功耗优化:

ECC-256安全级别，标量乘法的运算分解:
  点加（Point Addition）：~15次域乘法
  倍点（Point Doubling）：~10次域乘法
  256次迭代（二进制算法）：~256 × 12次 ≈ 3072次域乘法
  每次GF(p)域乘法（256位）：约10μs（8MHz MCU）
  总时间：~30ms，功耗~15mW
  能量：~450 mJ（对于低功耗设备极其昂贵）

低功耗优化策略:

1. Montgomery梯形算法（侧信道安全+高效）:
   恒定时间执行（防时序攻击），适合软件
   效率提升：vs 二进制法约2× 速度提升

2. 射影坐标（Projective Coordinates）:
   将仿射坐标(x,y)变换为射影坐标(X:Y:Z)
   消除昂贵的域除法（变为域乘法）
   速度提升：~3-5×（比直接仿射坐标快）

3. 专用ECC硬件加速器:
   面积：~50,000 GE（含ECDH和ECDSA）
   ECC-256签名：< 1ms
   功耗：~5mW（工作时）
   能量：< 5μJ/签名（vs 软件的450mJ，节省10000×！）

4. 轻量曲线选择:
   Curve25519 / Ed25519：专为高效实现设计
   运算量：比P-256少约20-30%
   安全性：与P-256相当（128位安全级别）
```

## 26.3 侧信道攻击与防护的功耗代价

### 26.3.1 侧信道攻击原理

```
侧信道攻击（Side-Channel Attack）分类:

1. 简单功耗分析（SPA, Simple Power Analysis）:
   观察单次执行的功耗波形
   直接读取密钥比特（RSA私钥方幂运算）
   防护成本：低（恒定时间实现）

2. 差分功耗分析（DPA, Differential Power Analysis）:
   收集大量功耗迹（通常>1000次）
   统计分析找出与密钥相关的功耗差异
   对AES/DES最有效
   防护成本：中-高（掩码技术）

3. 相关功耗分析（CPA, Correlation Power Analysis）:
   基于功耗模型（汉明重量/距离）
   比DPA更高效（需要更少迹）
   防护：掩码 + 随机化

4. 电磁分析（EMA）:
   探头贴近芯片，收集EM辐射
   比功耗分析更难防御
   防护：金属屏蔽、随机延迟

5. 故障注入（Fault Injection）:
   激光、电压毛刺、时钟毛刺
   使电路出错并观察错误输出
   防护：冗余计算、错误检测

攻击设备成本:
  DPA套件（商业）：$50,000-$200,000
  DIY DPA（开源）：~$500-$2,000（ChipWhisperer等）
  → 低成本攻击是IoT安全的重要威胁
```

### 26.3.2 掩码技术（Masking）

```
布尔掩码（Boolean Masking）防御DPA:

基本思想：将敏感变量x分成d+1份
  x = x₁ ⊕ x₂ ⊕ ... ⊕ x_{d+1}  (⊕ = XOR)
  
  任意单独的 xᵢ 不包含关于x的信息
  攻击者需要同时获取所有份额才能还原x

一阶掩码（d=1）：2份，x = x₁ ⊕ r（r是随机数）
  防护：可抵御一阶DPA
  功耗代价：约2× 原始实现
  缺点：不能抵御高阶DPA

二阶掩码（d=2）：3份
  防护：可抵御二阶DPA
  功耗代价：约3-4× 原始实现

AES-128一阶掩码硬件实现对比:
  无掩码AES-128：
    面积：12,000 GE，功耗：5mW
  一阶布尔掩码AES-128：
    面积：35,000 GE（+190%），功耗：12mW（+140%）
    随机数生成器（RNG）：额外 +2mW

  代价总结：安全性+1阶 → 面积3×，功耗2.4×

高效掩码实现优化:
  1. 掩码S盒（Masked S-Box）重用：
     预计算多个掩码S盒变体，运行时随机选择
     面积折中，功耗不成倍增加
  2. 阈值实现（Threshold Implementation）:
     信息论安全，可证明的一阶安全
     最少份额数：d+1（d阶保护）
     是目前学术界和工业界最严格的标准方案
  3. 随机延迟（Random Delay）:
     在操作序列中插入随机时钟延迟
     使攻击者难以对齐功耗迹
     低功耗代价（~10%），但不能完全防DPA
```

### 26.3.3 功耗随机化技术

```
降低信噪比（SNR）对抗统计攻击:

1. 随机时钟抖动（Clock Jitter Insertion）:
   ┌──────────────────────────────────────────┐
   │  正常时钟 ──→ 可调抖动源 ──→ 加密电路   │
   │                  ↑                       │
   │            TRNG控制（随机抖动量）         │
   │                                          │
   │  效果：功耗迹时间轴随机化，需更多迹对齐  │
   │  防御级别：使所需迹数增加10-100×         │
   │  功耗代价：TRNG ~0.5mW，几乎可忽略       │
   └──────────────────────────────────────────┘

2. 虚假操作（Dummy Operations）:
   在真实加密操作中插入虚假的不相关操作
   攻击者无法区分哪些迹对应哪一步
   功耗代价：~50-100%（额外操作占真实操作比例）

3. 双轨逻辑（Dual-Rail Logic / Differential Logic）:
   ┌──────────────────────────────────────────┐
   │  每个信号用正/负互补对表示               │
   │  无论输出0还是1，同时翻转一正一负        │
   │  功耗恒定（每个操作功耗与数据无关）      │
   │                                          │
   │  代表：WDDL（Wave Dynamic DL）          │
   │                   MDPL（Masked DPL）    │
   │                                          │
   │  面积代价：2-3×（两倍走线和单元）       │
   │  功耗：相对固定，泄露信息极少           │
   └──────────────────────────────────────────┘

4. 功耗平坦化（Power Flattening）:
   使用电容储能和电流调节
   对外呈现恒定电源电流
   硬件开销：额外稳压/恒流电路
   功耗代价：平坦化电路自身约10-20%额外功耗
```

## 26.4 真随机数生成器（TRNG）

### 26.4.1 TRNG的作用与功耗

```
TRNG（True Random Number Generator）在安全系统中的地位:

用途：
  密钥生成（最关键！弱随机数→密钥可预测）
  掩码随机数（防DPA的核心资源）
  协议随机数（nonce, challenge-response）
  密码学填充（padding randomness）

TRNG物理熵源类型:

1. 环形振荡器（Ring Oscillator, RO）TRNG:
   ┌──────────────────────────────────────────┐
   │  利用奇数个反相器构成振荡器              │
   │  振荡器频率的热噪声抖动作为随机源        │
   │  采样低频RO对高频RO的边沿位置            │
   │                                          │
   │  优点：CMOS友好，易于集成，面积小        │
   │  缺点：环境相关（温度、电压影响），     │
   │       需要连续健康测试                   │
   │  典型功耗：100μW - 1mW（视RO数量）      │
   │  吞吐率：1-100Mbps（后熵提取处理后）    │
   └──────────────────────────────────────────┘

2. 热噪声（Shot Noise）TRNG:
   放大电阻热噪声信号，比较输出作为随机位
   功耗：~100μW（放大器功耗）
   高质量但需要模拟电路

3. SRAM PUF作为TRNG（两用）:
   上电时SRAM的随机初始状态作为随机源
   功耗：几乎0（利用上电过程）
   但随机质量通常低于专用TRNG

超低功耗TRNG设计（IoT场景）:
  挑战：连续运行功耗过高，按需唤醒
  策略：按需产生随机数时才唤醒TRNG
         唤醒时间 + 填充内部缓冲（128-256bit）
         然后关闭直到缓冲耗尽
  典型功耗：平均 <50μW（低速率IoT）
```

### 26.4.2 TRNG的统计质量评估

```
TRNG质量评估标准（NIST SP 800-90B）:

主要健康测试（在芯片上实时执行）:
  1. 重复计数测试（Repetition Count Test）:
     检测连续重复的相同比特（卡住故障）
     硬件实现：~50 GE，几乎无功耗

  2. 自适应比例测试（Adaptive Proportion Test）:
     检测统计偏差（0和1的比例失衡）
     滑动窗口统计，~200 GE

  3. 后处理（熵提取）：
     SHA-256哈希压缩：将低质量原始位转为高质量输出
     AES-CTR-DRBG：NIST推荐的确定性随机比特生成器

完整TRNG子系统功耗预算（安全MCU）:
  熵源（RO阵列）：  ~200μW（常开）
  健康测试逻辑：    ~20μW（数字）
  SHA-256后处理：   ~500μW（触发执行时）
  DRBG状态机：      ~100μW
  总计（活跃）：    ~800μW
  睡眠（仅健康测试）：~220μW
```

## 26.5 物理不可克隆函数（PUF）

### 26.5.1 PUF原理与低功耗特性

```
PUF（Physical Unclonable Function）— 利用制造差异产生唯一指纹:

工作原理:
  利用芯片制造时的随机工艺变化（沟道长度、阈值电压等）
  相同设计的两颗芯片，PUF响应完全不同
  但同一颗芯片的响应在相同条件下高度重现

  输入"激励"（Challenge）→ PUF → 输出"响应"（Response）
  每颗芯片都有独特的CRP（Challenge-Response Pair）对

PUF的核心优势（vs 传统密钥存储）:
  传统NVM密钥存储：密钥存储在Flash/eFuse中
    风险：可被物理提取（FIB攻击）
    功耗：NVM读取 ~10-100μW，写入更高

  PUF密钥：根据物理特性在线重建，不永久存储
    优点：无法物理提取，每次上电动态重建
    功耗：仅在需要密钥时唤醒PUF测量
```

### 26.5.2 主流PUF类型

```
PUF类型对比:

1. SRAM PUF:
┌─────────────────────────────────────────────────┐
│  原理：SRAM上电时，双稳态cell随机偏向0或1       │
│  强度：弱PUF（固定响应，N个cell→N bit密钥）    │
│  唯一性：相邻cell差异率~50%（理想）             │
│  可靠性：~95-99%（温度/电压变化导致偶尔翻转）   │
│  需要纠错码（BCH/Reed-Solomon）恢复准确密钥     │
│                                                 │
│  低功耗特征：                                   │
│  上电时测量：< 1μs，额外功耗几乎为零           │
│  纠错计算：~1ms MCU时间，~0.1mJ                │
│  密钥不存储 → 不需要NVM写入功耗                │
│                                                 │
│  代表产品：NXP i.MX RT（SRAM PUF内置）         │
└─────────────────────────────────────────────────┘

2. 仲裁器PUF（Arbiter PUF）:
┌─────────────────────────────────────────────────┐
│  原理：两条平行延迟路径的竞争（哪条先到达）    │
│  可配置激励 → 输出1bit响应                    │
│  强度：强PUF（2^N个激励，支持认证协议）        │
│  面积：~1000 GE（64位激励），小巧              │
│  功耗：~100μW（仲裁测量期间）                 │
│  挑战：可被机器学习攻击（需要XOR混叠加强）     │
└─────────────────────────────────────────────────┘

3. 环形振荡器PUF（RO-PUF）:
┌─────────────────────────────────────────────────┐
│  原理：比较两个RO的频率差异（工艺变化导致）    │
│  简单可靠，面积适中                            │
│  功耗：~500μW（RO运行时），超出后关断          │
│  与TRNG同构，可复用硬件                        │
└─────────────────────────────────────────────────┘
```

### 26.5.3 PUF辅助密钥生成流程

```
PUF密钥重建完整流程（以SRAM PUF为例）:

注册阶段（出厂一次，芯片测试）:
┌──────────────────────────────────────────────────┐
│  1. 上电读取SRAM PUF初始状态（2048bit原始响应）  │
│  2. 应用纠错编码（BCH码，纠5bit错误）           │
│     生成"辅助数据"（Helper Data, ~3000bit）     │
│  3. 辅助数据存储到非易失存储（Flash/eFuse）     │
│     注意：辅助数据本身不泄露PUF响应！           │
│  4. SHA-256(PUF响应) → 注册密钥哈希（存服务器） │
└──────────────────────────────────────────────────┘

重建阶段（每次上电，低功耗关键路径）:
┌──────────────────────────────────────────────────┐
│  1. 上电读取SRAM（~1μs，功耗极低）              │
│  2. 读取Flash中的辅助数据                       │
│  3. BCH解码（纠错）→ 重建可靠PUF响应           │
│  4. SHA-256 → 256位设备唯一密钥                │
│  5. 密钥送入AES-256密钥寄存器（RAM存储）        │
│  6. 清除SRAM（擦除原始PUF测量值）              │
└──────────────────────────────────────────────────┘

能量分析:
  SRAM上电测量：  ~5μJ（含上电时间）
  BCH解码：       ~0.5μJ（数字计算）
  SHA-256：       ~0.1μJ（硬件加速）
  总计：          ~5.6μJ/次密钥重建

  对比NVM密钥读取（eFuse读取）：~10μJ/次（含时序）
  PUF方案功耗更低 + 安全性更高！
```

## 26.6 安全启动与信任根

### 26.6.1 安全启动流程与功耗

```
安全启动（Secure Boot）功耗分析:

完整安全启动链:
  ROM（硬编码公钥哈希） → 验证Bootloader签名
  Bootloader → 验证OS Kernel签名
  OS Kernel → 验证应用签名

每级验证的操作:
  1. 读取固件（Flash/eMMC）
  2. 计算SHA-256哈希（约1MB → ~10ms, ~5mW = 50μJ）
  3. RSA-2048或ECDSA-256签名验证
     RSA-2048（软件）：~500ms@100MHz → ~50mJ（极高！）
     ECDSA-256（软件）：~50ms@100MHz → ~5mJ
     ECDSA-256（硬件加速）：~1ms → ~0.1mJ

优化安全启动功耗:

1. 硬件加密加速器:
   SHA-256加速：100× 速度提升 → 100× 功耗效率提升
   ECDSA验证加速：50× → 从5mJ降到0.1mJ

2. 签名算法选择:
   Ed25519 > ECDSA-256 > RSA-2048（功耗由低到高）
   Ed25519硬件加速：~0.05mJ/次验证

3. 增量验证（Delta Verification）:
   仅验证变化的固件块（OTA更新场景）
   避免全量哈希计算

4. 并行验证:
   多核SoC：CPU验证Bootloader同时，
           安全协处理器验证OS Kernel
   减少启动时间 → 降低启动能耗

典型嵌入式MCU安全启动能耗:
  无硬件加速：~60mJ/次启动（影响电池寿命）
  有硬件加速：~2mJ/次启动
  优化后提升：30×
```

### 26.6.2 TrustZone与TEE的功耗影响

```
ARM TrustZone安全架构功耗分析:

TrustZone工作原理:
  处理器分为安全世界（Secure World）和正常世界（Normal World）
  通过SMC（Secure Monitor Call）切换

功耗影响因素:
  1. 世界切换（World Switch）开销:
     每次切换：~100-500 CPU周期（状态保存/恢复）
     典型切换频率：10-100次/秒（DRM、支付等）
     功耗代价：< 0.1%（可忽略）

  2. TEE操作系统（OP-TEE等）开销:
     常驻安全内存：~256KB（secure SRAM）
     功耗：轻微（内存保持功耗）

  3. 安全加密操作（DRM解密、支付PIN验证）:
     在TEE中运行AES、ECDSA等
     功耗与普通加密相同（只是在安全上下文中）

  4. 安全存储访问:
     加密写回到Flash → 额外I/O + AES功耗
     每次安全存储访问：~1ms, ~0.5mW = ~0.5μJ

TrustZone功耗优化策略:
  减少TEE进入次数（批量安全操作）
  TEE内部使用硬件加速器（共享）
  安全世界的后台任务使用低优先级（避免连续高功耗）
```

## 26.7 轻量级密码学（Lightweight Cryptography）

### 26.7.1 NIST轻量级密码标准

```
NIST轻量级密码标准化（LWC，2023年最终选择ASCON）:

ASCON密码族（NIST LWC获选算法）:
  算法：ASCON-128, ASCON-128a, ASCON-Hash
  设计目标：IoT/嵌入式设备的轻量级认证加密

ASCON vs AES-128-GCM 硬件实现对比（CMOS 65nm）:
  指标           │ AES-GCM         │ ASCON-128
  ───────────────┼─────────────────┼──────────────
  面积（GE）     │ ~15,000         │ ~2,800 (-81%)
  吞吐率         │ 高              │ 中等
  功耗（mW）     │ ~8mW            │ ~1.5mW (-81%)
  能效（μJ/块）  │ ~0.8            │ ~0.15 (-81%)
  安全级别       │ 128位           │ 128位（相当）

轻量级密码设计原则:
  1. 小S盒（4位 vs AES的8位）→ 面积和功耗更小
  2. 比特切片（Bit-slicing）→ 适合低面积实现
  3. 基于置换（Permutation-based）→ 设计简洁
  4. 减少轮数（但通过更宽状态维持安全性）

适用场景：
  超低功耗传感器节点：<1mW预算
  RFID/NFC标签：数百μW
  医疗植入设备：<500μW
  工业IoT：资源受限微控制器
```

### 26.7.2 超低功耗场景的密码选择

```
不同功耗预算下的密码方案选择指导:

功耗预算 < 10μW（纽扣电池，超低功耗传感器）:
  ├── 对称加密：SIMON/SPECK（纯软件，超低面积）
  ├── MAC：HMAC-SHA256的软件实现（触发执行）
  ├── 密钥交换：避免在线非对称运算
  └── 策略：预共享密钥（PSK），避免运行时公钥运算

功耗预算 10-100μW（BLE信标，IoT传感器）:
  ├── 对称加密：ASCON 或 AES-128（硬件加速器，低功耗）
  ├── 哈希：ASCON-Hash 或 SHA-256（硬件加速）
  ├── 认证：ECDSA-256（仅偶尔，深度睡眠间歇运行）
  └── 策略：尽量减少非对称运算次数

功耗预算 100μW - 10mW（智能卡，NFC设备）:
  ├── 完整TLS/DTLS协议（ECDH密钥协商）
  ├── AES-128/256（硬件加速，常用）
  ├── Ed25519签名（硬件加速，高效）
  └── PUF辅助密钥存储

功耗预算 > 10mW（智能手机、网关设备）:
  ├── 所有标准密码（AES, RSA-2048, ECC, SHA-3）
  ├── 后量子密码（CRYSTALS-Kyber, CRYSTALS-Dilithium）
  └── 完整PKI支持

后量子密码（PQC）的功耗代价:
  CRYSTALS-Kyber-768（密钥封装）:
    软件：~1ms（Cortex-M4）
    硬件加速：~0.1ms，~0.5mJ
    vs ECC-256：~5× 更慢，~3× 更多能耗
  设计影响：PQC将成为未来强制要求，功耗预算需预留余量
```

## 26.8 安全监控与反篡改

### 26.8.1 主动式安全监控功耗

```
反篡改（Anti-Tamper）监控机制:

主动网格（Active Mesh / Shield）:
┌──────────────────────────────────────────────────┐
│  芯片顶层金属：密集蛇形导线网格                  │
│  持续传输随机信号并检测是否被切断                │
│  物理穿透→导线断开→检测到攻击                   │
│                                                  │
│  功耗：~0.5-2mW（连续运行）                     │
│  安全级别：防御微探针攻击                        │
│  适用：高安全HSM、银行卡芯片                    │
└──────────────────────────────────────────────────┘

传感器阵列（Sensor Array）:
  电压传感器（防VCC毛刺攻击）：~10μW
  频率传感器（防时钟故障注入）：~10μW
  温度传感器（防低温攻击）：~20μW
  光线传感器（防开盖攻击）：~5μW
  总计：~45μW（持续运行）

低功耗监控策略:
  深度睡眠模式下，部分传感器进入超低功耗模式
  电压/频率监控：采样间隔可延长到1ms（降低功耗）
  光线/开盖传感器：必须持续开启（不可妥协！）
  攻击检测后：立即触发密钥清除 + 芯片锁定
```

### 26.8.2 密钥清除（Key Zeroization）

```
密钥清除 — 安全的最后防线（功耗无关，时间关键）:

场景：检测到物理攻击 → 必须在攻击者读出密钥前清除

密钥清除策略:
  1. SRAM密钥清除：
     写入全0（或随机值）覆盖
     速度：~10ns/字（硬件DMAØ触发）
     256位密钥：~80ns → 极快，功耗不是问题

  2. Flash eFuse密钥：
     无法清除（一次性编程）
     → 应避免将高价值密钥存入eFuse
     → 使用PUF重建密钥（无需存储）

  3. 电容保持电路（Backup Capacitor）:
     外部断电攻击时，电容维持内部电压
     保持时间：毫秒级（足够触发密钥清除）
     额外功耗：~10μW（电容维持充电）

  4. 全局电源开关（Kill Switch）:
     检测到攻击时切断VDD_CRYPTO
     所有加密状态瞬间丢失（< 1μs）
     无需显式写零

低功耗设计约束:
  密钥清除路径必须独立于主电源域
  使用小电容备份 + 独立低功耗检测器
  整个清除电路预算：~50μW（常开）
```

## 26.10 安全-功耗协同设计方法论

### 26.10.1 安全设计中的功耗建模

```
安全功能的功耗建模框架:

安全级别分类（参考NIST FIPS 140-3）:
  Level 1：软件安全，无物理保护需求
  Level 2：防篡改证据（物理封装）
  Level 3：防篡改响应（检测+清除）
  Level 4：完整物理保护（全方位监控）

各安全级别功耗预算模型:

  Level 1（软件安全）:
    附加硬件功耗：~0mW
    软件安全开销：算法依赖（见26.2节）

  Level 2（防篡改证据）:
    加密存储：+0.5mW（Flash加密引擎）
    完整性检查：+0.2mW（Boot验证）

  Level 3（防篡改响应）:
    传感器阵列：+0.05mW（常开）
    密钥保护电路：+0.01mW
    TRNG（按需）：+0.5mW（唤醒时）

  Level 4（完整物理保护）:
    主动网格：+1-2mW（持续）
    完整传感器套件：+0.1mW
    独立安全处理器：+2-5mW

  选择安全级别的原则：
    需求分析 → 威胁建模（STRIDE） → 确定必要安全级别
    不要过度设计（Level 4成本/功耗远高于Level 2-3）
```

### 26.10.2 安全感知的功耗优化

```
在满足安全约束下最小化功耗的设计流程:

Step 1: 威胁建模
  使用STRIDE框架识别威胁：
    Spoofing（欺骗）、Tampering（篡改）、Repudiation（否认）
    Information Disclosure（信息泄露）、DoS、Elevation of Privilege
  
  输出：每项资产的安全需求等级

Step 2: 算法与实现选择
  对称加密：AES/ASCON（硬件加速必须）
  非对称：Ed25519（优先）> ECDSA > RSA
  哈希：SHA-256/ASCON-Hash（硬件加速）
  轻量级场景：ASCON/SIMON/SPECK

Step 3: 安全功耗分析
  建立安全功能功耗模型（离线+在线）
  识别最大功耗贡献者（通常是非对称运算）
  评估每项安全功能的安全收益/功耗比

Step 4: 协同优化
  ┌────────────────────────────────────────────┐
  │  安全要求（不可妥协）→ 选择最低功耗实现  │
  │  功耗预算 → 确定可支持的安全特性集合     │
  │  系统设计 → 调度：安全操作避开功耗敏感期 │
  └────────────────────────────────────────────┘

  例：电池供电IoT设备中的非对称密钥协商
    方案A：每次通信都做ECDH → 功耗过高
    方案B：首次配对ECDH，后续用AES会话密钥
    → 将昂贵操作变为一次性操作，大幅降低平均功耗

Step 5: 验证
  功耗验证：实测 vs 建模
  安全验证：侧信道测试（TVLA测试）
  TVLA（Test Vector Leakage Assessment）：
    检验加密实现是否泄露信息
    用于验证掩码和随机化的有效性
```
