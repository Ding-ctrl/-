# 第23章 Chiplet与3D-IC低功耗设计

## 23.1 引言

随着摩尔定律逐渐放缓，单片式（Monolithic）SoC 在先进工艺节点下面临良率下降、成本飙升和设计复杂度爆炸等多重挑战。**Chiplet（芯粒）** 架构和 **3D-IC（三维集成电路）** 技术应运而生，通过将复杂芯片拆分为多个功能模块（Die），采用先进封装技术互联，实现"异构集成"。

然而，Chiplet/3D-IC 架构在带来灵活性和成本优势的同时，也引入了全新的低功耗设计挑战：Die间互联功耗、热堆叠效应、跨Die电源管理、异构电压域协调等。本章系统介绍 Chiplet 与 3D-IC 架构下的低功耗设计方法论，从架构规划到物理实现，全面覆盖这一前沿领域。

## 23.2 Chiplet架构基础

### 23.2.1 从Monolithic到Chiplet

```
传统SoC vs Chiplet架构:

Monolithic SoC (单片式):
┌─────────────────────────────────────────┐
│  ┌─────┐ ┌──────┐ ┌─────┐ ┌─────────┐  │
│  │ CPU │ │ GPU  │ │ NPU │ │ Memory  │  │
│  │     │ │      │ │     │ │ Ctrl    │  │
│  └─────┘ └──────┘ └─────┘ └─────────┘  │
│  ┌──────┐ ┌──────┐ ┌──────────────────┐ │
│  │ I/O  │ │ SerDes│ │   Interconnect  │ │
│  └──────┘ └──────┘ └──────────────────┘ │
│           全部同一工艺 (如5nm)            │
│         Die面积大 → 良率低 → 成本高       │
└─────────────────────────────────────────┘

Chiplet 架构:
┌──────────────────────────────────────────┐
│  ┌─────┐  ┌──────┐  ┌─────┐             │
│  │ CPU │  │ GPU  │  │ NPU │  ← 5nm      │
│  │ Die │  │ Die  │  │ Die │  高性能计算   │
│  └──┬──┘  └──┬───┘  └──┬──┘             │
│     │  D2D   │  D2D    │                │
│  ┌──┴────────┴─────────┴──┐             │
│  │     Interposer/Bridge   │  ← 被动硅  │
│  └──┬────────┬─────────┬──┘             │
│  ┌──┴──┐  ┌──┴───┐  ┌─┴─────┐          │
│  │ I/O │  │ Mem  │  │ SerDes │ ← 12nm   │
│  │ Die │  │ Ctrl │  │  Die   │  低成本   │
│  └─────┘  └──────┘  └───────┘           │
│           异构工艺 + 先进封装             │
│         小Die → 良率高 → 成本优           │
└──────────────────────────────────────────┘
```

### 23.2.2 Chiplet分解策略

| 分解维度 | 策略 | 功耗影响 | 典型案例 |
|----------|------|----------|----------|
| **按功能** | CPU/GPU/NPU/IO分离 | 各Die独立电压域 | AMD Zen系列 |
| **按工艺** | 计算Die用先进节点，IO用成熟节点 | IO Die漏电低 | Intel Ponte Vecchio |
| **按良率** | 大Die拆成多个小Die | 间接降低功耗（更好良率→更好Vmin） | AMD EPYC |
| **按复用** | 通用Die+专用Die | 减少重复设计 | UCIe生态 |

## 23.3 Die间互联功耗分析

### 23.3.1 Die-to-Die互联的功耗构成

```
D2D互联功耗模型:

P_D2D = P_TX + P_Channel + P_RX + P_Clocking + P_ECC

各部分占比 (典型2.5D μBump互联):

┌─────────────────────────────────────────┐
│ ████████████████████ 40%  TX驱动器      │
│ ████████████ 25%          Channel+Bump  │
│ ████████ 15%              RX接收器      │
│ ██████ 12%                时钟/同步     │
│ ████ 8%                   ECC/重传      │
└─────────────────────────────────────────┘

不同互联技术的单比特传输能耗:

互联类型              能耗/bit     带宽密度
─────────────────────────────────────────────
片上互联 (On-chip)    ~0.01 pJ/b   极高
Hybrid Bond          ~0.05 pJ/b   ~10⁶/mm²
μBump (3D)           ~0.1 pJ/b    ~10⁴/mm²
μBump (2.5D)         ~0.5 pJ/b    ~500/mm
EMIB Bridge          ~0.8 pJ/b    ~300/mm
有机基板 (Substrate)  ~2 pJ/b      ~100/mm
PCB (Board-level)    ~10 pJ/b     ~10/mm
SerDes (长距离)       ~20 pJ/b     N/A
─────────────────────────────────────────────

关键结论:
1. D2D互联功耗比片上互联高10-100×
2. 互联密度越高，单bit功耗越低
3. 选择封装技术时需权衡功耗与成本
```

### 23.3.2 互联功耗优化技术

```
D2D互联功耗优化方法:

方法1: 低摆幅信号传输 (Low-Swing Signaling)
─────────────────────────────────────────────
传统全摆幅:  VDD (0.8V)  → P ∝ C × V²
低摆幅:      0.2-0.4V    → P 降低 ~75%

    VDD ─────┐         VDD ─────┐
             │                  │
    Full     │         Low      │
    Swing    │         Swing    │
             │           ╌╌╌╌╌╌│── 0.4V
    GND ─────┘         GND ────┘── 0.2V

代价: 需要灵敏放大器(Sense Amp)，对噪声更敏感

方法2: 数据编码 (Data Encoding)
─────────────────────────────────────────────
Bus-Invert Coding:
  原始数据: 11001010 → 翻转5 bit
  编码后:   00110101 + INV=1 → 翻转3 bit + 1 INV
  节省翻转: (5-3-1)/5 = 20% 翻转减少

Limited Weight Coding (LWC):
  限制同时翻转的信号线数量
  功耗降低: 15-30% (取决于数据模式)

方法3: 串行化与时分复用
─────────────────────────────────────────────
  并行互联 (128条线):
  每条线: 1 Gbps, 0.5 pJ/b
  总功耗: 128 × 1G × 0.5p = 64 mW
  
  串行化 (16条线, 8:1 SerDes):
  每条线: 8 Gbps, 1.5 pJ/b (含SerDes开销)
  总功耗: 16 × 8G × 1.5p = 192 mW
  
  结论: 低带宽场景用并行, 高带宽场景需权衡

方法4: 自适应互联宽度
─────────────────────────────────────────────
  高负载: 使用全部128条D2D链路
  中负载: 关断一半，使用64条
  低负载: 进一步关断，使用32条
  
  功耗节省: 空闲链路关断可省50-75%互联功耗
```

### 23.4.2 跨Die DVFS协调

```
多Die DVFS协调策略:

策略1: 独立DVFS (Independent)
──────────────────────────────────
  CPU Die: 自主调节 VDD_CPU / Freq_CPU
  GPU Die: 自主调节 VDD_GPU / Freq_GPU
  
  优点: 实现简单，各Die最优化
  缺点: D2D接口频率需要异步处理
  
策略2: 协调DVFS (Coordinated)
──────────────────────────────────
  PMC (Power Management Controller) 统一协调:
  
  ┌──────────────────────────────────────┐
  │          System PMC (IO Die)         │
  │  ┌────────────────────────────────┐  │
  │  │ 负载监控 → 功耗预算 → 频率分配 │  │
  │  └────┬──────────┬──────────┬─────┘  │
  │       │ DVFS Cmd │          │        │
  │  ┌────▼────┐ ┌───▼────┐ ┌──▼────┐   │
  │  │CPU DVFS │ │GPU DVFS│ │IO DVFS│   │
  │  │Agent    │ │Agent   │ │Agent  │   │
  │  └─────────┘ └────────┘ └───────┘   │
  └──────────────────────────────────────┘
  
  协调算法示例:
  Total Power Budget = P_max (如25W)
  P_CPU + P_GPU + P_IO + P_D2D ≤ P_max
  
  高CPU负载场景:
    P_CPU = 15W (提升VF), P_GPU = 5W (降低VF)
    P_IO = 3W, P_D2D = 2W
    
  高GPU负载场景:
    P_CPU = 5W (降低VF), P_GPU = 15W (提升VF)
    P_IO = 3W, P_D2D = 2W

策略3: D2D链路DVFS
──────────────────────────────────
  D2D互联本身支持多个频率/电压工作点:
  
  ┌──────────┬──────────┬──────────┬──────────┐
  │ 工作点    │ 频率     │ 电压     │ 带宽     │
  ├──────────┼──────────┼──────────┼──────────┤
  │ High     │ 8 GHz   │ 0.8V    │ 256 GB/s │
  │ Medium   │ 4 GHz   │ 0.65V   │ 128 GB/s │
  │ Low      │ 2 GHz   │ 0.5V    │ 64 GB/s  │
  │ Sleep    │ 0       │ 关断     │ 0        │
  └──────────┴──────────┴──────────┴──────────┘
  
  功耗节省: High→Low 可节省约75% D2D功耗
```

### 23.4.3 跨Die电源开关与隔离

```
跨Die Power Gating设计要点:

1. Die级Power Gating:
   关断整个Die的电源域（VDD通过外部PMIC/开关控制）
   
   ┌────────────┐
   │   PMIC     │
   │ ┌──┐ ┌──┐ │
   │ │EN│ │EN│ │       EN=0: 整个Die关断
   │ └┬─┘ └┬─┘ │       EN=1: 整个Die上电
   └──┼────┼───┘
      │    │
   ┌──▼──┐ ┌▼────┐
   │CPU  │ │GPU  │
   │Die  │ │Die  │
   └─────┘ └─────┘
   
   挑战: 上电时序长（μs级），需要D2D链路重新训练

2. Die内Power Gating (传统片上方式):
   Die内部使用Header/Footer开关
   上电时序快（ns级），对D2D无影响
   
3. 跨Die隔离策略:
   
   关断Die的D2D接口必须有隔离措施:
   
   ┌──── Active Die ────┐    ┌──── Powered-Off Die ──┐
   │                    │    │                        │
   │  Logic → ISO → TX  │────│  RX → ISO → Logic     │
   │         │          │ D2D│       │    (关断)       │
   │    Clamp to 0/1    │    │  Clamp to 0/1         │
   │                    │    │  (防止浮空态漏电)       │
   └────────────────────┘    └────────────────────────┘
   
   隔离方式:
   a. TX端隔离: 关断Die前，TX驱动器输出钳位
   b. RX端隔离: 接收端内置钳位电路
   c. D2D PHY隔离: PHY自带低功耗状态处理
```

## 23.5 3D-IC热-功耗协同设计

### 23.5.1 3D-IC热堆叠效应

```
3D堆叠的热问题:

2D芯片散热:
  ┌──────────┐
  │   Die    │ → 热量主要从底部散出
  └────┬─────┘
       │ ↓ 热流
  ┌────┴─────┐
  │ Substrate│
  └────┬─────┘
       │ ↓
  ═══散热器═══

3D堆叠散热困难:
  ┌──────────┐
  │ Top Die  │ ← 热量被Bottom Die阻挡!
  └────┬─────┘
       │ ↓ TSV (热传导有限)
  ┌────┴─────┐
  │Bottom Die│ ← 自身发热 + Top Die热量叠加!
  └────┬─────┘
       │ ↓
  ═══散热器═══

温度分布示例 (3D堆叠, 单位°C):
  
  Top Die:     85  90  95  92  88    ← 热点温度高
               88  95 [105] 97  90   ← 热点可达105°C
               85  90  95  92  87
               
  Bottom Die:  80  85  88  86  82
               83  88  92  89  84    ← 受Top Die影响
               80  85  88  86  81

  温升:  3D堆叠比2D增加 15-30°C (典型值)
  
  功耗影响:
  - 温度每升高10°C → 漏电流增加~2×
  - 105°C vs 75°C → 漏电增加约8× !
  - 形成 "温度-漏电" 正反馈回路 (Thermal Runaway风险)
```

### 23.5.2 热感知的低功耗设计

```
3D-IC热-功耗协同优化策略:

策略1: 热感知的Die间功能映射
──────────────────────────────────
  原则: 高功耗模块不要在垂直方向对齐
  
  差的映射:                  好的映射:
  ┌────┬────┬────┐           ┌────┬────┬────┐
  │CPU │GPU │NPU │ Top      │CPU │SRAM│ IO │ Top
  ├────┼────┼────┤           ├────┼────┼────┤
  │MEM │DDR │IO  │ Bot      │GPU │NPU │DDR │ Bot
  └────┴────┴────┘           └────┴────┴────┘
  
  CPU在GPU正上方 → 热叠加!    CPU与SRAM/IO对齐 → 热分散

策略2: 热感知的动态功率管理 (DTPM)
──────────────────────────────────
  
  ┌────────────────────────────────────┐
  │       热感知功率管理控制器          │
  │                                    │
  │  温度传感器 → 热模型预测 → 功率分配 │
  │  (per-Die)    (实时)      (动态)   │
  └─────┬──────────┬──────────┬────────┘
        │          │          │
   ┌────▼────┐ ┌───▼───┐ ┌───▼───┐
   │ DVFS    │ │ Task  │ │ Power │
   │ 调节    │ │ 迁移  │ │ Gating│
   └─────────┘ └───────┘ └───────┘
  
  控制算法:
  IF T_top > T_threshold THEN
    1. 降低Top Die频率/电压
    2. 将任务迁移到Bottom Die (更靠近散热器)
    3. 关断Top Die空闲模块
  END IF
  
  温度-功率预算联合约束:
  Maximize: Performance (IPC_total)
  Subject to:
    P_top + P_bot ≤ P_budget
    T_top ≤ T_junction_max (如105°C)
    T_bot ≤ T_junction_max
    T_top = f(P_top, P_bot, R_th_stack)  ← 耦合!

策略3: TSV布局的热优化
──────────────────────────────────
  TSV不仅传电/传信号，还是热通道:
  
  热TSV (Thermal TSV):
  - 专门用于导热的TSV
  - 不传输信号，仅做热传导路径
  - 铜TSV热导率: ~400 W/(m·K)
  - 硅热导率:    ~150 W/(m·K)
  
  布局策略:
  ┌─────────────────────────┐
  │ ○   □   ○   □   ○      │
  │   □   ○   □   ○   □    │  ○ = 信号/电源 TSV
  │ ○   □   ●   □   ○      │  □ = 常规区域
  │   □   ○   □   ○   □    │  ● = 热点区域
  │ ○   □   ○   □   ○      │
  └─────────────────────────┘
  
  在热点区域(●)增加Thermal TSV密度:
  ┌─────────────────────────┐
  │ ○   □   ○   □   ○      │
  │   □   ○ ◆ ○ ◆  □      │  ◆ = Thermal TSV
  │ ○   □ ◆ ● ◆ □   ○     │
  │   □   ○ ◆ ○ ◆  □      │
  │ ○   □   ○   □   ○      │
  └─────────────────────────┘
  
  效果: 热点温度降低5-15°C → 漏电降低30-60%
```

### 23.5.3 3D-IC电源完整性

```
3D-IC PDN (Power Delivery Network) 挑战:

垂直PDN结构:
  
  Package → C4 Bump → Bottom Die → TSV → Top Die
  
  ┌──────────┐
  │ Top Die  │ ← VDD_top = VDD_bot - IR_drop_TSV
  │ (消费者) │
  └────┬─────┘
       │ TSV (有电阻和电感)
       │ R_TSV ≈ 0.1-1 Ω (每个TSV)
       │ L_TSV ≈ 10-50 pH
  ┌────┴─────┐
  │Bottom Die│ ← VDD_bot = Package_VDD - IR_drop_bump
  │ (转接)   │
  └────┬─────┘
       │ C4 Bump
  ┌────┴─────┐
  │ Package  │ ← VDD_package
  └──────────┘

IR Drop分析:
  假设 Top Die 电流: 10A
  TSV数量: 1000个电源TSV
  每TSV电流: 10mA
  R_TSV = 0.5 Ω
  
  单TSV压降: 10mA × 0.5Ω = 5mV
  但TSV分布不均 → 局部压降可达 30-50mV
  
  对功耗的影响:
  - IR Drop → 实际电压降低 → 需要提升Nominal VDD来补偿
  - Nominal VDD提升50mV → 动态功耗增加约12%
  - 所以3D-IC的PDN优化对功耗至关重要

优化方法:
┌─────────────────────┬──────────────────────────────┐
│ 方法                │ 效果                          │
├─────────────────────┼──────────────────────────────┤
│ 增加电源TSV数量     │ 减小等效电阻，降低IR Drop     │
│ TSV位置优化         │ 在高电流区域增加TSV密度        │
│ Die内Decap优化      │ 抑制瞬态压降 (di/dt noise)    │
│ 背面供电 (BSPDN)    │ 从Top Die背面直接供电         │
│ 嵌入式电压调节器    │ 在Die内集成LDO/Buck           │
└─────────────────────┴──────────────────────────────┘
```

## 23.6 背面供电网络 (BSPDN)

### 23.6.1 BSPDN原理与优势

```
传统正面供电 vs 背面供电:

传统 (FSPDN):                背面供电 (BSPDN):
                              
  ← 信号线 (M1-M10+)            ← 信号线 (M1-M10+)
  ┌──────────────────┐          ┌──────────────────┐
  │ M10 (VDD/VSS)   │          │ M10 (信号)       │
  │ M9  (VDD/VSS)   │          │ M9  (信号)       │
  │ ...              │          │ ...              │
  │ M3  (信号+电源) │          │ M3  (纯信号)     │
  │ M2  (信号+电源) │          │ M2  (纯信号)     │
  │ M1  (信号+电源) │          │ M1  (纯信号)     │
  ├──────────────────┤          ├──────────────────┤
  │    Transistors   │          │    Transistors   │
  └──────────────────┘          ├──────────────────┤
                                │ NanoTSV          │
                                │ BM1 (VDD/VSS)   │ ← 背面金属
                                │ BM2 (VDD/VSS)   │
                                └──────────────────┘
                                       ↑ 从背面供电

BSPDN 功耗优势:
┌─────────────────────┬──────────────┬───────────────┐
│ 指标                │ FSPDN        │ BSPDN         │
├─────────────────────┼──────────────┼───────────────┤
│ IR Drop             │ 基准         │ -30~50%       │
│ 所需Nominal VDD     │ 基准         │ -20~40 mV     │
│ 动态功耗            │ 基准         │ -5~10%        │
│ 信号线拥塞          │ 严重         │ 大幅缓解      │
│ 时钟网络功耗        │ 基准         │ -10~15%       │
│ 标准单元面积        │ 基准         │ -15~20%       │
└─────────────────────┴──────────────┴───────────────┘

原理: 电源线从正面移到背面 →
  1. 正面金属层全部用于信号 → 线长缩短 → 电容减小
  2. 背面粗金属专门供电 → IR Drop大幅降低
  3. VDD可以降低 → 功耗降低
```

### 23.6.2 BSPDN在3D-IC中的应用

```
3D-IC + BSPDN 组合:

传统3D-IC供电路径:
  Package → Bump → Bot.Die(正面) → TSV → Top.Die(正面)
  
  问题: 长供电路径, 大IR Drop, Top Die供电质量差

BSPDN + 3D-IC:
  方案1: Top Die使用BSPDN
  ┌──────────────┐
  │ Top Die      │
  │ (正面信号)   │
  │ (背面供电)←──│── 直接从封装背面供电
  └──────┬───────┘
         │ TSV (仅信号!)
  ┌──────┴───────┐
  │ Bottom Die   │
  │ (正面供电)   │
  └──────┬───────┘
         │ Bump
  ┌──────┴───────┐
  │   Package    │
  └──────────────┘
  
  优势:
  - Top Die供电质量大幅提升 (不经过Bot Die)
  - TSV仅传信号 → TSV数量减少 → 面积节省
  - 功耗节省: 10-20% (IR Drop改善 + 线长缩短)

  方案2: 双Die均使用BSPDN (未来方向)
  两个Die背对背堆叠，各自背面供电
  信号通过正面TSV互联
```

# 1. 创建顶层电源域

# 2. 创建各Die子域
create_power_domain PD_CPU_DIE \
  -elements {u_cpu_die} \
  -supply {primary}

create_power_domain PD_GPU_DIE \
  -elements {u_gpu_die} \
  -supply {primary}

create_power_domain PD_IO_DIE \
  -elements {u_io_die} \
  -supply {primary}

# 3. 创建供电网络 (各Die独立供电)
create_supply_net VDD_CPU -domain PD_CPU_DIE
create_supply_net VDD_GPU -domain PD_GPU_DIE
create_supply_net VDD_IO  -domain PD_IO_DIE
create_supply_net VSS     -domain PD_TOP

# 4. D2D接口电源域
create_power_domain PD_D2D_CPU \
  -elements {u_cpu_die/u_d2d_phy} \
  -supply {primary}

create_power_domain PD_D2D_GPU \
  -elements {u_gpu_die/u_d2d_phy} \
  -supply {primary}

create_supply_net VDD_D2D_CPU -domain PD_D2D_CPU
create_supply_net VDD_D2D_GPU -domain PD_D2D_GPU

# 5. 电源开关 (Die级Power Gating)
create_power_switch SW_GPU_DIE \
  -domain PD_GPU_DIE \
  -input_supply_port {vin VDD_GPU} \
  -output_supply_port {vout VDD_GPU_SW} \
  -control_port {gpu_pwr_en u_io_die/pmc/gpu_en} \
  -on_state {on_s vin {gpu_pwr_en}}

# 6. 跨Die隔离策略
set_isolation ISO_CPU_TO_GPU \
  -domain PD_CPU_DIE \
  -applies_to outputs \
  -clamp_value 0 \
  -isolation_signal {u_io_die/pmc/cpu_gpu_iso_en}

set_isolation ISO_GPU_TO_CPU \
  -domain PD_GPU_DIE \
  -applies_to outputs \
  -clamp_value 0 \
  -isolation_signal {u_io_die/pmc/gpu_cpu_iso_en}

# 7. D2D接口电平转换
set_level_shifter LS_CPU_D2D \
  -domain PD_CPU_DIE \
  -applies_to outputs \
  -rule both \
  -location self

# 8. 电源状态定义
add_power_state PD_CPU_DIE.active \
  -supply_expr {power == `{FULL_ON, 0.75}}
add_power_state PD_CPU_DIE.drowsy \
  -supply_expr {power == `{FULL_ON, 0.55}}
add_power_state PD_CPU_DIE.off \
  -supply_expr {power == `{OFF}}

add_power_state PD_GPU_DIE.active \
  -supply_expr {power == `{FULL_ON, 0.85}}
add_power_state PD_GPU_DIE.off \
  -supply_expr {power == `{OFF}}

# 9. 系统级功耗状态表 (合法状态组合)
add_power_state PD_TOP.sys_active \
  -logic_expr {
    PD_CPU_DIE == active &&
    PD_GPU_DIE == active &&
    PD_IO_DIE == active
  }

add_power_state PD_TOP.gpu_off \
  -logic_expr {
    PD_CPU_DIE == active &&
    PD_GPU_DIE == off &&
    PD_IO_DIE == active
  }

add_power_state PD_TOP.deep_sleep \
  -logic_expr {
    PD_CPU_DIE == off &&
    PD_GPU_DIE == off &&
    PD_IO_DIE == drowsy
  }
```

## 23.8 Chiplet系统功耗分析方法

### 23.8.1 系统级功耗建模

```
Chiplet系统功耗建模框架:

P_total = Σ P_die(i) + Σ P_d2d(i,j) + P_package + P_pmic

各项功耗建模:

1. Die功耗 (P_die):
   与传统SoC功耗分析相同
   P_die = P_dynamic + P_leakage + P_short_circuit
   
2. D2D互联功耗 (P_d2d):
   P_d2d = N_links × f_link × E_per_bit × α_d2d
   
   其中:
   N_links  = D2D链路数量
   f_link   = 链路频率
   E_per_bit= 单bit传输能耗
   α_d2d    = D2D活动因子 (数据传输占比)

3. 封装级功耗 (P_package):
   P_package = I² × R_bump + I² × R_trace
   
4. PMIC效率损耗:
   P_pmic = P_total_delivery × (1/η - 1)
   η = PMIC效率 (典型85-95%)

功耗分析工具链:
┌──────────────────────────────────────────────┐
│                                              │
│  ┌────────┐   ┌──────────┐   ┌───────────┐  │

│  │功耗分析│   │ 功耗模型 │   │ PDN分析   │  │
│  │(PrimePW│   │(自定义   │   │(Ansys    │  │
│  │ /Joules│   │ 模型)    │   │ RedHawk) │  │
│  │ /Volta)│   │          │   │          │  │
│  └───┬────┘   └────┬─────┘   └────┬──────┘  │
│      │             │              │          │
│      └─────────────┼──────────────┘          │
│                    ▼                         │
│           ┌────────────────┐                 │
│           │ 系统级功耗集成 │                 │
│           │ 与热分析耦合   │                 │
│           └────────┬───────┘                 │

## 23.11 未来趋势

### 23.11.1 技术趋势展望

```
Chiplet/3D-IC低功耗设计未来方向:

趋势1: 光互联 (Optical D2D)
──────────────────────────────
  目标: 将D2D能耗从0.5pJ/b降到<0.1pJ/b
  技术: 硅光子学 + 微环调制器
  状态: 研究/早期开发阶段
  
  电互联: ~0.5 pJ/b (2.5D μBump)
  光互联: ~0.05 pJ/b (目标)
  节省:   90% D2D功耗

趋势2: 嵌入式电源管理
──────────────────────────────
  将PMIC功能集成到Die内部:
  - 片内Buck/LDO转换器
  - 纳秒级DVFS切换 (vs μs级传统PMIC)
  - 消除封装级电源损耗

趋势3: 自适应供电 (Adaptive Body Biasing in 3D)
──────────────────────────────
  3D堆叠中利用背面偏置调节:
  - 通过TSV传递偏置电压
  - 实时调节各Die的Vth
  - 补偿3D热效应导致的漏电增加

趋势4: AI驱动的功耗管理
──────────────────────────────
  利用ML模型预测和管理多Die功耗:
  - 工作负载预测 → 提前DVFS调节
  - 热预测 → 预防性节流
  - 多Die协同优化 → 全局最优能效
  
趋势5: Chiplet标准化生态
──────────────────────────────
  UCIe + CXL + AMBA CHI → 统一互联标准
  - 降低D2D接口设计复杂度
  - 标准化的低功耗状态管理
  - 第三方Chiplet即插即用
```
