# 第24章 AI与ML加速器低功耗设计

## 24.1 引言

人工智能（AI）与机器学习（ML）的爆发式增长，使算力需求以每年数倍的速度膨胀。从云端数据中心到边缘终端设备，AI推断与训练的功耗问题已成为制约部署规模、运营成本乃至可持续发展的核心瓶颈。

**功耗挑战的三个维度：**

1. **计算强度**：Transformer、CNN等神经网络每次推断需执行数百亿至数万亿次乘加运算（MAC），原始算力功耗极高。
2. **数据搬运**：片上存储带宽和片外DRAM访问的能耗往往远超实际计算，"内存墙"问题在AI芯片上尤为突出。
3. **部署场景多样性**：从毫瓦级可穿戴设备到百瓦级服务器加速卡，AI芯片需要在极宽的功耗约束范围内工作。

本章系统介绍AI/ML加速器的低功耗设计方法，涵盖算法-架构协同优化、数据流设计、稀疏性利用、量化低精度计算、存储层次优化、动态功耗管理以及主流产品的工程实践，帮助读者掌握高能效AI芯片设计的完整知识体系。

### 24.2.3 Roofline模型与能效分析

```
Roofline模型: 理解计算与访存的功耗平衡点

性能上限
(TOPS)  │                        ____________________
        │                   ____/   计算受限区域
        │              ____/        (提升计算效率)
        │         ____/
        │    ____/  访存受限区域
        │___/       (提升数据复用)
        │
        └──────────────────────────────── 算术强度
                    脊点 (Ops/Byte)       (Ops/Byte)

能效最优化目标：
1. 提升算术强度（增加数据复用）→ 降低DRAM访问功耗
2. 在计算受限区：提升MAC利用率 → 降低每TOPS功耗
3. 设计点应落在"脊点"附近
```

## 24.3 数据流架构与能效优化

### 24.3.1 三种基本数据流

数据流（Dataflow）决定了操作数在PE（Processing Element）阵列中的流动方式，直接影响数据复用率和能耗。

```
三种经典数据流架构对比:

1. 权重固定（Weight Stationary, WS）:
   ┌──────────────────────────────────────┐
   │  权重加载一次，固定在PE寄存器中       │
   │  输入激活值流过PE阵列                │
   │  输出累加后写出                      │
   │  优点：权重访问能耗低                │
   │  缺点：激活值和输出需要大量数据移动  │
   │  适合：大kernel卷积，batch=1推断     │
   └──────────────────────────────────────┘
   代表：Google TPU v1

2. 输出固定（Output Stationary, OS）:
   ┌──────────────────────────────────────┐
   │  输出部分和固定在PE寄存器中          │
   │  权重和激活值流入完成计算            │
   │  优点：输出累加能耗最小              │
   │  缺点：权重和激活值重复加载          │
   │  适合：输出feature map较小的层       │
   └──────────────────────────────────────┘

3. 行固定（Row Stationary, RS）:
   ┌──────────────────────────────────────┐
   │  将1D卷积映射到一行PE上              │
   │  最大化所有操作数的复用              │
   │  优点：总能耗最低（综合考虑所有操作数）│
   │  缺点：映射复杂度较高                │
   │  适合：通用CNN加速                  │
   └──────────────────────────────────────┘
   代表：MIT Eyeriss
```

### 24.3.2 脉动阵列设计

```
脉动阵列（Systolic Array）能效优化:

标准脉动阵列 (Google TPU风格):

    A[0]→  ┌────┐  ┌────┐  ┌────┐
           │ PE │→ │ PE │→ │ PE │
    A[1]→  ├────┤  ├────┤  ├────┤
           │ PE │→ │ PE │→ │ PE │
    A[2]→  ├────┤  ├────┤  ├────┤
           │ PE │→ │ PE │→ │ PE │
           ↓     ↓     ↓
           B[0]  B[1]  B[2]

能效关键设计:
1. 权重预加载（Preloading）：
   - 计算阶段权重固定在寄存器，无需重新加载
   - 节省~40%的SRAM访问能耗

2. 零跳过（Zero Skipping）：
   - 检测输入激活值为0时，禁用对应乘法器
   - 典型ReLU后稀疏度50%，可节省~25%计算能耗

3. 双缓冲（Double Buffering）：
   - 计算当前tile的同时预取下一个tile
   - 消除计算-访存的流水线气泡
```

### 24.3.3 近存计算（PIM/CIM）架构

```
Processing-In-Memory 架构对比传统架构:

传统架构（冯诺依曼）:
  DRAM → 总线 → Cache → 计算单元
  数据搬运能耗：~100-200 pJ/bit × 大量数据 = 高功耗

PIM架构:
  ┌─────────────────────────────────────┐
  │           DRAM Die                  │
  │  ┌──────┐ ┌──────┐ ┌──────┐       │
  │  │ Bank │ │ Bank │ │ Bank │       │
  │  │  +   │ │  +   │ │  +   │       │
  │  │ MAC  │ │ MAC  │ │ MAC  │       │
  │  └──────┘ └──────┘ └──────┘       │
  │         ↓ 近存计算                  │
  │  数据在DRAM内部完成MAC运算           │
  │  只传输结果（Byte级），不传原始数据  │
  └─────────────────────────────────────┘

能效提升：3-10×（视负载而定）
带宽提升：10-50×（利用内部带宽）

代表产品：
- Samsung HBM-PIM（GDDR6-PIM）
- SK Hynix AiM（Acceleration in Memory）
- UPMEM DPU
```

## 24.4 稀疏计算低功耗技术

### 24.4.1 神经网络的稀疏性来源

```
稀疏性分类与典型比例:

1. 激活稀疏（Activation Sparsity）:
   ├── ReLU激活后：~50% 零值
   ├── ReLU6/HardSwish：~30-40% 零值
   └── 来源：ReLU将负值截断为0

2. 权重稀疏（Weight Sparsity）:
   ├── 非结构化剪枝：可达70-90%稀疏度
   ├── 结构化剪枝（通道/滤波器）：20-50%稀疏度
   └── 来源：剪枝（Pruning）压缩技术

3. 梯度稀疏（训练阶段）:
   ├── 梯度稀疏度：~99%（通信压缩场景）
   └── 来源：大部分梯度接近于0

4. 注意力稀疏（Attention Sparsity）:
   ├── Top-K Attention：保留K个最高分
   ├── 局部窗口注意力：~80-95%稀疏
   └── 来源：Transformer注意力机制优化
```

### 24.4.2 稀疏加速硬件设计

```
稀疏感知PE设计:

传统密集计算（4×4 矩阵，50%稀疏）:
  时间步:  1  2  3  4  5  6  7  8
  计算:   [×][×][×][×][×][×][×][×]  8步
  其中:  [有效][0跳][有效][0跳][有效][0跳][有效][0跳]

稀疏感知计算（零跳过）:
  时间步:  1  2  3  4
  计算:   [×][×][×][×]  仅4步（节省50%计算功耗）

硬件实现—压缩稀疏行（CSR）格式:
  原始矩阵:  [3, 0, 1, 0]
             [0, 0, 4, 0]
             [0, 2, 0, 5]

  CSR存储:
    values:  [3, 1, 4, 2, 5]       (非零值)
    col_idx: [0, 2, 2, 1, 3]       (列索引)
    row_ptr: [0, 2, 3, 5]          (行起始位置)

  优点：仅处理非零元素，跳过零值计算
  存储开销：需额外存储稀疏坐标信息
```

### 24.4.3 NVIDIA Ampere稀疏加速实例

```
NVIDIA A100 细粒度结构化稀疏（2:4稀疏）:

原则：每4个连续元素中，至少2个为零
例：  [1.2,  0,  3.4,  0]   ← 2个非零，2个零

硬件实现:
┌─────────────────────────────────────────────────────┐
│  稀疏权重存储:                                       │
│  原始：[W0, 0, W1, 0, W2, W3, 0, 0]  8个元素/8字节  │
│  压缩：[W0, W1, W2, W3] + 元数据索引  4字节+索引    │
│                                                      │
│  稀疏Tensor Core执行:                               │
│  1. 加载压缩权重（4字节）                           │
│  2. 加载元数据索引（2bit×4=1字节）                  │
│  3. 硬件根据索引选择对应激活值                      │
│  4. 执行4个有效MAC（跳过0×anything）                │
│                                                      │
│  结果：2× 吞吐量提升，存储节省~50%                  │
└─────────────────────────────────────────────────────┘

能效收益：
- 相同功耗下性能翻倍
- 或相同性能下功耗减半
- DRAM带宽需求降低~50%
```

## 24.5 量化与低精度计算

### 24.5.1 量化基础与能效分析

量化（Quantization）将浮点权重和激活值映射到低比特整数，是AI芯片最核心的能效优化技术。

```
不同精度的MAC单元面积与功耗对比（16nm工艺）:

精度      │ 面积(μm²) │ 功耗(pJ/op) │ 相对FP32
──────────┼──────────┼────────────┼──────────
FP32      │   ~1850   │   ~3.7     │  1.0×
FP16      │   ~780    │   ~1.1     │  3.4×
BF16      │   ~620    │   ~0.9     │  4.1×
INT8      │   ~282    │   ~0.2     │  18.5×
INT4      │   ~80     │   ~0.06    │  62×
INT2/二值 │   ~20     │   ~0.01    │  370×

结论：INT8 vs FP32 能效提升约18×，面积节省约6.5×
```

### 24.5.2 量化方案分类

```
量化方案体系:

按量化时机分类:
├── 训练后量化（PTQ, Post-Training Quantization）
│   ├── 静态量化：预计算量化参数（scale/zero-point）
│   ├── 动态量化：运行时计算激活值量化参数
│   └── 优点：无需重新训练，快速部署
│       缺点：精度损失相对较大
│
└── 量化感知训练（QAT, Quantization-Aware Training）
    ├── 在训练中模拟量化误差（STE梯度估计器）
    ├── 模型学会补偿量化带来的精度损失
    └── 优点：精度损失最小
        缺点：训练成本高

按量化粒度分类:
├── 逐层（Per-tensor）：一层一组量化参数，简单但精度低
├── 逐通道（Per-channel）：每个输出通道独立量化，精度更高
└── 逐组（Per-group/Group-wise）：每N个元素一组，精度高但开销大

典型量化精度配置:
  推断场景      │ 权重精度 │ 激活精度 │ 累加精度
  ─────────────┼─────────┼─────────┼─────────
  高精度推断    │ INT8     │ INT8    │ INT32
  平衡配置      │ W4A8     │ INT8    │ INT32
  极低功耗边缘  │ W4A4     │ INT4    │ INT16
  研究/实验     │ INT1/2   │ INT4    │ INT8
```

### 24.5.3 混合精度量化策略

```
混合精度量化—敏感层保持高精度:

网络层敏感度分析:
  Layer 1 (Conv)   : 敏感度 低  → INT4量化
  Layer 2 (Conv)   : 敏感度 中  → INT8量化
  Layer 3 (BN+ReLU): 敏感度 低  → INT8量化
  Layer 4 (FC)     : 敏感度 高  → FP16量化  ← 最后几层通常敏感
  Softmax/Output   : 敏感度 极高 → FP32量化

自动混合精度搜索 (AMQ - Automatic Mixed Quantization):

  for each layer:
    评估精度损失 = full_precision_acc - quantized_acc
    评估能效收益 = latency_saving + memory_saving
    选择 最优(精度损失/能效收益) 的量化方案

  约束：整体精度损失 < 阈值（如顶1精度下降 < 1%）
```

### 24.5.4 LLM低精度推断

```
大语言模型（LLM）的量化挑战:

GPT-3/LLaMA规模的模型权重分布:
  大多数权重分布集中（易量化）
  ~0.1%的异常值（Outlier）幅度极大（难量化）
  →  简单INT8量化精度损失严重

解决方案—SmoothQuant:
  观察：激活值存在通道维度的大异常值
  策略：将激活值的量化难度"平滑"迁移到权重

  Y = (X·diag(s)⁻¹)·(diag(s)·W)
     ─────────────   ─────────────
     平滑后的激活X̂    平滑后的权重Ŵ
     （更易量化）      （仍易量化）

  效果：W8A8量化，LLaMA-65B精度无损

AWQ (Activation-aware Weight Quantization):
  识别重要的权重通道（与激活值分布相关）
  对这些通道进行缩放保护，其余INT4压缩
  效果：W4A16量化，精度接近FP16基线
```

## 24.6 存储层次与数据复用优化

### 24.6.1 片上存储层次设计

```
AI加速器典型存储层次架构:

┌───────────────────────────────────────────────────┐
│  DRAM (HBM2e/LPDDR5)                             │
│  容量: 8-80GB  带宽: 500GB/s-3.2TB/s             │
│  功耗: ~20-30W（HBM访问为主）                     │
└────────────────────┬──────────────────────────────┘
                     │ 片外带宽（瓶颈）
┌────────────────────▼──────────────────────────────┐
│  全局缓冲区 (Global Buffer / Unified Buffer)       │
│  容量: 4-32MB  带宽: 2-20TB/s                     │
│  SRAM阵列，分Bank减少冲突                         │
│  功耗: ~5-15W                                     │
└────────────────────┬──────────────────────────────┘
                     │ 片上高带宽互联
┌────────────────────▼──────────────────────────────┐
│  PE本地缓冲 (Local Buffer / Scratchpad)            │
│  容量: 每PE 256B-4KB  总: 1-8MB                   │
│  距离计算单元最近，功耗极低                        │
│  功耗: ~1-5W                                      │
└────────────────────┬──────────────────────────────┘
                     │ 本地读写
┌────────────────────▼──────────────────────────────┐
│  寄存器文件 (Register File / Accumulator)          │
│  容量: 每PE 64-512B                               │
│  保存部分和，避免重复读写SRAM                      │
│  功耗: < 1W                                       │
└───────────────────────────────────────────────────┘
```

### 24.6.2 Tiling策略与数据复用

```
Tiling（分块）策略最大化数据复用:

矩阵乘法 C = A × B (M×K × K×N → M×N)
未分块:  每个C[i,j] = Σ A[i,k]×B[k,j]
         A的每行访问N次，B的每列访问M次 → 大量重复DRAM访问

Tiling后:
  将M×K×N分成 Tm×Tk×Tn 的小块
  每块完全在片上缓冲区处理

  for im in range(0, M, Tm):
    for in in range(0, N, Tn):
      # 加载C块到累加器
      for ik in range(0, K, Tk):
        # 加载A块（Tm×Tk）到缓冲区  ← 复用Tn次
        # 加载B块（Tk×Tn）到缓冲区  ← 复用Tm次
        # 执行 Tm×Tk×Tn 次MAC（全在片上）
      # 写回C块到DRAM

数据复用率分析:
  A块: 从DRAM加载1次，在片上使用Tn次  → 复用率 = Tn
  B块: 从DRAM加载1次，在片上使用Tm次  → 复用率 = Tm

DRAM访问量降低：
  原始：O(M×K×N)次DRAM读写
  Tiling后：O(M×K×N / (Tm × Tn))次DRAM读写  ← 大幅降低
```

### 24.6.3 KV Cache管理（LLM推断优化）

```
Transformer推断的KV Cache挑战:

推断过程（自回归生成）:
  Token 1: 计算K1,V1 → 缓存
  Token 2: 计算K2,V2 → 缓存; 加载K1,V1 → 注意力
  Token n: 计算Kn,Vn → 缓存; 加载K1..Kn-1, V1..Vn-1

  问题：KV Cache随序列长度线性增长
  LLaMA-70B，序列长度2048：KV Cache ~35GB
  带宽消耗：每生成一个Token需读取全部KV Cache

低功耗KV Cache优化策略:

1. MQA（Multi-Query Attention）:
   所有注意力头共享K和V（只有Q不同）
   KV Cache减少 head_num 倍（如32×）
   带宽节省：~30倍

2. GQA（Grouped-Query Attention）:
   G组共享K和V（折中方案）
   KV Cache减少 head_num/G 倍
   应用：LLaMA-2 70B使用GQA

3. 量化KV Cache:
   KV从FP16量化到INT8/INT4
   显存节省2-4×，带宽节省2-4×
   精度损失可控（注意力中的量化）

4. KV Cache卸载:
   长序列时将冷KV卸载到CPU DRAM
   热KV保留在GPU HBM
   延迟增加但支持超长上下文
```

### 24.7.2 AI工作负载驱动的DVFS

```
AI推断场景的DVFS策略:

场景1：连续视频推断（持续负载）
  NPU频率: 最高频率（如1GHz）
  NPU电压: 最高电压（如1.0V）
  策略: 维持高频以满足实时性约束

场景2：离线批处理（延时不敏感）
  NPU频率: 中等频率（如600MHz）
  NPU电压: 降低至0.8V
  功耗节省: ~50%（f↓40%，V²↓36%）

场景3：待机+触发推断（稀疏唤醒）
  NPU状态: Deep Sleep（功耗<1mW）
  触发事件: 语音/图像预处理结果
  唤醒时间: <1ms（快速唤醒要求）

层级DVFS（Fine-grained DVFS）:
  同一推断任务中不同层的算术强度不同

  Layer类型    │ 算术强度 │ 推荐状态
  ─────────────┼─────────┼────────────
  大卷积核    │ 高       │ 高频计算
  深度可分离卷积│ 低      │ 降频节能
  FC层        │ 低       │ 降频+压缩
  激活函数    │ 极低     │ 等待或降频

  实现：层级边界插入电压/频率切换点
  典型节能：10-20%（整体推断能耗）
```

### 24.7.3 细粒度Power Gating

```
AI加速器的Power Gating层级:

芯片级（Chip-level）:
  NPU完全关断（Deep Sleep）
  关断时间：数ms，适合应用级空闲

模块级（Module-level）:
  MAC阵列块（如将256×256阵列分为4个64×64块）
  每块独立电源门控
  未使用的MAC块关断（小模型推断时）

  示例：MobileNet v3推断
    通道数少 → 仅需1/4 MAC阵列
    关断3/4 MAC阵列 → 节省75%计算功耗

PE级（PE-level）:
  单个PE或PE行关断（基于稀疏性）
  对应零激活值通道的PE行关断
  实现难度高，但收益可观

电源门控时序（100MHz时钟）:
  ┌─────┬──────────┬──────┬─────┐
  │ 使能│ 头部延迟  │ 计算 │ 关断│
  │      │ (~10周期)│      │     │
  └─────┴──────────┴──────┴─────┘
  最小关断时间 > 唤醒延迟（防止频繁开关）
```

### 24.7.4 热管理与功耗预算

```
AI推断的热管理策略:

动态热功耗管理（DTPM）for AI加速器:

  while True:
    T_current = 读取温度传感器()
    
    if T_current > T_critical (如95°C):
      # 紧急降频：立即执行

    elif T_current < T_low (如70°C):

      NPU_DVFS(提升1档)
    
    sleep(热采样周期 10ms)

AI工作负载的功耗包络控制（Power Capping）:
  TDP约束：整个AI加速器不超过设定TDP
  
  方法1：限制并发推断任务数

  方法4：多Die系统的Die间负载均衡

## 24.8 编译器与映射的功耗优化

### 24.8.1 算子融合减少访存

```
算子融合（Operator Fusion）降低中间张量的DRAM访问:

未融合执行（朴素方式）:
  Conv → [写DRAM] → BN → [写DRAM] → ReLU → [写DRAM]
  每个算子独立执行，中间结果写DRAM后再读回
  DRAM访问次数：3次写 + 2次读 = 5次

融合执行（Kernel Fusion）:
  Conv+BN+ReLU → 融合为单个Kernel
  中间结果保留在寄存器/L1缓存
  DRAM访问次数：1次写 = 1次（减少80%）

常见融合模式:
  ├── Conv + BN + ReLU（最常见）
  ├── Conv + Add（残差连接）
  ├── MatMul + Bias + Activation
  ├── LayerNorm + Linear（Transformer）
  └── Attention Score + Softmax + Dropout（FlashAttention思路）

FlashAttention的访存优化:
  标准注意力：S = Q×K^T (写HBM) → softmax(S) (读HBM) → A×V
  FlashAttention：在片上SRAM完成整个注意力计算
  HBM读写量降低：~5-10×（对长序列效果显著）
```

### 24.8.2 模型部署的内存布局优化

```
张量内存布局优化（Layout Optimization）:

NCHW vs NHWC:
  NCHW (batch, channel, height, width): GPU友好，通道在快速维
  NHWC (batch, height, width, channel): CPU/移动端友好，向量化友好

硬件对齐布局:
  假设硬件MAC阵列宽度=16（INT8）

  未对齐（通道数=13）:
    每行: [C0..C12, PAD PAD PAD]  ← 需要填充3个无效元素
    实际计算效率：13/16 = 81%

  对齐优化（填充到16）:
    补零到16通道
    MAC利用率：16/16 = 100%
    内存开销：+23%，但避免了低效计算路径

权重预排列（Weight Reorder）:
  根据硬件数据流模式预先排列权重内存布局
  消除运行时的地址计算开销
  典型收益：5-15%延迟降低，间接降低功耗
```

TVM / XLA 等编译器的自动调优流程:

输入：模型（ONNX/TF/PyTorch）+ 目标硬件

## 24.9 训练vs推断的低功耗设计差异

### 24.9.1 训练场景的功耗特征

```
训练 vs 推断 功耗特征对比:

维度              │ 推断（Inference）    │ 训练（Training）
──────────────────┼────────────────────┼────────────────────
计算量            │ 1×（前向传播）      │ ~3×（前向+反向+梯度）
精度要求          │ INT8/FP16即可       │ FP16/BF16/FP32
显存需求          │ 低（模型参数）      │ 高（参数+梯度+优化器状态）
批大小（batch）   │ 小（1-32）          │ 大（32-2048）
实时性约束        │ 有（延时约束）      │ 无（吞吐优先）
典型功耗          │ 5W-350W             │ 300W-700W（A100：400W TDP）
重复性            │ 重复推断相同模型    │ 持续迭代直到收敛
```

### 24.9.2 混合精度训练（AMP）

```
自动混合精度训练（AMP - Automatic Mixed Precision）:

动机：FP16训练 vs FP32训练
  ├── FP16 Tensor Core性能：FP32的8-16倍（A100）
  ├── FP16显存：FP32的1/2 → 支持更大batch
  └── 问题：FP16动态范围小（max≈65504），梯度下溢

AMP解决方案:

  ┌────────────────────────────────────────────────┐
  │  前向传播：FP16计算（快速）                     │
  │  ↓ FP16 loss                                  │
  │  损失缩放（Loss Scaling）:                     │
  │    loss_scaled = loss × scale_factor（如2¹⁰）  │
  │    防止FP16梯度下溢                            │
  │  ↓ FP16 scaled gradients                      │
  │  反向传播：FP16计算（快速）                     │
  │  ↓ 梯度反缩放 + 梯度裁剪                       │
  │  主权重（Master Weights）: FP32存储             │
  │    → FP32更新确保精度                          │
  │  → 复制到FP16副本用于下次前向                  │
  └────────────────────────────────────────────────┘

功耗收益：
  训练速度：1.5-3×（取决于网络结构）
  显存：节省约40%
  间接效果：训练时间缩短 → 总能耗降低
```

### 24.9.3 分布式训练的通信功耗优化

```
大规模分布式训练通信功耗:

AllReduce通信开销（梯度同步）:
  GPT-3（1750亿参数）每步梯度通信：
    参数量：175B × 2字节（FP16）= 350GB
    AllReduce通信量：~700GB/step（发送+接收）
    NVLink带宽：600GB/s → 通信时间：~1.2s
    通信功耗占比：~15-25%

通信功耗优化策略:

1. 梯度压缩（Gradient Compression）:
   Top-K稀疏化：仅传输最大的K%梯度
   1-bit Adam：梯度量化到1bit + 误差反馈
   通信量降低：10-100×

2. 梯度累积（Gradient Accumulation）:
   每N个mini-batch才同步一次梯度
   通信频率降低N倍，GPU利用率提升
   效果：等效增大batch size，减少通信轮次

3. 流水线并行（Pipeline Parallelism）:
   不同层放在不同GPU上
   层间通信量：仅activation（远小于梯度）
   通信量降低：~model_layer倍

4. 张量并行（Tensor Parallelism）:
   单个权重矩阵切分到多GPU
   通信量：行/列切分对应AllReduce/AllGather
   Megatron-LM: 最小化通信开销的切分策略
```

NAS（神经架构搜索）with 硬件感知:

  代表：FBNet（Facebook），MnasNet（Google）
  效果：比人工设计模型能效提升2-5×

量化感知架构设计:
  从设计之初就考虑低精度友好的结构
  如：ReLU代替GELU（量化更容易）
      避免异常值产生的结构设计
      
Once-for-All Network:
  训练一次，动态适应不同硬件约束
  同一模型参数支持边缘到云端全场景部署
  功耗可随硬件约束动态调整
```

### 24.11.3 绿色AI趋势

```
绿色AI（Green AI）与碳足迹优化:

训练大模型的碳排放：
  GPT-3训练：~552 tCO2e
  相比：纽约-旧金山往返机票 = ~0.7 tCO2e
  GPT-3 ≈ 790次往返机票碳排放

绿色AI行动方向：

1. 硬件能效提升:
   更高TOPS/W → 相同算力更少能耗
   目标：每5年能效翻4×

2. 可再生能源:
   谷歌：100%可再生能源匹配
   微软：2030碳负排放承诺
   数据中心PUE趋近1.1（Meta Prineville: 1.08）

3. 模型效率优化:
   知识蒸馏（Knowledge Distillation）：小模型继承大模型知识
   模型剪枝（Pruning）：删除冗余参数
   稀疏专家（Mixture of Experts）：条件计算，不激活全部参数
   GPT-4使用MoE：推断时只激活~12%的参数

4. 碳感知调度:
   在可再生能源充足时运行训练任务
   Google Carbon-Aware Computing：将训练迁移到低碳时段/地区

量化指标：
  2012→2019年：最佳模型实现相同ImageNet精度所需算力降低了44×
  2017→2022年：Transformer模型每年能效提升约2.5×
```
