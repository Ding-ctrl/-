# 第7章 电源管理单元设计

## 7.1 引言

电源管理单元（Power Management Unit, PMU）是SoC低功耗架构的"大脑"，负责协调和控制芯片内部所有电源域的供电状态、电压等级、时钟配置以及上下电时序。在复杂的多电源域SoC中，PMU的设计质量直接决定了低功耗策略能否安全、高效地执行。

现代旗舰移动SoC通常包含**10~30个独立电源域**，支持**5~8种系统级功耗状态**，涉及数十个电源开关、隔离单元、保持寄存器和时钟控制信号的精确时序协调。PMU不仅需要正确地执行复杂的电源状态转换，还要在微秒级甚至亚微秒级的时间内完成，以满足实时响应需求。

本章系统性地介绍PMU的架构设计、电源状态机、电源域控制序列、与PMIC的接口设计，以及PMU的验证方法。

### 7.2.2 PMU核心功能模块

| 模块 | 功能 | 关键指标 |
|------|------|---------|
| 电源状态机 (PSM) | 管理系统级与域级电源状态转换 | 状态数、转换延迟 |
| 电源域控制器 | 控制单个电源域的开关、隔离、保持 | 域数量、控制精度 |
| 时序引擎 (Sequencer) | 按预定义序列执行电源操作 | 步骤数、最小步长 |
| PMIC接口 | 与外部PMIC通信，调节电压 | 接口速度、协议支持 |
| 唤醒控制器 | 管理唤醒源、中断聚合 | 唤醒延迟、源数量 |
| 时钟管理 | 控制PLL、分频器、时钟门控 | 时钟域数、切换速度 |
| 看门狗定时器 | 防止系统死锁，超时复位 | 超时精度 |
| 调试接口 | 电源状态监控、调试支持 | 可观测性 |

### 7.2.3 PMU设计约束

```
PMU设计的核心约束:

1. Always-On约束
   └── PMU自身必须位于常开电源域(Always-On Domain)
       └── 即使其他所有域关断，PMU仍需工作
       └── PMU功耗直接计入系统最低功耗

2. 可靠性约束
   └── 电源控制序列必须100%正确
       └── 错误的上下电顺序可能导致:
           ├── 闩锁效应 (Latch-up) → 芯片损坏
           ├── 总线悬空 → 系统死锁
           └── 数据丢失 → 功能错误

3. 延迟约束
   └── 状态转换需在目标时间内完成
       ├── 唤醒延迟: 通常 < 100μs (移动设备)
       ├── 域切换: 通常 < 10μs
       └── 中断响应: 通常 < 1μs

4. 面积与功耗约束
   └── PMU本身应尽可能小、低功耗
       ├── 典型面积: < 0.5% SoC总面积
       └── 典型功耗: < 100μW (深度睡眠时)
```

## 7.3 电源状态定义与管理

### 7.3.1 系统级电源状态

现代SoC通常定义多层次的电源状态：

```
系统电源状态层次:

┌────────────────────────────────────────────────────┐
│ S0: Active (运行态)                                 │
│ └── 至少一个CPU核心在执行指令                        │
│     └── 子状态: S0i0(全速) / S0i1(低频) / S0i2(部分│
│         核心WFI) / S0i3(深度idle)                   │
├────────────────────────────────────────────────────┤
│ S1: Standby (待机态)                                │
│ └── 所有CPU核心停止，外设部分活跃                     │
│     └── DRAM自刷新，快速唤醒 (~100μs)               │
├────────────────────────────────────────────────────┤
│ S2: Deep Sleep (深度睡眠)                           │
│ └── 大部分电源域关断，仅保持关键状态                  │
│     └── CPU/GPU关断，保持寄存器活跃                  │
│     └── 唤醒延迟 ~1ms                               │
├────────────────────────────────────────────────────┤
│ S3: Suspend-to-RAM (挂起到内存)                     │
│ └── 仅Always-On域和DRAM供电                         │
│     └── 唤醒延迟 ~10ms                              │
├────────────────────────────────────────────────────┤
│ S4: Hibernate (休眠)                                │
│ └── 所有状态保存到非易失存储                          │
│     └── 仅RTC/唤醒逻辑供电                           │
│     └── 唤醒延迟 ~秒级                               │
├────────────────────────────────────────────────────┤
│ S5: Shutdown (关机)                                  │
│ └── 完全断电（可能保留RTC供电）                       │
└────────────────────────────────────────────────────┘
```

**系统状态功耗对比（典型移动SoC）：**

| 系统状态 | CPU | GPU | NPU | 外设 | DRAM | 总功耗 | 唤醒延迟 |
|---------|-----|-----|-----|------|------|--------|---------|
| S0-Active | ON | ON | ON | ON | Active | 2~8W | — |
| S0i3-Idle | WFI | OFF | OFF | 部分 | Active | 100~300mW | <10μs |
| S1-Standby | OFF | OFF | OFF | 部分 | Self-Ref | 5~20mW | ~100μs |
| S2-Deep Sleep | OFF | OFF | OFF | OFF | Self-Ref | 1~5mW | ~1ms |
| S3-Suspend | OFF | OFF | OFF | OFF | Self-Ref | 0.5~2mW | ~10ms |
| S4-Hibernate | OFF | OFF | OFF | OFF | OFF | <0.1mW | ~秒 |
| S5-Shutdown | OFF | OFF | OFF | OFF | OFF | <0.01mW | ~秒 |

### 7.3.2 电源域状态

每个电源域也有独立的状态定义：

```
电源域状态:

┌──────────┐  power_up   ┌──────────┐  sleep    ┌──────────┐
│   OFF    │────────────▶│   ON     │─────────▶│  SLEEP   │
│ (关断)   │◀────────────│ (活跃)   │◀─────────│ (休眠)   │
└──────────┘  power_down └──────────┘  wakeup  └──────────┘
      │                       │                      │
      │                       │   ret_enter           │
      │                       ▼──────────▶┌──────────┐│
      │                                   │RETENTION ││
      │                       ◀───────────│ (保持)   ││
      │                        ret_exit   └──────────┘│
      │                                               │
      └──── 可从任意状态直接进入OFF ─────────────────────┘

各状态特征:
┌──────────┬─────────┬──────────┬──────────┬──────────┐
│ 状态     │ 供电     │ 时钟     │ 数据保持  │ 漏电     │
├──────────┼─────────┼──────────┼──────────┼──────────┤
│ ON       │ VDD正常  │ 可用     │ ✓        │ 100%     │
│ SLEEP    │ VDD正常  │ 关断     │ ✓        │ ~60%     │
│ RETENTION│ VDD降低  │ 关断     │ ✓(影子)  │ ~15%     │
│ OFF      │ 无供电   │ 无       │ ✗        │ ~0%      │
└──────────┴─────────┴──────────┴──────────┴──────────┘
```

### 7.3.3 电源状态表 (Power State Table, PST)

电源状态表定义了在每种系统状态下各电源域的目标状态：

**示例PST（简化移动SoC）：**

| 系统状态 | CPU_Big域 | CPU_Little域 | GPU域 | NPU域 | Modem域 | Always-On域 | IO域 |
|---------|----------|-------------|-------|-------|---------|------------|------|
| S0-Full | ON | ON | ON | ON | ON | ON | ON |
| S0-Compute | ON | ON | OFF | ON | OFF | ON | ON |
| S0-Light | OFF | ON(低频) | OFF | OFF | ON | ON | ON |
| S1-Standby | OFF | RET | OFF | OFF | RET | ON | SLEEP |
| S2-DeepSleep | OFF | RET | OFF | OFF | OFF | ON | OFF |
| S3-Suspend | OFF | OFF | OFF | OFF | OFF | ON | OFF |

**UPF电源状态表声明：**

```tcl
# UPF 电源状态表定义示例
add_power_state cpu_big_domain \
  -state ON   {-supply_expr {power == FULL_ON  && ground == FULL_ON}} \
  -state RET  {-supply_expr {power == RETAIN   && ground == FULL_ON}} \
  -state OFF  {-supply_expr {power == OFF      && ground == FULL_ON}}

add_power_state system \
  -state S0_FULL    {-logic_expr {cpu_big@ON   && cpu_lit@ON  && gpu@ON  && aon@ON}} \
  -state S1_STANDBY {-logic_expr {cpu_big@OFF  && cpu_lit@RET && gpu@OFF && aon@ON}} \
  -state S3_SUSPEND {-logic_expr {cpu_big@OFF  && cpu_lit@OFF && gpu@OFF && aon@ON}}
```

## 7.4 PMU核心组件设计

### 7.4.1 电源状态机 (Power State Machine)

电源状态机是PMU的核心逻辑，管理系统级和域级的状态转换：

```
                        电源状态机架构

┌──────────────────────────────────────────────────┐
│                  系统级FSM                         │
│                                                   │
│  ┌─────┐  ┌─────┐  ┌─────┐  ┌─────┐  ┌─────┐  │
│  │ S0  │─▶│ S1  │─▶│ S2  │─▶│ S3  │─▶│ S5  │  │
│  │     │◀─│     │◀─│     │◀─│     │◀─│     │  │
│  └──┬──┘  └─────┘  └─────┘  └─────┘  └─────┘  │
│     │                                            │
│     │ 触发域级状态转换                              │
│     ▼                                            │
│  ┌──────────────────────────────────────────┐    │
│  │          域级FSM (每个电源域一个)           │    │
│  │                                          │    │
│  │  ┌─────┐  ┌─────┐  ┌─────┐  ┌─────┐   │    │
│  │  │ ON  │─▶│SLEEP│─▶│ RET │─▶│ OFF │   │    │
│  │  │     │◀─│     │◀─│     │◀─│     │   │    │
│  │  └─────┘  └─────┘  └─────┘  └─────┘   │    │
│  └──────────────────────────────────────────┘    │
│                                                   │
│  每个域FSM输出控制信号:                             │
│  - power_switch_en (电源开关控制)                   │
│  - isolation_en (隔离使能)                          │
│  - retention_en (保持使能)                          │
│  - clk_enable (时钟使能)                            │
│  - reset_n (复位控制)                               │
└──────────────────────────────────────────────────┘
```

**状态机RTL伪代码（域级FSM）：**

```verilog
// 域级电源状态机
module domain_power_fsm (
    input  wire        clk_aon,        // Always-on时钟
    input  wire        rst_n,          // 异步复位
    input  wire [1:0]  target_state,   // 目标状态 (来自系统FSM)
    input  wire        ack_pwr_switch, // 电源开关应答
    input  wire        ack_clamp,      // 隔离应答
    output reg         pwr_switch_en,  // 电源开关使能
    output reg         isolation_en,   // 隔离使能
    output reg         retention_en,   // 保持使能
    output reg         clk_enable,     // 时钟使能
    output reg         reset_n_out,    // 复位输出
    output reg [1:0]   current_state,  // 当前状态
    output reg         transition_done // 转换完成标志
);

// 状态编码
localparam ST_OFF   = 2'b00;
localparam ST_RET   = 2'b01;
localparam ST_SLEEP = 2'b10;
localparam ST_ON    = 2'b11;

// 状态机实现
always @(posedge clk_aon or negedge rst_n) begin
    if (!rst_n) begin
        current_state <= ST_OFF;
    end else begin
        case (current_state)
            ST_OFF: begin
                if (target_state == ST_ON)
                    // 启动上电序列
                    current_state <= ST_ON;  // 通过时序引擎
            end
            ST_ON: begin
                case (target_state)
                    ST_SLEEP: current_state <= ST_SLEEP;
                    ST_RET:   current_state <= ST_RET;
                    ST_OFF:   current_state <= ST_OFF;
                endcase
            end
            // ... 其他状态转换
        endcase
    end
end
endmodule
```

### 7.4.2 时序引擎 (Power Sequencer)

时序引擎负责按预定义的顺序和时间间隔执行电源控制操作：

```
上电序列 (Power-Up Sequence):

步骤   操作                    时间      说明
─────────────────────────────────────────────────────
 1     启动PMIC电压轨          0μs       通过I²C/SPMI命令
 2     等待电压稳定             ~100μs    PMIC建立时间
 3     释放电源开关 (PSW=ON)    ~105μs    头开关逐步导通
 4     等待电源稳定             ~110μs    IR-drop稳定
 5     保持复位有效             ~110μs    RST_N=0
 6     释放隔离 (ISO=OFF)       ~112μs    数据可以流通
 7     恢复保持数据 (RET→FF)    ~113μs    如果之前是Retention
 8     启动时钟 (CLK=ON)        ~115μs    PLL/分频器使能
 9     释放复位 (RST_N=1)       ~120μs    域开始运行
10     发送完成信号             ~120μs    通知系统FSM
─────────────────────────────────────────────────────

下电序列 (Power-Down Sequence):

步骤   操作                    时间      说明
─────────────────────────────────────────────────────
 1     软件保存上下文           0μs       可选，由软件执行
 2     关断时钟 (CLK=OFF)       ~1μs      停止域内翻转
 3     保存保持数据 (FF→RET)    ~2μs      如果需要Retention
 4     使能隔离 (ISO=ON)        ~3μs      隔离域边界信号
 5     关断电源开关 (PSW=OFF)   ~5μs      切断供电
 6     （可选）关闭PMIC轨       ~10μs     通过I²C/SPMI
 7     发送完成信号             ~10μs     通知系统FSM
─────────────────────────────────────────────────────
```

**时序引擎架构：**

```
┌─────────────────────────────────────────────────┐
│              时序引擎 (Sequencer)                  │
│                                                   │
│  ┌───────────────────────────────────────────┐   │
│  │            微程序存储器 (μROM)              │   │
│  │                                           │   │
│  │  Step 0: WAIT  100μs                      │   │
│  │  Step 1: SET   pwr_switch_en = 1          │   │
│  │  Step 2: WAIT  5μs                        │   │
│  │  Step 3: CLR   isolation_en = 0           │   │
│  │  Step 4: SET   retention_restore = 1      │   │
│  │  Step 5: WAIT  2μs                        │   │
│  │  Step 6: SET   clk_enable = 1             │   │
│  │  Step 7: WAIT  5μs                        │   │
│  │  Step 8: CLR   reset_n = 1                │   │
│  │  Step 9: DONE                             │   │
│  └───────────────────┬───────────────────────┘   │
│                      │                            │
│  ┌───────────────────▼───────────────────────┐   │
│  │          步骤计数器 + 定时器                │   │
│  │  PC: 当前步骤指针                          │   │
│  │  Timer: 等待计数器                         │   │
│  │  ACK: 应答检查逻辑                         │   │
│  └───────────────────┬───────────────────────┘   │
│                      │                            │
│  ┌───────────────────▼───────────────────────┐   │
│  │          控制信号输出寄存器                  │   │
│  │  pwr_switch_en, isolation_en,             │   │
│  │  retention_en, clk_enable, reset_n        │   │
│  └───────────────────────────────────────────┘   │
└─────────────────────────────────────────────────┘
```

**可编程时序引擎的优势：**

| 特性 | 硬编码FSM | 可编程时序引擎 |
|------|---------|-------------|
| 灵活性 | 固定流程 | 可通过软件修改 |
| 调试 | 需重新流片 | 可在线调整 |
| 复杂度 | 适合简单域 | 支持复杂多步骤 |
| 面积 | 较小 | 较大(含μROM) |
| 适用场景 | 少量域、固定流程 | 多域、需灵活调整 |

### 7.4.3 电源开关控制器 (Power Switch Controller)

电源开关控制器管理域内电源头开关(Header Switch)或脚开关(Footer Switch)的导通过程：

```
电源开关渐进导通 (Daisy-chain / Staged Turn-on):

VDD_MAIN ─────────────────────────────────────────
              │         │         │         │
           ┌──┴──┐   ┌──┴──┐   ┌──┴──┐   ┌──┴──┐
           │SW_0 │   │SW_1 │   │SW_2 │   │SW_N │
           │(强) │   │(中) │   │(弱) │   │(弱) │
           └──┬──┘   └──┬──┘   └──┬──┘   └──┬──┘
              │         │         │         │
VDD_LOCAL ────┴─────────┴─────────┴─────────┴────

导通时序:
              ┌─────────────────────────
SW_0 (粗)  ───┘                          ← 第1阶段: 粗调开关
                   ┌────────────────────
SW_1 (中)  ────────┘                     ← 第2阶段: 中间开关
                        ┌───────────────
SW_2~N (细) ────────────┘                ← 第3阶段: 细调开关

           ────────────────────▶ 时间
VDD_LOCAL:  0V → 慢上升 → 快上升 → VDD稳定

目的: 限制浪涌电流(Inrush Current), 防止VDD_MAIN压降过大
```

**浪涌电流控制策略：**

| 策略 | 原理 | 浪涌电流 | 上电时间 | 复杂度 |
|------|------|---------|---------|--------|
| 一次全开 | 所有开关同时导通 | 最大 (危险) | 最快 | 最低 |
| 菊花链(Daisy-chain) | 逐个导通 | 小但时间长 | 最慢 | 中等 |
| 分阶段(Staged) | 分组导通 | 中等,可控 | 中等 | 中等 |
| 斜坡(Ramp) | 渐进增大导通比 | 最小,平滑 | 可调 | 最高 |

### 7.4.4 唤醒控制器 (Wakeup Controller)

```
┌──────────────────────────────────────────────────┐
│               唤醒控制器架构                       │
│                                                   │
│  唤醒源:                                          │
│  ┌──────────┐  ┌──────────┐  ┌──────────┐       │

### 7.6.2 AO域功耗优化

AO域的功耗是系统最低功耗的下限，必须严格优化：

**AO域功耗预算（典型移动SoC）：**

| AO域组件 | 功耗 (深度睡眠时) | 优化措施 |
|---------|-----------------|---------|
| PMU状态机 | ~5μW | 高Vt标准单元，最小化逻辑 |
| 32kHz振荡器 | ~2μW | 低功耗RC/Crystal振荡器 |
| RTC | ~1μW | 最小化计数器位宽 |
| 唤醒控制 | ~3μW | 组合逻辑为主，减少寄存器 |
| PMIC接口(待机) | ~2μW | 接口时钟门控 |
| 关键寄存器 | ~5μW | 高Vt保持寄存器 |
| 复位/检测电路 | ~2μW | 低功耗比较器 |
| AO互连 | ~3μW | 最小化布线 |
| **总计** | **~23μW** | — |

**AO域设计原则：**

```
1. 最小化逻辑量
   └── 只保留绝对必要的功能
   └── 可推迟到唤醒后执行的逻辑不放入AO域

2. 使用高Vt单元
   └── 所有AO域逻辑使用HVT(高阈值电压)标准单元
   └── 漏电降低5~10倍 (vs SVT)

3. 使用低频时钟
   └── AO域运行在32.768kHz时钟
   └── 动态功耗极低 (P ∝ f)

4. 电压优化
   └── AO域可使用独立的低电压供电 (如0.5V~0.6V)
   └── 前提: 所有AO逻辑在此电压下满足时序

5. 门控一切可门控的时钟
   └── 即使在AO域内，非活跃模块的时钟也要门控
```

### 7.6.3 AO域与可关断域的接口

```
┌────────────────────┐    ┌────────────────────┐
│  Always-On Domain  │    │  Power-Gated Domain │
│                    │    │                     │
│  信号A ───────────[ISO]──── 信号A'            │
│                    │    │                     │
│  信号B ◀──────────[ISO]──── 信号B'            │
│                    │    │                     │
│  中断 ◀───────────[ISO]──── 中断请求          │
│  (唤醒)            │    │  (关断前需发出)      │
│                    │    │                     │
│                    │    │ [Level Shifter]     │
│  (若电压不同)      │    │  电平转换            │
└────────────────────┘    └────────────────────┘

关键规则:
- AO→可关断域: 加隔离单元，关断时输出安全值
- 可关断域→AO: 加隔离单元，防止浮空信号
- 电压不同时: 加电平转换器 (Level Shifter)
- 唤醒请求: 必须在AO域检测，作为唤醒源
```

## 7.7 低功耗调试支持

### 7.7.1 电源调试的挑战

```
低功耗调试的核心挑战:

1. 调试器连接问题
   └── JTAG/SWD控制器位于可关断域
       └── 进入深度睡眠后调试连接丢失
       └── 解决: 部分调试逻辑放入AO域

2. 状态可观测性
   └── 关断域内的寄存器不可读
       └── 需要在关断前保存关键状态
       └── 解决: PMU状态寄存器在AO域

3. 断点与单步
   └── 电源状态转换期间无法单步
       └── 解决: 可配置的"转换完成"断点

4. 时序观测
   └── 低频AO时钟限制采样率
       └── 解决: 专用的电源事件时间戳计数器
```

## 7.8 安全与保护机制

### 7.8.1 电源安全威胁

```
电源相关安全威胁:

1. 故障注入攻击 (Fault Injection)
   └── 通过电压毛刺导致密码模块计算错误
   └── 对策: 欠压/过压检测器 (BOD/OVP)

2. 侧信道攻击 (Side Channel)
   └── 通过功耗分析推导密钥
   └── 对策: 恒定功耗执行路径

3. 非法电源状态
   └── 软件错误或攻击导致非法状态转换
   └── 对策: 状态转换权限检查

4. 浪涌攻击
   └── 频繁触发上下电导致可靠性下降
   └── 对策: 转换频率限制器
```

### 7.8.3 安全启动与电源

```
安全启动电源序列:

1. 硬件POR (Power-On Reset)
   └── 电源轨达到阈值 → POR释放
   
2. PMU初始化
   └── 加载eFuse/OTP配置
   └── 配置默认电源状态
   
3. BootROM执行
   └── 最小电源配置 (仅必要域供电)
   └── 安全校验
   
4. 安全世界初始化
   └── TrustZone/安全飞地供电
   └── 密钥加载、完整性校验
   
5. 正常世界启动
   └── 逐步开启应用域
   └── 操作系统接管电源管理

安全约束:
- 安全域在非安全域之前供电
- 安全域的电源控制不可被非安全软件访问
- 紧急关断时安全域最后关断
```

│ - 完整的S0→S3→S0状态循环                     │

└──────────────────────────────────────────────┘
```

### 7.9.2 UPF验证

UPF (Unified Power Format, IEEE 1801) 是电源意图验证的基础：

**UPF验证检查项：**

| 验证项目 | 检查内容 | 工具支持 |
|---------|---------|---------|
| 隔离完整性 | 所有跨域信号都有隔离单元 | 形式化检查 |
| 电平转换覆盖 | 不同电压域之间有Level Shifter | 形式化检查 |
| 保持正确性 | Retention寄存器的保存/恢复行为 | 仿真+形式化 |
| 电源状态合法性 | 所有可能的状态组合合法 | 仿真 |
| 上下电顺序 | 控制信号时序正确 | 仿真+波形检查 |
| 腐蚀检测 | 关断域输出的X传播 | 仿真(PA仿真) |

**Power-Aware仿真流程：**

```
UPF驱动的仿真验证:

RTL设计文件
    │
    ├── design.sv/v (RTL源码)
    │
    ├── power_intent.upf (UPF文件)
    │   ├── 电源域定义
    │   ├── 隔离策略
    │   ├── 保持策略
    │   ├── 电平转换策略
    │   └── 电源状态表
    │
    ├── testbench.sv (验证环境)
    │   └── 电源控制序列 (模拟PMU行为)
    │
    └── 仿真器 (支持UPF)
        ├── Synopsys VCS (带UPF支持)
        ├── Cadence Xcelium (带UPF支持)
        └── Siemens Questa (带UPF支持)

仿真中的电源效果:
- 关断域: 输出变为X (不确定)
- 隔离单元: 输出钳位到安全值
- 保持寄存器: 保存/恢复寄存器值
- 电平转换: 电压域转换延迟建模
```

## 7.11 本章小结

本章详细介绍了电源管理单元(PMU)的设计方法，核心要点包括：

1. **PMU架构**：PMU是SoC低功耗策略的中枢，包含电源状态机、时序引擎、PMIC接口、唤醒控制器等核心模块
2. **电源状态管理**：系统级多层电源状态(S0~S5)与域级状态(ON/SLEEP/RETENTION/OFF)的协调管理
3. **时序引擎**：可编程时序引擎支持灵活的上下电序列，关键约束为"上电先开电源后释放隔离，下电先使能隔离后关电源"
4. **PMIC接口**：SPMI是移动SoC首选的PMIC接口，支持快速电压调节和中断聚合
5. **浪涌电流控制**：分阶段导通电源开关，防止VDD压降和闩锁效应
6. **Always-On域**：AO域功耗是系统最低功耗的下限，必须使用高Vt、低频时钟等技术严格优化
7. **安全保护**：欠压检测、温度保护、电压毛刺检测确保电源完整性和系统安全
8. **验证方法**：基于UPF的Power-Aware仿真是PMU验证的基础，需覆盖所有状态转换场景

> **下一章预告**：第8章将从SoC系统级角度，介绍低功耗集成与验证方法，包括全芯片低功耗架构规划、UPF/CPF驱动的设计流程、低功耗物理实现以及硅后功耗验证。
