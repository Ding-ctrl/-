# 第3章 电源域与电压岛设计

## 3.1 引言

在现代SoC设计中，不同功能模块对供电电压和电源管理有着差异化的需求。电源域（Power Domain）与电压岛（Voltage Island）设计是实现多电压、电源关断等低功耗技术的基础架构，也是UPF/CPF等低功耗标准所描述的核心对象。

合理的电源域划分可以在不影响系统功能的前提下，最大限度地降低静态功耗和动态功耗。本章系统性地介绍电源域与电压岛的基本概念、划分策略、关键电路单元以及基于UPF标准的设计方法。

## 3.2 基本概念

### 3.2.1 电源域 (Power Domain)

**定义：** 电源域是一组共享同一电源开关控制的逻辑单元集合。同一电源域中的所有单元可以被同时打开或关断。

**核心特征：**
- 一个电源域对应一个独立可控的电源区域
- 电源域可以被独立地上电、断电或保持
- 电源域之间的信号传递需要特殊处理（电平转换、隔离等）
- 每个电源域有明确的电源状态表（Power State Table）

```
SoC 电源域划分示例：

┌─────────────────────────────────────────────────┐
│                   Always-On Domain               │
│  ┌──────────┐  ┌──────────┐  ┌───────────────┐  │
│  │ PMU/PMIC │  │ Wakeup   │  │ Retention     │  │
│  │ Control  │  │ Logic    │  │ Registers     │  │
│  └──────────┘  └──────────┘  └───────────────┘  │
├─────────────────────────────────────────────────┤
│              可关断电源域                          │
│  ┌──────────────┐  ┌──────────────┐              │
│  │ CPU Domain   │  │ GPU Domain   │              │
│  │ (可独立关断)  │  │ (可独立关断)  │              │
│  └──────────────┘  └──────────────┘              │
│  ┌──────────────┐  ┌──────────────┐              │
│  │ NPU Domain   │  │ Modem Domain │              │
│  │ (可独立关断)  │  │ (可独立关断)  │              │
│  └──────────────┘  └──────────────┘              │
└─────────────────────────────────────────────────┘
```

### 3.2.2 电压岛 (Voltage Island)

**定义：** 电压岛是一组工作在相同供电电压下的逻辑单元集合。不同电压岛可以在不同电压等级下独立运行。

**与电源域的区别：**

| 特性 | 电源域 (Power Domain) | 电压岛 (Voltage Island) |
|------|----------------------|------------------------|
| 核心功能 | 电源开关控制（开/关）| 电压等级控制（高/低）|
| 主要目标 | 降低静态功耗（漏电）| 降低动态功耗（V²相关）|
| 关键电路 | 电源开关、隔离单元 | 电平转换器 (Level Shifter) |
| 状态管理 | 需要保持/恢复状态 | 不涉及状态丢失 |
| 实现复杂度 | 高（状态管理复杂）| 中等 |

**联合使用：** 实际设计中，电源域和电压岛通常结合使用。一个电源域可以是一个电压岛，也可以多个电源域共享一个电压岛。

### 3.2.3 多电压设计 (Multi-Voltage Design, MVD)

多电压设计是指在同一芯片中使用多个不同电压等级的技术。

**典型多电压配置：**

| 电压域 | 电压范围 | 供电对象 | 说明 |
|--------|---------|---------|------|
| VDD_HIGH | 0.9~1.1V | 高性能CPU核心 | 高频运行 |
| VDD_NOM | 0.7~0.85V | 中等性能模块 | 标准运行 |
| VDD_LOW | 0.5~0.65V | 低功耗外设 | 低速运行 |
| VDD_RET | 0.3~0.4V | 保持寄存器 | 仅维持状态 |
| VDD_IO | 1.8/3.3V | IO接口 | 外部接口标准 |
| VDD_AO | 0.7~0.8V | Always-on逻辑 | 常开域 |

**功耗收益分析：**

由动态功耗公式 P = α × C × V² × f，假设将电压从1.0V降到0.7V：

```
功耗比 = (0.7)² / (1.0)² = 0.49
```

即仅通过电压缩放，动态功耗可降低约51%。若同时降低频率（电压降低后最大频率也降低），总功耗降低更加显著。

## 3.3 电源域划分策略

### 3.3.1 划分原则

电源域划分需要综合考虑功能需求、功耗目标、时序约束和物理实现可行性。

**核心划分原则：**

1. **功能独立性原则**
   - 功能相对独立的模块划为同一电源域
   - 频繁交互的模块避免划入不同电源域（减少隔离/电平转换开销）

2. **活跃度差异原则**
   - 活跃度差异大的模块分属不同电源域
   - 长期空闲的模块应可独立关断
   - 始终活跃的模块放入Always-on域

3. **电压需求匹配原则**
   - 相同速度要求的模块共享电压岛
   - 不同频率需求的模块使用不同电压

4. **物理邻近原则**
   - 同一电源域的模块在物理版图上应连续
   - 减少电源网络布线复杂度
   - 避免电源域之间的交叉

#### (2) IoT芯片简化电源域

IoT芯片功耗预算极低（μW~mW级别），电源域设计更加精简：

| 电源域 | 包含模块 | 典型电压 | 关断场景 |

| Radio Domain | BLE/WiFi射频、基带 | 1.1V | 无通信时 |
| Sensor Domain | ADC、比较器、传感器接口 | 0.8V | 不采样时 |

### 3.3.3 电源状态表 (Power State Table, PST)

电源状态表定义了各电源域在不同系统状态下的供电情况。

| 普通使用 | ON (0.8V) | OFF | OFF | ON (0.9V) | ON (0.75V) | ON |

| 关机 | OFF | OFF | OFF | OFF | OFF | ON (RTC) |

## 3.4 电源开关网络 (Power Switch Network)

### 3.4.1 电源开关 (Power Switch/Header/Footer)

电源开关是实现电源关断（Power Gating）的核心单元，通过在电源轨和逻辑电路之间插入MOSFET开关来控制供电。

**两种拓扑：**

```
Header Switch (PMOS):              Footer Switch (NMOS):

    VDD (真实电源)                      ┌── 逻辑电路 ──┐
     │                                  │              │
    [PMOS开关] ← 控制信号              VDD            VVSS
     │                                                  │
    VVDD (虚拟电源)                    [NMOS开关] ← 控制信号
     │                                  │
    ┌── 逻辑电路 ──┐                   GND (真实地)
    │              │
   GND
```

**Header vs Footer对比：**

| 特性 | Header Switch (PMOS) | Footer Switch (NMOS) |
|------|---------------------|---------------------|
| 开关类型 | PMOS | NMOS |
| 导通电阻 | 较高（PMOS迁移率低）| 较低（NMOS迁移率高）|
| 面积 | 较大 | 较小 |
| IR-drop影响 | 影响VDD供电 | 影响GND网络 |
| 工业常用 | ✅ 更常用 | 较少用 |
| 适用场景 | 大多数数字逻辑 | 特殊模拟电路 |

**实际应用中Header Switch更常见的原因：**
- PMOS开关不影响GND网络的完整性
- 数字逻辑对VDD噪声的容忍度高于GND噪声
- EDA工具和标准单元库对Header Switch支持更完善

### 3.4.2 电源开关网络设计

在实际芯片中，电源开关不是单个器件，而是由大量开关单元组成的分布式网络。

**分布式电源开关网络：**

```
VDD (真实电源轨)
 │      │      │      │      │
[SW1] [SW2] [SW3] [SW4] [SW5]  ← 电源开关阵列
 │      │      │      │      │
VVDD ─────────────────────────  ← 虚拟电源轨 (连接到逻辑电路)
```

**关键设计参数：**

| 参数 | 说明 | 典型约束 |
|------|------|---------|
| 导通电阻 (Ron) | 开关导通时的等效电阻 | < 50~100mΩ |
| IR-drop | 通过开关网络的电压降 | < 3~5% VDD |
| 浪涌电流 (Inrush) | 上电瞬间的峰值电流 | < 电源供电能力 |
| 开关面积占比 | 电源开关占总面积比例 | 通常5%~15% |
| 关断漏电 | 开关关断后的剩余漏电 | < 1% 原始漏电 |

### 3.4.3 浪涌电流控制

电源域上电时，逻辑电路中的内部电容需要充电，会产生巨大的浪涌电流。如不加控制，可能导致电源网络电压暂降、相邻电源域被干扰。

**分步上电策略 (Daisy-Chain / Staggered Turn-on)：**

```
时间轴 →
           ┌───────────────────
SW_group1  │   导通
        ───┘
              ┌────────────────
SW_group2     │   导通
           ───┘
                 ┌─────────────
SW_group3        │   导通
              ───┘
                    ┌──────────
SW_group4           │   导通
                 ───┘

浪涌电流: ▁▂▃▄▅▆▇█ → ▂▂▂▂ (平滑化)
```

**具体实现方法：**

1. **菊花链 (Daisy-Chain)**
   - 电源开关串联使能信号
   - 前一组完全导通后触发下一组
   - 控制简单，但上电时间较长

2. **计数器控制**
   - 使用计数器逐步使能开关组
   - 可精确控制上电速率
   - 上电时间可配置

3. **电流检测反馈**
   - 监测浪涌电流大小
   - 电流超过阈值时暂停使能新开关
   - 最安全，但控制电路复杂

### 3.4.4 电源关断的时序考虑

```
关断流程：
1. 保存关键状态 → Retention寄存器
2. 发出隔离使能信号 → 隔离所有输出
3. 等待隔离生效 (数个时钟周期)
4. 关断时钟 → 停止电源域内所有翻转
5. 触发电源开关关断 → 切断供电

上电流程（反序）：
1. 分步导通电源开关 → 恢复供电
2. 等待电压稳定 (需考虑VVDD上升时间)
3. 恢复时钟
4. 释放隔离信号
5. 恢复状态 → 从Retention寄存器恢复
6. 正常运行
```

**关键时序约束：**
- 隔离信号必须在电源关断前生效
- 电源恢复后，需等待虚拟电源轨稳定才能释放隔离
- 时钟恢复应在隔离释放之前
- 整个流程需要严格的时序控制序列

## 3.5 隔离单元 (Isolation Cell)

### 3.5.1 隔离需求

当一个电源域被关断时，其输出信号变为不确定状态（浮动），可能在接收端产生以下问题：
- 短路电流（输入处于中间电平，PMOS和NMOS同时部分导通）
- 逻辑错误传播
- 未知状态影响后续电路功能

**隔离单元的作用：** 在电源域关断时，将该域的输出钳位到确定的逻辑值（0或1），防止不确定信号传播到活跃域。

### 3.5.2 隔离单元类型

| 类型 | 钳位值 | 实现方式 | 应用场景 |
|------|--------|---------|---------|
| Clamp-to-0 | 逻辑0 | AND门 + 隔离信号 | 默认低电平的信号 |
| Clamp-to-1 | 逻辑1 | OR门 + 隔离信号 | 默认高电平的信号（如使能信号取反）|
| Clamp-to-Latch | 保持关断前的值 | 锁存器 | 需保持最后状态的信号 |

**Clamp-to-0 隔离单元逻辑：**

```
                    ┌─────────┐
  数据输入 (from ──▶│         │
  关断域)           │  AND    │──▶ 数据输出 (to 活跃域)
                    │         │
  隔离使能 ────────▶│         │
  (ISO_EN, 活跃域)  └─────────┘

  当 ISO_EN = 0 时：输出 = 0 (钳位)
  当 ISO_EN = 1 时：输出 = 数据输入 (正常传输)
```

### 3.5.3 隔离单元放置规则

**关键规则：**

1. **供电域归属**
   - 隔离单元必须由始终有电的一侧供电
   - 通常放在接收端（活跃域侧）
   - 或使用专门的Always-on电源供电

2. **信号方向**
   - 仅对从可关断域输出到其他域的信号添加隔离
   - 输入信号（到可关断域）无需隔离（关断时不需要接收）

3. **隔离控制信号**
   - 隔离使能信号必须来自Always-on域
   - 隔离使能必须在电源关断前置为有效
   - 隔离释放必须在电源恢复后才能进行

4. **覆盖率**
   - 可关断域的所有输出信号都必须被隔离
   - 包括数据信号、控制信号、握手信号等
   - 漏隔离会导致功能错误或硬件损坏

## 3.6 电平转换器 (Level Shifter)

### 3.6.1 电平转换需求

当信号在不同电压岛之间传递时，由于电压等级不同，需要电平转换器来确保信号的正确识别。

**问题场景：**
- 低电压域（0.7V）输出的高电平信号进入高电压域（1.0V）
- 0.7V的高电平可能无法被1.0V域的接收器正确识别为逻辑"1"
- 反之，1.0V高电平进入0.7V域，可能导致过大电压，增加可靠性风险

### 3.6.2 电平转换器类型

#### (1) 低到高电平转换 (Low-to-High Level Shifter)

```
输入: VDD_L域的信号 (0 ~ VDD_L)
输出: VDD_H域的信号 (0 ~ VDD_H)

常见实现：交叉耦合锁存器 (Cross-coupled Latch)
```

| 参数 | 典型值 |
|------|--------|
| 延迟 | 0.1~0.5ns |
| 功耗 | 低 |
| 面积 | 小 |
| 最小电压差 | >100mV (通常) |

#### (2) 高到低电平转换 (High-to-Low Level Shifter)

```
输入: VDD_H域的信号 (0 ~ VDD_H)
输出: VDD_L域的信号 (0 ~ VDD_L)
```

- 相对简单，可通过简单的截断/限幅实现
- 注意过高输入电压对低压域器件的可靠性影响
- 可能需要串联电阻或钳位电路保护

#### (3) 使能型电平转换器 (Enable Level Shifter)

```
集成电平转换 + 隔离功能于一体

功能：
- 正常模式：电平转换
- 隔离模式：输出钳位值

优势：节省面积（一个单元替代两个）
```

#### (4) 保持型电平转换器 (Retention Level Shifter)

- 集成电平转换 + 锁存功能
- 在源电压域关断时保持最后的输出值
- 适用于需要状态保持的跨域信号

### 3.6.3 电平转换器的插入策略

| 场景 | 是否需要LS | 说明 |
|------|-----------|------|
| 同电压域内部信号 | 否 | 电压相同 |
| 低压域→高压域 | 是 (L→H) | 确保识别 |
| 高压域→低压域 | 可能需要 | 保护低压器件 |
| 跨电压且可关断 | 是 (Enable LS) | 同时处理电平和隔离 |

**自动插入流程（EDA工具）：**

```
1. UPF定义电压域和电源状态
2. 综合工具识别跨域信号
3. 自动在跨域边界插入电平转换器
4. 选择正确类型（L→H, H→L, Enable, Retention）
5. 后端布局时放置在域边界附近
```

## 3.7 状态保持 (Retention)

### 3.7.1 Retention寄存器

电源关断会导致寄存器内容丢失。对于需要快速恢复的电源域，使用Retention寄存器可以在关断期间保持关键状态。

**Retention寄存器结构：**

```
┌───────────────────────────────────────────┐
│  Retention Register                        │
│                                            │
│  ┌──────────┐      ┌──────────────────┐   │
│  │ 主寄存器  │─────▶│ 影子寄存器       │   │
│  │ (VDD供电) │ SAVE │ (VDD_RET供电)    │   │
│  │          │◀─────│ (低电压保持)      │   │
│  └──────────┘ REST │                   │   │
│                ORE  └──────────────────┘   │
└───────────────────────────────────────────┘

SAVE: 关断前，将主寄存器值复制到影子寄存器
RESTORE: 上电后，将影子寄存器值恢复到主寄存器
```

**关键信号：**

| 信号 | 方向 | 功能 |
|------|------|------|
| SAVE | 输入 | 触发保存操作（主→影子）|
| RESTORE | 输入 | 触发恢复操作（影子→主）|
| VDD | 电源 | 主寄存器供电（可关断）|
| VDD_RET | 电源 | 影子寄存器供电（Retention电压，持续供电）|

### 3.7.2 Retention策略选择

| 策略 | 面积开销 | 恢复速度 | 功耗开销 | 适用场景 |
|------|---------|---------|---------|---------|
| 全寄存器Retention | 高（每个FF加影子）| 最快（1-2周期）| 中等 | 快速唤醒场景 |
| 部分Retention | 中等 | 快 | 较低 | 仅关键状态需保持 |
| 存储器备份 | 低 | 慢（需DMA搬运）| 低 | 大量状态保存 |
| 无Retention | 无 | 最慢（重新初始化）| 最低 | 可接受长唤醒时间 |

### 3.7.3 Always-On逻辑

某些逻辑必须始终保持工作，不能被关断：

**必须放入Always-on域的模块：**
- 电源管理控制器 (PMU/PMIC接口)
- 唤醒中断控制器
- 实时时钟 (RTC)
- 看门狗定时器 (Watchdog)
- 隔离控制信号生成逻辑
- 电源开关控制序列器
- 关键调试接口 (JTAG TAP Controller)

**设计原则：**
- Always-on域的面积和功耗应尽量小
- 仅包含维持系统最低运行所需的逻辑
- 使用最低安全电压供电
- 典型Always-on域功耗占总芯片功耗的1%~5%

## 3.8 基于 UPF 2.0（IEEE 1801-2013）的低功耗设计规范

### 3.8.1 UPF 2.0 概述与版本演进

**UPF（Unified Power Format）** 是 IEEE 1801 标准族，用于以独立于 RTL 的方式描述芯片的完整电源架构。

| 版本 | 标准号 | 发布年份 | 主要新增能力 |
|------|--------|---------|------------|
| UPF 1.0 | IEEE 1801-2009 | 2009 | 基础电源域、隔离、Retention |
| **UPF 2.0** | **IEEE 1801-2013** | **2013** | Supply Set、`add_power_state`、层次化 UPF、`create_composite_domain` |
| UPF 3.0 | IEEE 1801-2015 | 2015 | 功能验证增强、Supply Set 扩展 |

> **本节所有命令均基于 UPF 2.0（IEEE 1801-2013）语法。**

**UPF 2.0 相对于 UPF 1.0 的关键变化：**
- 引入 **Supply Set**（`create_supply_set`）概念，以具名电源集合替代分散的电源网络引用
- 使用 `add_power_state` 替代 `create_pst` + `add_pst_state` 的旧式电源状态表写法
- 新增 `create_composite_domain` 支持跨层次的复合电源域
- `set_isolation` / `set_retention` / `set_level_shifter` 均可直接引用 Supply Set 名称
- 支持 `load_upf` 进行层次化 UPF 组合
- 新增 `set_scope` 精确控制命令作用范围

---

### 3.8.2 UPF 2.0 核心命令详解

#### (1) 顶层作用域设置

在 UPF 2.0 中，所有命令都需要明确作用于哪个设计层次。推荐在文件开头使用 `set_design_top` 声明顶层。

```tcl
# UPF 2.0: 声明设计顶层（必须，UPF 2.0 新要求）
set_design_top soc_top

# 使用 set_scope 切换当前命令作用范围（UPF 2.0 新增）
# 后续所有命令默认作用于 /soc_top
set_scope /soc_top
```

---

#### (2) 电源网络与端口定义

```tcl
# ── 顶层电源端口（来自 PAD / PMIC）──────────────────────
create_supply_port VDD      -direction in   ; # 主电源
create_supply_port VDD_RET  -direction in   ; # 保持电源
create_supply_port VSS      -direction in   ; # 地

# ── 内部电源网络 ─────────────────────────────────────────
create_supply_net VDD       -domain PD_TOP
create_supply_net VDD_CPU   -domain PD_CPU
create_supply_net VDD_GPU   -domain PD_GPU
create_supply_net VDD_RET   -domain PD_TOP
create_supply_net VSS       -domain PD_TOP

# ── 端口→网络连接 ────────────────────────────────────────
connect_supply_net VDD     -ports {VDD}
connect_supply_net VDD_RET -ports {VDD_RET}
connect_supply_net VSS     -ports {VSS}
```

---

#### (3) Supply Set 定义（UPF 2.0 核心新特性）

Supply Set 是 UPF 2.0 最重要的新概念：将一组相关的电源网络（primary/backup/retention/isolation…）封装为具名集合，后续所有策略直接引用集合名，而非逐条写出网络名。

```tcl
# ── 顶层 Always-On 域的 Supply Set ──────────────────────
create_supply_set SS_TOP \
    -function {primary   VDD} \
    -function {ground    VSS}

# ── CPU 域的 Supply Set（含保持和隔离电源）──────────────
create_supply_set SS_CPU \
    -function {primary   VDD_CPU} \
    -function {ground    VSS}     \
    -function {retention VDD_RET} \
    -function {isolation VDD}        ; # 隔离单元由 Always-On VDD 供电

# ── GPU 域的 Supply Set ──────────────────────────────────
create_supply_set SS_GPU \
    -function {primary   VDD_GPU} \
    -function {ground    VSS}     \
    -function {isolation VDD}
```

> **规则**：每个 Supply Set 的 `primary` 与 `ground` 函数为**必填项**；`retention` 和 `isolation` 仅在对应域有相关策略时才需声明。

---

#### (4) 电源域定义（UPF 2.0 语法）

UPF 2.0 的 `create_power_domain` 通过 `-supply` 选项直接绑定 Supply Set，不再在命令本身中引用具体网络名。

```tcl
# ── Always-On 顶层域 ─────────────────────────────────────
create_power_domain PD_TOP \
    -supply {primary SS_TOP}          ; # 绑定 Supply Set

# ── CPU 可关断域 ────────────────────────────────────────
create_power_domain PD_CPU \
    -elements {cpu_top}               \   ; # 对应 RTL 实例路径
    -supply   {primary   SS_CPU}      \
    -supply   {retention SS_CPU}

# ── GPU 可关断域 ────────────────────────────────────────
create_power_domain PD_GPU \
    -elements {gpu_top}               \
    -supply   {primary   SS_GPU}      \
    -supply   {isolation SS_GPU}

# ── 复合域（UPF 2.0 新增：跨子模块的联合域）────────────
# 当 CPU + NPU 必须同步上下电时可使用复合域
create_composite_domain PD_COMPUTE \
    -subdomains {PD_CPU PD_NPU}
```

> **与 UPF 1.0 对比**：UPF 1.0 写 `-supply {primary}`（裸字符串），UPF 2.0 写 `-supply {primary SS_CPU}`（Supply Set 对象）。

---

#### (5) 电源开关（Power Switch）定义

```tcl
# ── CPU 域电源开关 ───────────────────────────────────────
create_power_switch SW_CPU \
    -domain             PD_CPU              \
    -input_supply_port  {vin  VDD}          \   ; # 来自 Always-On VDD
    -output_supply_port {vout VDD_CPU}      \   ; # 输出到 CPU 域
    -control_port       {ctrl cpu_pwr_en}   \   ; # 控制信号（来自 AO 域 PMU）
    -on_state           {on_st  vin  {ctrl}}    \   ; # ctrl=1 → 导通
    -off_state          {off_st      {!ctrl}}       ; # ctrl=0 → 关断

# ── GPU 域电源开关（链式开关，减少浪涌电流）────────────
create_power_switch SW_GPU_HEAD \
    -domain             PD_GPU              \
    -input_supply_port  {vin  VDD}          \
    -output_supply_port {vout VDD_GPU_A}    \
    -control_port       {ctrl gpu_pwr_en}   \
    -on_state           {on_st  vin {ctrl}} \
    -off_state          {off_st    {!ctrl}}

create_power_switch SW_GPU_TAIL \
    -domain             PD_GPU              \
    -input_supply_port  {vin  VDD_GPU_A}    \   ; # 接上一级开关输出
    -output_supply_port {vout VDD_GPU}      \
    -control_port       {ctrl gpu_pwr_en}   \
    -on_state           {on_st  vin {ctrl}} \
    -off_state          {off_st    {!ctrl}}
```

> **UPF 2.0 规则**：`-on_state` 的格式为 `{<状态名> <input_supply_port_name> <控制表达式>}`；`-off_state` 的格式为 `{<状态名> <控制表达式>}`。控制表达式可使用 `!` 取反、`&&` / `||` 组合。

---

#### (6) 隔离单元策略（Isolation）

```tcl
# ── CPU 域输出隔离（UPF 2.0 语法）──────────────────────
set_isolation ISO_CPU_OUT \
    -domain           PD_CPU           \
    -applies_to       outputs          \   ; # 对该域所有输出端口生效
    -clamp_value      0                \   ; # 关断时输出箝位为 0
    -isolation_supply_set SS_CPU       \   ; # UPF 2.0: 引用 Supply Set 的 isolation 函数
    -location         parent               ; # 隔离单元放置在父域（PD_TOP）

# ── 隔离使能信号（UPF 2.0: 与策略分开声明）───────────
set_isolation_control ISO_CPU_OUT \
    -domain           PD_CPU           \
    -isolation_signal {cpu_iso_en}     \   ; # 来自 PMU（AO 域）
    -isolation_sense  high             \   ; # 高电平有效
    -location         parent

# ── 仅对不同电压跨域信号施加隔离（UPF 2.0 新增选项）──
set_isolation ISO_GPU_DIFF \
    -domain           PD_GPU           \
    -applies_to       outputs          \
    -clamp_value      0                \
    -diff_supply_only true             \   ; # ★ UPF 2.0 新增：仅在供电电压不同时插入隔离
    -isolation_supply_set SS_GPU       \
    -location         parent

set_isolation_control ISO_GPU_DIFF \
    -domain           PD_GPU           \
    -isolation_signal {gpu_iso_en}     \
    -isolation_sense  high             \
    -location         parent
```

> **`-diff_supply_only true`** 是 UPF 2.0 的重要新增选项：仅当信号穿越的两个域供电电压不同时才插入隔离单元，避免同电压域之间的冗余隔离单元，节省面积和功耗。

---

#### (7) 电平转换器策略（Level Shifter）

```tcl
# ── CPU 域输出电平转换（低→高）────────────────────────
set_level_shifter LS_CPU_OUT \
    -domain           PD_CPU           \
    -applies_to       outputs          \
    -rule             low_to_high      \   ; # 仅在目标电压更高时插入
    -location         parent               ; # 放置于父域

# ── GPU 域双向电平转换（UPF 2.0：可指定 threshold）──
set_level_shifter LS_GPU_INOUT \
    -domain           PD_GPU           \
    -applies_to       both             \   ; # 输入+输出均处理
    -rule             any              \   ; # 任意方向的电压差均转换
    -threshold        0.1              \   ; # 电压差 >0.1V 时才插入
    -location         self
```

> **UPF 2.0 规则**：`-rule` 可选值为 `low_to_high`、`high_to_low`、`any`；`-threshold` 指定最小电压差阈值（单位 V），低于此阈值则认为电压相同，不插入 Level Shifter。

---

#### (8) 状态保持策略（Retention）

```tcl
# ── CPU 域状态保持（UPF 2.0 语法）──────────────────────
set_retention RET_CPU \
    -domain                PD_CPU       \
    -retention_supply_set  SS_CPU       \   ; # UPF 2.0: 引用 Supply Set 的 retention 函数
    -save_signal    {cpu_save    posedge} \  ; # 上升沿触发保存
    -restore_signal {cpu_restore posedge}   ; # 上升沿触发恢复

# ── 仅保留关键寄存器（UPF 2.0: -elements 精确指定）────
set_retention RET_CPU_CRITICAL \
    -domain                PD_CPU           \
    -elements              {cpu_top/reg_file \
                            cpu_top/ctrl_reg} \
    -retention_supply_set  SS_CPU           \
    -save_signal    {cpu_save    posedge}   \
    -restore_signal {cpu_restore posedge}
```

> **与 UPF 1.0 对比**：UPF 1.0 使用 `-retention_power_net` + `-retention_ground_net` 分别指定保持电源和地线；UPF 2.0 统一用 `-retention_supply_set` 引用 Supply Set，工具自动从 `retention` 函数中解析电源/地网络。

---

#### (9) 电源状态定义（UPF 2.0 全新写法）

UPF 2.0 废弃了 `create_pst` + `add_pst_state` 的旧式写法，改用 `add_power_state` 直接在 Supply Set 或 Power Domain 上声明状态。

```tcl
# ── 在 Supply Set 上定义各网络的电压状态 ────────────────

# CPU 主电源的允许电压状态
add_power_state SS_CPU.primary \
    -state {FULL_ON   -supply_expr {power == 1.0}} \
    -state {LOW_VOL   -supply_expr {power == 0.7}} \
    -state {OFF       -supply_expr {power == off}}

# CPU 保持电源的允许电压状态
add_power_state SS_CPU.retention \
    -state {RET_ON    -supply_expr {power == 0.4}} \
    -state {OFF       -supply_expr {power == off}}

# ── 在 Power Domain 上定义域级组合状态 ─────────────────
add_power_state PD_CPU \
    -state {ACTIVE \
        -supply_expr {primary == FULL_ON && retention == RET_ON} \
        -simstate    NORMAL}                                      \
    -state {LOW_POWER \
        -supply_expr {primary == LOW_VOL && retention == RET_ON} \
        -simstate    NORMAL}                                      \
    -state {RETENTION \
        -supply_expr {primary == OFF     && retention == RET_ON} \
        -simstate    CORRUPT_ON_RESTORE}                          \
    -state {SHUTDOWN \
        -supply_expr {primary == OFF     && retention == OFF}    \
        -simstate    CORRUPT}

# ── 顶层 SoC 电源状态（涵盖所有子域的组合）────────────
add_power_state PD_TOP \
    -state {SYS_ACTIVE \
        -logic_expr {PD_CPU == ACTIVE && PD_GPU == ACTIVE}}    \
    -state {SYS_IDLE \
        -logic_expr {PD_CPU == ACTIVE && PD_GPU == RETENTION}} \
    -state {SYS_SLEEP \
        -logic_expr {PD_CPU == RETENTION && PD_GPU == SHUTDOWN}}
```

> **关键差异**：
> - `add_power_state` 的 `-supply_expr` 直接引用 Supply Set 函数名（`primary`、`retention` 等）和预定义电压状态名
> - `-simstate` 控制仿真器行为：`NORMAL`（正常）、`CORRUPT_ON_RESTORE`（恢复时可能损坏）、`CORRUPT`（已损坏）

---

#### (10) 层次化 UPF（UPF 2.0 多文件组织）

对于大型 SoC，推荐将 UPF 按层次拆分，使用 `load_upf` 组合。

```tcl
# ── 顶层 top.upf ─────────────────────────────────────────
set_design_top soc_top
set_scope /soc_top

# 定义顶层电源结构
create_supply_net VDD    -domain PD_TOP
create_supply_net VSS    -domain PD_TOP
create_supply_net VDD_RET -domain PD_TOP
create_supply_set SS_TOP \
    -function {primary VDD} -function {ground VSS}
create_power_domain PD_TOP -supply {primary SS_TOP}

# 加载子模块 UPF（UPF 2.0 层次化关键命令）
load_upf cpu.upf  -scope /soc_top/cpu_top   ; # CPU 子域 UPF
load_upf gpu.upf  -scope /soc_top/gpu_top   ; # GPU 子域 UPF

# ── 子模块 cpu.upf（在 cpu_top 范围内描述）──────────────
# set_design_top 无需重复，由 load_upf -scope 确定作用范围
create_supply_net VDD_CPU
create_supply_net VDD_RET
create_supply_set SS_CPU \
    -function {primary   VDD_CPU} \
    -function {ground    VSS}     \
    -function {retention VDD_RET} \
    -function {isolation VDD}
create_power_domain PD_CPU \
    -elements {.}              \   ; # "." 表示当前 scope 对应的实例
    -supply   {primary   SS_CPU} \
    -supply   {retention SS_CPU}
# ... 后续 set_isolation / set_retention / add_power_state ...
```

#### (11) UPF 2.0 完整示例（CPU 子域）

以下是一个自洽的 CPU 电源域 UPF 2.0 完整脚本，可直接用于 Synopsys VCS-LP / Cadence Genus 验证：

```tcl
##############################################################
# File : cpu_pd.upf
# Spec : IEEE 1801-2013 (UPF 2.0)
# Desc : CPU 电源域完整低功耗描述
##############################################################
set_design_top cpu_top

# 1. 电源网络
create_supply_net VDD_CPU
create_supply_net VDD_RET
create_supply_net VSS

# 2. Supply Set
create_supply_set SS_CPU \
    -function {primary   VDD_CPU} \
    -function {ground    VSS}     \
    -function {retention VDD_RET} \
    -function {isolation VDD}        ; # VDD 来自父域 PD_TOP

# 3. 电源域
create_power_domain PD_CPU \
    -elements {.}                \
    -supply   {primary   SS_CPU} \
    -supply   {retention SS_CPU}

# 4. 电源开关（由父域 UPF 定义，此处声明期望端口）
# create_power_switch 通常写在顶层 UPF

# 5. 隔离
set_isolation ISO_CPU \
    -domain                PD_CPU  \
    -applies_to            outputs \
    -clamp_value           0       \
    -diff_supply_only      true    \
    -isolation_supply_set  SS_CPU  \
    -location              parent
set_isolation_control ISO_CPU \
    -domain           PD_CPU      \
    -isolation_signal cpu_iso_en  \
    -isolation_sense  high        \
    -location         parent

# 6. 电平转换
set_level_shifter LS_CPU \
    -domain     PD_CPU   \
    -applies_to outputs  \
    -rule       any      \
    -threshold  0.1      \
    -location   parent

# 7. 状态保持
set_retention RET_CPU \
    -domain               PD_CPU \
    -retention_supply_set SS_CPU \
    -save_signal    {cpu_save    posedge} \
    -restore_signal {cpu_restore posedge}

# 8. 电源状态
add_power_state SS_CPU.primary \
    -state {FULL_ON -supply_expr {power == 1.0}} \
    -state {LOW_VOL -supply_expr {power == 0.7}} \
    -state {OFF     -supply_expr {power == off}}

add_power_state SS_CPU.retention \
    -state {RET_ON  -supply_expr {power == 0.4}} \
    -state {OFF     -supply_expr {power == off}}

add_power_state PD_CPU \
    -state {ACTIVE    -supply_expr {primary == FULL_ON && retention == RET_ON} -simstate NORMAL}             \
    -state {LOW_POWER -supply_expr {primary == LOW_VOL && retention == RET_ON} -simstate NORMAL}             \
    -state {RETENTION -supply_expr {primary == OFF     && retention == RET_ON} -simstate CORRUPT_ON_RESTORE} \
    -state {SHUTDOWN  -supply_expr {primary == OFF     && retention == OFF}    -simstate CORRUPT}
```

### 3.8.3 UPF 2.0 命令与 UPF 1.0 对照速查表

| 功能 | UPF 1.0（IEEE 1801-2009）| UPF 2.0（IEEE 1801-2013）| 说明 |
|------|--------------------------|--------------------------|------|
| 作用域 | 无显式声明 | `set_design_top` + `set_scope` | 2.0 强制要求声明 |
| 电源集合 | 无（逐条写网络名）| `create_supply_set` | 核心新特性 |
| 电源域绑定 | `-supply {primary}` | `-supply {primary SS_NAME}` | 引用 Supply Set |
| 电源状态表 | `create_pst` + `add_pst_state` | `add_power_state` | 彻底重写 |
| 仿真状态 | 无 | `-simstate` | 控制仿真器 X 传播 |
| 选择性隔离 | 无 | `-diff_supply_only` | 减少冗余隔离 |
| 隔离电源引用 | `-isolation_power_net` | `-isolation_supply_set` | 引用 Supply Set |
| 保持电源引用 | `-retention_power_net` | `-retention_supply_set` | 引用 Supply Set |
| 层次化加载 | 有限支持 | `load_upf -scope` | 正式标准化 |
| 复合域 | 无 | `create_composite_domain` | 多子域联动关断 |

### 3.8.4 UPF 2.0 设计流程与工具支持

```
┌──────────────────────────────────────────────────────────┐
│                  UPF 2.0 完整设计流程                     │
└──────────────────────────────────────────────────────────┘

  1. 架构规划
     └─ 确定电源域 / Supply Set / 电源状态

  2. 编写 UPF 2.0 文件（层次化）
     ├─ top.upf    → PD_TOP、电源网络、load_upf
     ├─ cpu.upf    → PD_CPU、SS_CPU、隔离、Retention、状态
     └─ gpu.upf    → PD_GPU、SS_GPU、隔离、状态

  3. RTL + UPF 功能仿真
     ├─ 工具：Synopsys VCS-LP / Cadence Xcelium-LP
     ├─ 检查：隔离单元 X 传播、Retention 保存/恢复时序
     └─ 关键：-simstate 驱动仿真器的 CORRUPT 行为

  4. 逻辑综合（Synthesis + UPF）
     ├─ 工具：Synopsys DC Ultra / Cadence Genus
     ├─ 自动插入：ICG、Isolation Cell、Level Shifter、Retention FF
     └─ 检查：read_upf → check_upf → report_power_domain

  5. 形式验证（Formal + UPF）
     ├─ 工具：Synopsys Conformal Low Power (CLP)
     └─ 验证：低功耗单元插入前后功能等价性

  6. 物理实现（APR + UPF）
     ├─ 工具：Synopsys IC Compiler II / Cadence Innovus
     ├─ 电源开关布局、电源环/条规划
     └─ UPF 驱动电源网格布线策略

  7. 签核验证
     ├─ 静态功耗：PrimeTime PX（读取 UPF + SAIF）
     ├─ 动态功耗：Voltus-Fi
     └─ IR-Drop：VDD_CPU 独立网格的电压降分析
```

## 3.9 物理实现考虑

### 3.9.1 电源网络设计

多电源域设计对物理实现提出额外要求：

| 设计要素 | 单电源域 | 多电源域 |
|----------|---------|---------|
| 电源轨数量 | VDD + VSS | 多组VDD + VSS + VVDD |
| 金属层资源 | 较少 | 更多（额外电源轨）|
| IR-drop | 简单分析 | 需分析每个域 |
| 电源开关 | 无 | 需要分布式布局 |
| 特殊单元 | 无 | LS、ISO、Retention FF |

### 3.9.2 Floorplan策略

```
好的Floorplan:                    差的Floorplan:
┌────────┬────────┐              ┌──┬──┬──┬──┐
│ Domain │ Domain │              │D1│D2│D1│D2│  ← 域交叉
│   A    │   B    │              ├──┼──┼──┼──┤
├────────┼────────┤              │D2│D1│D2│D1│  ← 电源网络
│ Domain │ Domain │              ├──┼──┼──┼──┤     复杂
│   C    │   D    │              │D1│D2│D1│D2│
└────────┴────────┘              └──┴──┴──┴──┘

✅ 域连续, 边界清晰               ❌ 域交错, 布线困难
```

**Floorplan原则：**
- 同一电源域的模块物理上连续
- 跨域信号路径最短化
- 电源开关沿域边界均匀分布
- 隔离单元和电平转换器放置在域边界

### 3.9.3 电源域间的IR-Drop分析

多电源域设计需要特别关注虚拟电源轨的IR-drop：

```
关键检查点：
1. 电源开关导通电阻造成的静态IR-drop
2. 瞬态电流引起的动态IR-drop
3. 多域同时上电时的电源噪声耦合
4. 不同PVT条件下的worst-case分析
```

## 3.11 本章小结

本章详细介绍了电源域与电压岛设计的核心内容，要点如下：

1. **基本概念**：电源域控制电源开关（开/关），电压岛控制电压等级（高/低），两者通常结合使用
2. **划分策略**：基于功能独立性、活跃度差异、电压需求和物理邻近性进行划分
3. **电源开关网络**：Header Switch是主流方案，需关注导通电阻、IR-drop和浪涌电流控制
4. **隔离单元**：防止关断域的不确定输出影响活跃域，必须确保100%覆盖
5. **电平转换器**：处理不同电压域之间的信号传递，EDA工具可自动识别和插入
6. **Retention设计**：通过影子寄存器在关断期间保持状态，实现快速唤醒
7. **UPF标准**：IEEE 1801提供统一的低功耗设计意图描述，贯穿整个设计流程
8. **物理实现**：需要良好的Floorplan规划和电源网络设计
