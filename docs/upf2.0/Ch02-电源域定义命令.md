# Ch02 - 电源域定义命令

## 2.1 create_power_domain

### 命令语法

```tcl
create_power_domain domain_name
    [-include_scope]
    [-elements {element_list}]
    [-supply {supply_set_handle}]
    [-atomic]
```

### 命令定义

`create_power_domain` 是 UPF 最核心的命令，用于**将设计中的逻辑单元划分为可独立控制电源的区域**。

### 参数详解

| 参数 | 含义 | 芯片上的影响 |
|------|------|------------|
| `domain_name` | 电源域名称 | 定义芯片上一个电压岛的逻辑标识 |
| `-include_scope` | 将当前作用域的所有元素包含在域内 | 该层次下所有逻辑都属于这个电压岛 |
| `-elements` | 明确指定属于该域的设计元素 | 精确控制哪些模块属于哪个电压岛 |
| `-supply` | 指定默认供电集合 | 确定该区域的供电来源 |
| `-atomic` | 声明域不可再细分 | 该区域作为不可分割的电源控制单元 |

### 对实际芯片的作用

#### 1. 形成电压岛 (Voltage Island)

```
芯片平面图（Floorplan）

┌─────────────────────────────────────────────────────────┐
│                    芯片 Die                               │
│                                                          │
│   ┌─────────────┐    ┌─────────────┐    ┌──────────┐    │
│   │             │    │             │    │          │    │
│   │  PD_CPU     │    │  PD_GPU     │    │ PD_DDR   │    │
│   │  VDD=0.9V   │    │  VDD=0.75V  │    │ VDD=1.1V │    │
│   │             │    │             │    │          │    │
│   │ ┌───┐ ┌───┐│    │ ┌────────┐  │    │  DDR PHY │    │
│   │ │CPU│ │CPU││    │ │Shader  │  │    │  DDR Ctrl│    │
│   │ │ 0 │ │ 1 ││    │ │Array   │  │    │          │    │
│   │ └───┘ └───┘│    │ └────────┘  │    └──────────┘    │
│   │ ┌─────────┐│    │ ┌────────┐  │                     │
│   │ │L2 Cache ││    │ │Texture │  │                     │
│   │ └─────────┘│    │ │Unit    │  │                     │
│   └─────────────┘    │ └────────┘  │                     │
│                      └─────────────┘                     │
│                                                          │
│   ┌─────────────────────────────────────────────────┐    │
│   │              PD_ALWAYS_ON (常开域)                │    │
│   │              VDD=0.9V (always on)                │    │
│   │   PMU | GIC | Timer | RTC | WakeUp Logic         │    │
│   └─────────────────────────────────────────────────┘    │
└─────────────────────────────────────────────────────────┘
```

**每个 `create_power_domain` 命令在芯片上形成一个独立的物理区域**，具有：

1. **独立的电源网格 (Power Grid)**：该区域有自己的 VDD 金属走线网络
2. **独立的控制能力**：可以单独开关电源、调节电压
3. **明确的物理边界**：在布局时会形成明确的区域划分
4. **边界处理需求**：域边界处需要插入隔离/电平转换单元

#### 2. 决定电源网格拓扑

不同的电源域划分直接决定了芯片上电源网格的结构：

```
金属层示意（截面图）

    M9 ═══════════════════════════════  VDD_TOP (全局电源环)
         │              │
    M8 ──┼──────────────┼──────────── VSS (全局地线)
         │              │
    M7 ═══╪══════╗      ╠════════════  VDD_CPU (通过 Switch)
         │      ║      ║
    M6 ──┼──────╫──────╫──────────── VDD_GPU (通过 Switch)
         │      ║      ║
         ▼      ▼      ▼
    Standard Cell Rail  Rail  Rail
    (M1)   VDD   VSS   VDD
```

### 使用示例

#### 示例 1：顶层域（常开域）

```tcl
# 顶层域：包含作用域内所有未被其他域覆盖的逻辑
# 芯片上：常开区域，包含 PMU、中断控制器等
create_power_domain PD_TOP -include_scope
```

**芯片影响**：`PD_TOP` 中的逻辑在任何功耗模式下都保持供电，这意味着这些逻辑使用的标准单元库是常开类型（non-switchable），电源网格直接连到顶层 VDD，不经过任何开关。

#### 示例 2：可关断域

```tcl
# CPU 子系统域：可以独立关断
# 芯片上：CPU 区域形成一个独立电压岛
create_power_domain PD_CPU -elements {u_cpu_subsys}
```

**芯片影响**：
- `u_cpu_subsys` 模块下的所有逻辑被归入 PD_CPU
- 后端实现时，这些逻辑会被放置在芯片上的指定区域
- 该区域的 VDD 通过电源开关供电（Virtual VDD）
- 关断时，该区域所有逻辑的供电被切断

#### 示例 3：层次化域

```tcl
# 在 CPU 子系统内部进一步划分
# 芯片上：CPU 电压岛内的子区域
create_power_domain PD_CPU_CORE0 \
    -elements {u_cpu_subsys/u_core0}
    
create_power_domain PD_CPU_CORE1 \
    -elements {u_cpu_subsys/u_core1}

create_power_domain PD_CPU_L2 \
    -elements {u_cpu_subsys/u_l2cache}
```

**芯片影响**：CPU 子系统内形成更细粒度的电源控制：
- Core0 和 Core1 可以独立关断（大小核调度）
- L2 Cache 有独立的电源控制（可能只降压不关断）
- 每个子域都有自己的 Virtual VDD 和开关逻辑

## 2.2 电源域的层次结构

### 父子域关系

```tcl
create_power_domain PD_TOP -include_scope          # 根域
create_power_domain PD_CPU -elements {u_cpu}        # PD_TOP 的子域
create_power_domain PD_CORE0 -elements {u_cpu/u_c0} # PD_CPU 的子域
```

**层次关系图：**

```
PD_TOP (根域，常开)
  ├── PD_CPU (可关断)
  │     ├── PD_CORE0 (可独立关断)
  │     ├── PD_CORE1 (可独立关断)
  │     └── (PD_CPU 中其余逻辑，如 L2 Cache)
  ├── PD_GPU (可关断)
  └── (PD_TOP 中其余逻辑，如 PMU、总线)
```

**芯片上的物理体现：**

- 子域在物理上被包含在父域区域内（或相邻）
- 电源开关形成层次：关断父域会同时关断所有子域
- 但子域可以独立关断而不影响父域

### 域的继承规则

```tcl
# 子域默认继承父域的 ground net
# 但可以有不同的 power net
set_domain_supply_net PD_TOP -primary_power_net VDD -primary_ground_net VSS
set_domain_supply_net PD_CPU -primary_power_net VDD_CPU -primary_ground_net VSS
# PD_CPU 使用独立的 VDD_CPU，但共享 VSS
```

**芯片影响**：共享 VSS 意味着在物理上，这些域的接地网格是连通的，但 VDD 网格是独立的。

## 2.3 域边界的芯片影响

当信号跨越电源域边界时，芯片上必须处理以下问题：

### 问题 1：源域关断时的输出不确定

```
            域边界
  PD_CPU (可关断)    │   PD_TOP (常开)
                     │
  ┌───┐              │
  │ FF├──── output ──┼──→ ???? (当 PD_CPU 关断时，
  └───┘              │         output 电平不确定！)
                     │         可能浮空、可能是中间电平
                     │         → 导致短路电流！
```

**解决方案**：在域边界插入**隔离单元** (Isolation Cell)

```
  PD_CPU (可关断)    │   PD_TOP (常开)
                     │
  ┌───┐         ┌────┼────┐
  │ FF├── out ──┤ ISO │    ├──→ 确定的 0 或 1
  └───┘         │ Cell│    │    (Clamp value)
                └────┼────┘
                     │
```

### 问题 2：跨域电压不匹配

```
  PD_CPU (0.9V)      │   PD_GPU (0.75V)
                      │
  ┌───┐               │   ┌───┐
  │ FF├── 0.9V 信号 ──┼──→│ FF│  电压不匹配！
  └───┘               │   └───┘  0.9V 信号直接驱动
                      │          0.75V 域的逻辑
                      │          → 可靠性问题！
```

**解决方案**：插入**电平转换器** (Level Shifter)

```
  PD_CPU (0.9V)      │   PD_GPU (0.75V)
                      │
  ┌───┐          ┌────┼────┐   ┌───┐
  │ FF├── 0.9V ──┤ LS │    ├──→│ FF│  正确的 0.75V
  └───┘          │Cell │    │   └───┘
                 └────┼────┘
                      │
```

## 2.4 电源域设计的最佳实践

### 2.4.1 域划分原则

| 原则 | 说明 | 芯片影响 |
|------|------|---------|
| **功能独立性** | 功能独立的模块划分为独立域 | 减少跨域信号数量，降低隔离/LS 开销 |
| **控制粒度** | 需要独立电源控制的模块独立成域 | 每个域需要独立的开关和控制逻辑 |
| **面积效率** | 避免过细的域划分 | 过多的域会增加开关、隔离单元面积 |
| **时序考虑** | 关键时序路径尽量在同一域内 | 跨域路径会经过 ISO/LS，增加延迟 |

### 2.4.2 常见错误

```tcl
# ❌ 错误：在同一模块内部划分域
create_power_domain PD_A -elements {u_top/u_mod/signal_a}
# signal_a 不是一个模块，不能作为域元素！

# ✅ 正确：以模块（instance）为粒度划分
create_power_domain PD_A -elements {u_top/u_mod_a}

# ❌ 错误：遗漏逻辑单元
create_power_domain PD_A -elements {u_mod_a}
create_power_domain PD_B -elements {u_mod_b}
# u_mod_c 没有被任何域覆盖！
# 它会隐式属于父域，但可能不是设计意图

# ✅ 正确：确保所有逻辑都被覆盖
create_power_domain PD_TOP -include_scope  # 捕获所有未分配的逻辑
create_power_domain PD_A -elements {u_mod_a}
create_power_domain PD_B -elements {u_mod_b}
```

## 2.5 高级域配置

### 2.5.1 -atomic 选项的使用场景

`-atomic` 声明电源域不可再被子域细分，适用于确保某些 IP 块的电源完整性：

```tcl
# 声明 DDR PHY 为原子域 — 不允许内部再划分子域
create_power_domain PD_DDR_PHY \
    -elements {u_ddr_phy} \
    -atomic

# 如果有人试图在 PD_DDR_PHY 内部创建子域，EDA 工具会报错
# create_power_domain PD_DDR_DQ -elements {u_ddr_phy/u_dq}  ← 错误！
```

**使用场景：**
- **模拟/混合信号 IP**：模拟电路的电源不能被数字逻辑的域划分干扰
- **硬核 IP (Hard Macro)**：已经完成物理实现的 IP，内部电源结构不可改变
- **关键路径模块**：确保时序关键的逻辑不会被域边界的 ISO/LS 打断

### 2.5.2 多层次域划分模式

在大型 SoC 中，域划分通常采用**层次化**方式：

```
方式一：平坦式 (Flat) — 适用于小型设计
┌──────────────────────────────────────┐
│ PD_TOP                               │
│  ├── PD_CPU                          │
│  ├── PD_GPU                          │
│  ├── PD_DDR                          │
│  └── PD_PERI                         │
└──────────────────────────────────────┘
所有域在同一个 UPF 文件中定义

方式二：层次式 (Hierarchical) — 适用于大型 SoC
┌──────────────────────────────────────┐
│ PD_TOP (soc_top.upf)                 │
│  ├── PD_CPU_SUBSYS (cpu_subsys.upf)  │
│  │     ├── PD_CORE0                  │
│  │     ├── PD_CORE1                  │
│  │     └── PD_L2                     │
│  ├── PD_GPU_SUBSYS (gpu_subsys.upf)  │
│  │     ├── PD_SHADER                 │
│  │     └── PD_TEXTURE                │
│  └── PD_PERI (peri.upf)              │
└──────────────────────────────────────┘
每个子系统有独立的 UPF 文件
通过 load_upf -scope 在顶层引用
```

### 2.5.3 域与 RTL 层次的对齐原则

```
原则：电源域边界应尽量与 RTL 模块边界对齐

✅ 好的对齐：
   RTL:  u_soc / u_cpu / u_core0    →  PD_CORE0
         u_soc / u_cpu / u_core1    →  PD_CORE1
         u_soc / u_gpu              →  PD_GPU
   
   域边界 = 模块边界
   → 跨域信号 = 模块间接口信号（数量少、定义清晰）
   → EDA 工具容易处理

❌ 差的对齐：
   RTL:  u_soc / u_subsys / module_a 的一部分 → PD_A
         u_soc / u_subsys / module_a 的另一部分 → PD_B
   
   域边界切割模块内部
   → 跨域信号数量爆炸
   → 隔离/电平转换面积开销巨大
   → 时序闭合困难
```

### 2.5.4 不同 SoC 类型的典型域划分

**移动 SoC（如手机处理器）：**

| 域 | 特点 | 典型策略 |
|----|------|---------|
| CPU 各核心 | 独立关断 + Retention | Power Gating + DVFS |
| GPU | 独立关断，无 Retention | Power Gating |
| NPU/DSP | 独立关断 | Power Gating |
| Modem | 独立电压域 | DVFS |
| Always-On | 永不关断 | 最低漏电设计 |

**汽车 SoC（如座舱处理器）：**

| 域 | 特点 | 典型策略 |
|----|------|---------|
| 安全岛 (Safety Island) | 功能安全，独立域 | 冗余供电，不关断 |
| AP (应用处理器) | 可关断 | Power Gating |
| GPU/Display | 显示域独立 | 独立电压 |
| CAN/LIN 通信 | 常开 | 低功耗设计 |
| Always-On | PMU + 唤醒 | 最小面积 |

**IoT/可穿戴 SoC：**

| 域 | 特点 | 典型策略 |
|----|------|---------|
| 主处理器 | 大部分时间关断 | 深度 Power Gating + Retention |
| 传感器控制器 | 低频常开 | 超低压运行 |
| 无线通信 (BLE) | 间歇工作 | Power Gating |
| Always-On | RTC + 唤醒 | 亚阈值设计 |

## 2.6 本章小结

| 要点 | 说明 |
|------|------|
| `create_power_domain` 是 UPF 的基石 | 所有其他命令都建立在域划分的基础上 |
| 每个域 = 芯片上一个电压岛 | 独立的电源网格、开关控制能力 |
| 域边界 = 芯片上需要特殊处理的位置 | 隔离、电平转换、保持 |
| 域划分粒度影响面积和功耗 | 过粗无法精细控制，过细增加开销 |
