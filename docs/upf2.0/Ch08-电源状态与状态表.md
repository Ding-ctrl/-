# Ch08 - 电源状态与状态表

## 概述

电源状态 (Power State) 描述了芯片在某一时刻各个供电网络的电压值组合，而**电源状态表 (Power State Table, PST)** 定义了所有合法的状态组合。这些命令帮助 EDA 工具和验证环境理解芯片的合法工作模式。

---

## 8.1 add_power_state

### 命令语法

```tcl
add_power_state supply_or_domain
    -state {state_name [-supply_expr {expression}] [-logic_expr {expression}]}
    [-state ...] ...
```

### 命令定义

为一个供电网络或电源域定义其可能的**电压状态**。

### 参数详解

| 参数 | 含义 | 芯片上的影响 |
|------|------|------------|
| `supply_or_domain` | 供电网络/域名称 | 定义哪个网络的状态 |
| `-state` | 状态定义 | 该网络的一种电压工况 |
| `state_name` | 状态名称 | 逻辑标识（如 ON, OFF, DVFS_LOW） |
| `-supply_expr` | 供电表达式 | 该状态下网络的电压值 |
| `-logic_expr` | 逻辑表达式 | 该状态下域内逻辑的行为 |

### 对实际芯片的作用

`add_power_state` 定义了芯片在不同功耗模式下各个电源的电压值：

```
芯片功耗模式与各电源网络的电压对应关系：

┌──────────────────────────────────────────────────┐
│                                                   │
│  模式1: FULL_PERFORMANCE (全性能模式)              │
│  VDD = 0.9V, VDD_CPU = 0.9V, VDD_GPU = 0.8V     │
│  → 所有域全速运行                                  │
│                                                   │
│  模式2: CPU_ONLY (仅CPU模式)                       │
│  VDD = 0.9V, VDD_CPU = 0.9V, VDD_GPU = OFF       │
│  → GPU 关断，节省功耗                              │
│                                                   │
│  模式3: LOW_POWER (低功耗模式)                     │
│  VDD = 0.9V, VDD_CPU = 0.75V, VDD_GPU = OFF      │
│  → CPU 降压运行 (DVFS)，GPU 关断                   │
│                                                   │
│  模式4: DEEP_SLEEP (深度睡眠模式)                  │
│  VDD = 0.9V, VDD_CPU = OFF, VDD_GPU = OFF        │
│  → 仅常开域工作（PMU, RTC, WakeUp）               │
│                                                   │
└──────────────────────────────────────────────────┘
```

### 使用示例

```tcl
# ===== 为供电网络定义状态 =====

# 全局 VDD（常开）的状态
add_power_state VDD \
    -state {FULL_ON  -supply_expr {power == `{FULL_ON, 0.9}}} \
    -state {STANDBY  -supply_expr {power == `{FULL_ON, 0.9}}}
# VDD 始终 0.9V，因为是常开电源

# CPU 域电源的状态
add_power_state VDD_SW_CPU \
    -state {ON_HIGH  -supply_expr {power == `{FULL_ON, 0.9}}} \
    -state {ON_LOW   -supply_expr {power == `{FULL_ON, 0.75}}} \
    -state {OFF      -supply_expr {power == `{OFF}}}
# CPU 可以：满压运行 / 降压运行 / 完全关断

# GPU 域电源的状态
add_power_state VDD_SW_GPU \
    -state {ON       -supply_expr {power == `{FULL_ON, 0.8}}} \
    -state {OFF      -supply_expr {power == `{OFF}}}
# GPU 可以：正常运行 / 完全关断

# ===== 为电源域定义状态 =====
add_power_state PD_CPU \
    -state {ACTIVE_HIGH -supply_expr {power == `{FULL_ON, 0.9}} \
                        -logic_expr  {PD_CPU == ACTIVE}} \
    -state {ACTIVE_LOW  -supply_expr {power == `{FULL_ON, 0.75}} \
                        -logic_expr  {PD_CPU == ACTIVE}} \
    -state {RETENTION   -supply_expr {power == `{OFF}} \
                        -logic_expr  {PD_CPU == RETENTION}} \
    -state {POWER_OFF   -supply_expr {power == `{OFF}} \
                        -logic_expr  {PD_CPU == OFF}}
```

## 8.2 create_pst (UPF 1.0 风格)

### 命令语法

```tcl
create_pst pst_name -supplies {supply_list}

add_pst_state state_name -pst pst_name -state {voltage_list}
```

### 命令定义

创建一个**电源状态表**，定义所有供电网络的合法电压组合。

### 参数详解

| 参数 | 含义 | 芯片上的影响 |
|------|------|------------|
| `pst_name` | 状态表名称 | 芯片电源模式的完整描述 |
| `-supplies` | 参与的供电网络列表 | 哪些电源网络参与状态切换 |
| `state_name` | 状态名称 | 一种合法的电源模式 |
| `-state` | 各网络的电压值 | 该模式下每个网络的电压 |

### 对实际芯片的作用

PST 直接对应芯片 PMU（电源管理单元）的**状态机**：

```
PMU 状态机与 PST 的对应关系：

┌─────────────────────────────────────────────┐
│                PMU 硬件                       │
│                                              │
│   ┌──────────┐     ┌───────────────────┐    │
│   │ 状态寄存器 │────→│ 电源控制逻辑       │    │
│   │ (PST ID) │     │                   │    │
│   └──────────┘     │ → VDD_CPU 开关控制  │    │
│        ↑           │ → VDD_GPU 开关控制  │    │
│    软件写入         │ → DVFS 电压控制     │    │
│    或硬件触发       │ → 隔离使能控制      │    │
│                    │ → Retention 控制    │    │
│                    └───────────────────┘    │
│                                              │
│   PST 定义了所有合法的状态组合                  │
│   PMU 只能在这些合法状态之间切换               │
└─────────────────────────────────────────────┘
```

### 使用示例

```tcl
# 创建电源状态表
create_pst soc_pst -supplies {VDD VDD_SW_CPU VDD_SW_GPU}

# 定义合法的电源状态组合
#                                  VDD    VDD_SW_CPU  VDD_SW_GPU
add_pst_state FULL_PERFORMANCE \
    -pst soc_pst \
    -state {0.9    0.9         0.8}

add_pst_state CPU_ONLY \
    -pst soc_pst \
    -state {0.9    0.9         off}

add_pst_state LOW_POWER \
    -pst soc_pst \
    -state {0.9    0.75        off}

add_pst_state DEEP_SLEEP \
    -pst soc_pst \
    -state {0.9    off         off}
```

**对应的芯片行为：**

| PST 状态 | 芯片行为 | 典型应用场景 |
|----------|---------|------------|
| FULL_PERFORMANCE | 全速运行，最高功耗 | 高负载计算、游戏 |
| CPU_ONLY | GPU 关断，CPU 全速 | 纯计算任务 |
| LOW_POWER | CPU 降压降频，GPU 关断 | 后台任务 |
| DEEP_SLEEP | 仅常开域，最低功耗 | 待机、等待唤醒 |

## 8.3 UPF 2.0 统一电源状态 (Unified Power State)

### add_power_state 的增强用法 (UPF 2.0)

UPF 2.0 中，`add_power_state` 可以定义**跨域的复合电源状态**，替代 UPF 1.0 的 `create_pst`：

```tcl
# UPF 2.0 风格：在顶层定义系统级电源状态
add_power_state PD_TOP \
    -state {FULL_PERF \
        -logic_expr {
            (PD_CPU == ACTIVE_HIGH) && \
            (PD_GPU == ACTIVE) && \
            (PD_TOP == ACTIVE)
        }} \
    -state {CPU_ONLY \
        -logic_expr {
            (PD_CPU == ACTIVE_HIGH) && \
            (PD_GPU == POWER_OFF) && \
            (PD_TOP == ACTIVE)
        }} \
    -state {LOW_POWER \
        -logic_expr {
            (PD_CPU == ACTIVE_LOW) && \
            (PD_GPU == POWER_OFF) && \
            (PD_TOP == ACTIVE)
        }} \
    -state {DEEP_SLEEP \
        -logic_expr {
            (PD_CPU == RETENTION) && \
            (PD_GPU == POWER_OFF) && \
            (PD_TOP == ACTIVE)
        }}
```

### UPF 2.0 vs UPF 1.0 对比

```
UPF 1.0 (create_pst):
  - 基于供电网络的电压值列表
  - 简单直观但缺乏层次化能力
  - 不支持复杂的逻辑状态描述

UPF 2.0 (add_power_state):
  - 基于域和供电集合的状态表达式
  - 支持层次化、可复用的状态定义
  - 支持 logic_expr 描述逻辑行为
  - 可以描述更复杂的状态关系
```

## 8.4 状态转换约束

### 合法的状态转换路径

```
状态转换图：

  ┌──────────────┐     ┌──────────────┐
  │ FULL_PERF    │←───→│  CPU_ONLY    │
  │ (全性能)      │     │  (仅CPU)     │
  └──────┬───────┘     └──────┬───────┘
         │                     │
         │  ┌──────────────┐   │
         └─→│  LOW_POWER   │←──┘
            │  (低功耗)     │
            └──────┬───────┘
                   │
            ┌──────┴───────┐
            │  DEEP_SLEEP  │
            │  (深度睡眠)   │
            └──────────────┘

合法转换路径（芯片 PMU 必须遵守）：
  FULL_PERF ←→ CPU_ONLY    ✅ (只关/开 GPU)
  FULL_PERF ←→ LOW_POWER   ✅ (关 GPU + CPU 降压)
  CPU_ONLY  ←→ LOW_POWER   ✅ (CPU 降压)
  LOW_POWER ←→ DEEP_SLEEP  ✅ (关 CPU)
  
非法转换路径：
  FULL_PERF → DEEP_SLEEP   ❌ (不能直接从全速到深度睡眠)
  DEEP_SLEEP → FULL_PERF   ❌ (不能直接从深度睡眠到全速)
  
原因：中间需要经过隔离、保存、上电等一系列步骤
```

### 芯片上的实现

```
PMU 状态机（硬件实现）：

┌─────────────────────────────────────────────────┐
│ PMU State Machine                                │
│                                                  │
│  current_state ──→ ┌─────────────┐              │
│                    │ Next State  │              │
│  request     ──→   │ Logic       │──→ next_state│
│                    │             │              │
│  constraints ──→   │ (PST 约束)  │              │
│                    └─────────────┘              │
│                          │                       │
│                    ┌─────┴──────┐                │
│                    │ Sequence   │                │
│                    │ Controller │                │
│                    └─────┬──────┘                │
│                          │                       │
│           ┌──────────────┼──────────────┐        │
│           ▼              ▼              ▼        │
│     power_switch   isolation_en   save/restore   │
│     control        control        control        │
│                                                  │
└─────────────────────────────────────────────────┘
```

## 8.5 电源状态对验证的影响

### UPF-aware 仿真中的状态检查

```
仿真器（如 VCS/Xcelium）基于 PST 进行以下检查：

1. ✅ 检查是否进入了非法的电源状态组合
   → 如果 VDD_CPU=OFF 但 VDD_GPU=ON 不在 PST 中定义
   → 仿真器报错

2. ✅ 检查状态转换是否合法
   → 从 FULL_PERF 直接跳到 DEEP_SLEEP
   → 仿真器可发出警告

3. ✅ 检查关断域的信号行为
   → 关断域输出应为 X (不确定) 或被隔离的确定值
   → 未隔离的跨域信号 → 仿真器报错

4. ✅ 检查 Retention 行为
   → save 后关断，restore 后上电
   → 验证寄存器值是否正确恢复
```

## 8.6 本章小结

| 要点 | 说明 |
|------|------|
| `add_power_state` | 定义供电网络/域的电压状态 → 芯片的功耗模式 |
| `create_pst` | UPF 1.0 的状态表 → 合法电源模式组合 |
| PST 对应 PMU 状态机 | 芯片硬件只能在合法状态间切换 |
| 状态转换约束 | 不能任意跳转 → 需要遵循上/下电序列 |
| 验证支持 | 仿真器基于 PST 检查非法状态 |
