# 第9章 软件栈与操作系统

## 9.1 操作系统选型

高端座舱SoC通常运行**多个操作系统**，各司其职：

```
座舱SoC多操作系统生态

  ┌────────────────────────────────────────────────────────────┐
  │  操作系统         │ 应用场景         │ 优势                  │
  ├────────────────────────────────────────────────────────────┤
  │  Android Auto OS  │ IVI中控娱乐     │ 应用生态丰富（Play Store）│
  │  Linux（AOSP基础） │ 仪表/辅助功能   │ 开源，定制灵活           │
  │  QNX Neutrino     │ 安全关键功能    │ 微内核，ASIL-B认证，稳定  │
  │  RTOS（FreeRTOS） │ MCU实时控制     │ 极低延迟，确定性强        │
  │  AUTOSAR Classic  │ 安全岛控制      │ 汽车标准，功能安全支持    │
  └────────────────────────────────────────────────────────────┘
```

## 9.2 Android Automotive OS（AAOS）

### 9.2.1 AAOS架构

**Android Automotive OS** 是Google专为车载设计的Android分支（有别于Android Auto镜像投射）：

```
AAOS架构（基于Android 13/14）

  ┌──────────────────────────────────────────────────────────┐
  │  应用层（Apps）                                           │
  │  ├── 原生车载App（OEM内置）                               │
  │  │   ├── 车辆设置、空调控制、行车记录仪                   │
  │  │   └── 360环视、DMS驾驶员监控                           │
  │  ├── Google服务（GMS）                                    │
  │  │   ├── Google Maps（导航）                             │
  │  │   ├── Google Assistant（语音助手）                    │
  │  │   └── Google Play Store（应用商店）                   │
  │  └── 第三方App（QQ音乐、网易云、高德地图等）               │
  ├──────────────────────────────────────────────────────────┤
  │  Car Service（车辆服务框架）                               │
  │  ├── CarPropertyManager：车辆属性读写（车速/档位/门状态）  │
  │  ├── CarAudioManager：汽车音频管理（焦点/通道/音量）       │
  │  ├── CarHVACManager：空调控制                             │
  │  └── CarPowerManager：电源状态管理                        │
  ├──────────────────────────────────────────────────────────┤
  │  Android Framework                                       │
  │  ├── SurfaceFlinger（显示合成）                           │
  │  ├── AudioFlinger（音频路由）                             │
  │  ├── InputManagerService（输入管理）                      │
  │  └── PackageManagerService（应用管理）                    │
  ├──────────────────────────────────────────────────────────┤
  │  HAL层（硬件抽象层）                                       │
  │  ├── VHAL（Vehicle HAL）：与MCU/CAN通信的接口             │
  │  ├── Camera HAL3（摄像头抽象）                            │
  │  ├── Audio HAL（音频编解码器抽象）                         │
  │  ├── Display HAL（显示控制器抽象）                         │
  │  └── GNSS HAL（定位服务抽象）                             │
  ├──────────────────────────────────────────────────────────┤
  │  Linux内核（Android 13 基于 Linux 5.15 / GKI 2.0）       │
  │  ├── 驱动：GPU、NPU、ISP、VPU、WiFi、BT                   │
  │  ├── 安全：SELinux + Seccomp                              │
  │  └── 实时补丁：PREEMPT_RT（部分场景）                     │
  └──────────────────────────────────────────────────────────┘
```

### 9.2.2 VHAL（Vehicle Hardware Abstraction Layer）

VHAL是AAOS与车辆底层通信的核心接口：

```
VHAL通信架构

  Car App（Java）
      │ Car Service API（CarPropertyManager）
      ▼
  Car Service（System Process）
      │ VHAL AIDL接口
      ▼
  VHAL实现（OEM实现，native层）
      │ CAN/以太网/SOME/IP
      ▼
  MCU / 其他ECU（车辆信号源）

VHAL属性示例：
  ├── VEHICLE_SPEED（车速，只读，安全关键）
  ├── GEAR_SELECTION（档位，只读）
  ├── DOOR_LOCK（车门锁，可读写）
  ├── HVAC_TEMPERATURE_SET（空调温度设定，可读写）
  └── EV_BATTERY_LEVEL（电池电量，只读）
```

## 9.3 QNX Neutrino RTOS

### 9.3.1 QNX微内核架构

**QNX** 是业界最广泛使用的车载实时操作系统，以微内核（Microkernel）设计著称：

```
QNX微内核 vs Linux宏内核

  Linux（宏内核）              QNX（微内核）
  ┌────────────────┐           ┌────────────────┐
  │ 用户空间       │           │ 用户空间       │
  │ App            │           │ App + 驱动进程 │
  │                │           │ + 文件系统进程 │
  ├────────────────┤           │ + 网络协议进程 │
  │ 内核空间       │           ├────────────────┤
  │ 调度/内存/驱动 │           │ 微内核（最小）  │
  │ 文件系统/网络  │           │ 仅调度/IPC/内存│
  └────────────────┘           └────────────────┘

QNX优势：
  ├── 任意进程崩溃不影响内核稳定性（驱动运行在用户态）
  ├── 确定性调度（最坏情况中断延迟 < 10µs）
  ├── ASIL-B/D功能安全认证（TÜV认证）
  └── 适合仪表显示等安全关键场景
```

### 9.3.2 QNX在座舱中的应用

```
QNX负责的座舱功能

  仪表显示域
  ├── Qt渲染引擎（仪表UI）
  ├── 车速/转速/油量/警告灯显示
  └── ADAS信息叠加（HUD/仪表提示）

  安全显示通道
  ├── 接收来自MCU的ASIL-B安全信号
  └── 直接写入安全帧缓冲区（绕过Android GPU路径）

  实时任务调度
  ├── 屏幕开机显示（< 2s）
  └── 关键告警立即显示（优先级最高）
```

## 9.4 Hypervisor选型与配置

### 9.4.1 主流车载Hypervisor对比

| 特性 | QNX Hypervisor | ACRN | Green Hills INTEGRITY | OpenSynergy COQOS |
|------|--------------|------|----------------------|-------------------|
| 类型 | Type-1 | Type-1 | Type-1 | Type-1 |
| 开源 | 否（商业） | ✓（开源） | 否（商业） | 否（商业） |
| 安全认证 | ASIL-B | 进行中 | ASIL-D | ASIL-B/D |
| 支持Guest OS | QNX/Linux/Android | Linux/Android | INTEGRITY/Linux | QNX/Linux/Android |
| 实时性 | 高（µs级） | 中 | 极高（ns级） | 高 |

### 9.4.2 CPU核资源分配

```
CPU核分配方案（8核示例：1+3+4架构）

  Prime Core（1核）─────── QNX仪表VM（专属，低延迟保证）
  Performance Core（3核）── Android IVI VM（主力计算）
  Efficiency Core（4核）─── 系统服务 + Linux辅助 + 空闲

  内存分配（24GB示例）：
  ├── QNX VM：2GB（仪表UI + 安全服务）
  ├── Android VM：16GB（IVI OS + 应用 + 缓存）
  ├── Linux VM：2GB（ADAS可视化 + 系统服务）
  └── Hypervisor：1GB
  └── 共享/保留：3GB

  设备直通（Device Passthrough）：
  ├── 仪表屏显示控制器 → 直通给QNX VM（ASIL要求）
  ├── IVI屏显示控制器 → 直通给Android VM
  ├── 摄像头（部分） → 直通给Android VM
  └── CAN控制器 → 通过安全MCU，不直通
```

## 9.5 驱动框架与BSP

### 9.5.1 Android驱动框架（Linux内核驱动）

```
关键驱动模块

  GPU驱动
  ├── 内核态：DRM/KMS框架 + 厂商私有GPU驱动
  ├── 用户态：OpenGL ES / Vulkan ICD
  └── 桥接：EGL（连接渲染框架与显示系统）

  NPU驱动
  ├── 内核态：NPU设备驱动（内存分配/调度）
  └── 用户态：SNPE/TFLite Delegate（调用NPU）

  Camera驱动（V4L2框架）
  ├── 内核态：MIPI CSI控制器驱动 + 传感器驱动
  └── 用户态：Camera HAL3实现

  音频驱动（ALSA框架）
  ├── 内核态：I2S/TDM控制器驱动 + Codec驱动
  └── 用户态：ALSA lib + Audio HAL

  显示驱动（DRM框架）
  ├── 内核态：显示控制器驱动（CRTC/Encoder/Connector）
  └── 用户态：libdrm + SurfaceFlinger
```

## 9.7 OTA（空中下载更新）软件架构

```
OTA完整软件架构

  云端（TSP/OEM后台）
  ├── 版本管理服务器
  ├── 差分包生成（BSDiff/ZSTD压缩）
  └── 数字签名（私钥签名）

  车端OTA客户端（Android Service）
  ├── 1. 检查更新（HTTP轮询/推送）
  ├── 2. 下载（HTTPS，断点续传，带宽限速）
  ├── 3. 签名验证（HSM加速）
  ├── 4. 完整性校验（SHA-256）
  ├── 5. 解压/差分应用（A/B分区）
  └── 6. 重启切换

  支持的更新范围：
  ├── Android OS + 应用（全量/差分）
  ├── QNX仪表固件（全量）
  ├── MCU固件（CAN/ETH Bootloader刷写）
  ├── NPU模型（.dlc/.tflite文件替换）
  └── 地图数据（增量更新）

  OTA安全控制：
  ├── 防回滚：eFuse版本计数器
  ├── 失败回滚：A/B自动切换
  └── 更新前预检：磁盘空间、电量、车辆状态
```

## 小结

本章介绍了座舱SoC的完整软件生态：
- **Android Automotive OS**：车载定制Android，VHAL桥接车辆信号，支持GMS/三方App
- **QNX**：ASIL-B认证RTOS，承担仪表等安全关键显示功能
- **Hypervisor**：Type-1虚拟化，多OS隔离共存，CPU/内存/设备灵活分配
- **驱动框架**：DRM/V4L2/ALSA标准框架，厂商私有驱动实现
- **OTA**：完整安全空中升级，支持全车ECU差分更新
