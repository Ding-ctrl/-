# 第14章 HMI 人机交互设计

## 14.1 汽车 HMI 设计体系概述

### 14.1.1 多模态交互融合框架

```
座舱多模态交互体系

  输入模态：
  ┌──────────────────────────────────────────────────────────┐
  │  语音（Voice）   触控（Touch）  手势（Gesture）  视线（Gaze） │
  │      │               │              │               │      │
  │      ▼               ▼              ▼               ▼      │
  │  ┌─────────────────────────────────────────────────────┐  │
  │  │          多模态融合引擎（Multimodal Fusion）            │  │
  │  │  ├── 意图解析（Intent Recognition）                   │  │
  │  │  ├── 上下文维护（Context Manager）                    │  │
  │  │  └── 冲突消解（Conflict Resolution）                  │  │
  │  └─────────────────────────────────────────────────────┘  │
  └──────────────────────────────────────────────────────────┘
              │
              ▼
  输出模态：
  ├── 视觉（显示屏/HUD/氛围灯）
  ├── 听觉（车载音响/TTS语音反馈）
  └── 触觉（方向盘振动/座椅振动反馈）

设计原则（NCAP分心驾驶评测要求）：
  ├── 主要视线：不得离开道路 > 2s（单次操作）
  ├── 总操作时间：单个任务 < 12s
  ├── 手动操作步骤：≤ 3步完成常用功能
  └── 驾驶时：地图/导航类功能仅显示，禁止文字输入
```

## 14.2 语音交互系统

### 14.2.1 语音处理分级架构

```
语音系统处理流水线（端侧优先架构）

  麦克风阵列（4~8 mic）
       │  AEC（回声消除） + BF（波束成形） + NS（降噪）
       ▼
  ┌─────────────────────────────────────────────────────────┐
  │  Level 1：本地 KWS（关键词检测）                          │
  │  ├── 唤醒词：小艺/你好车机/Hi Bixby（< 50ms 响应）        │
  │  ├── 运行于：DSP 或 NPU 低功耗算法（< 5mW）               │
  │  └── 误唤醒率（FAR）：< 1次/10小时                        │
  ├─────────────────────────────────────────────────────────┤
  │  Level 2：本地 ASR（语音识别）                            │
  │  ├── 领域：车控（导航/空调/音乐/电话），识别率 ≥ 95%        │
  │  ├── 延迟：< 500ms（端到端，本地）                         │
  │  ├── 算法：CTC + Transformer（量化INT8，< 200MB模型）      │
  │  └── 语言：普通话 + 方言（粤语/四川话等）                  │
  ├─────────────────────────────────────────────────────────┤
  │  Level 3：云端 NLU（自然语言理解）/ LLM                   │
  │  ├── 处理开放域问答、百科查询、复杂指令                     │
  │  ├── 延迟：500ms~2s（依网络）                             │
  │  └── 离线降级：无网络时回退到 Level 2 本地能力             │
  └─────────────────────────────────────────────────────────┘

麦克风阵列信号处理（座舱SoC集成）：
  ├── 阵列拓扑：线阵（仪表台前方4mic）+ 吸顶1mic（后排）
  ├── AEC（回声消除）：基于 NLMS 算法，消除车载音响干扰
  ├── 波束成形（Beamforming）：MVDR/LCMV，空间滤波主驾方向
  └── 降噪（Noise Suppression）：RNNoise / DeepSpeech 深度学习降噪
```

### 14.2.2 TTS 语音合成

```
TTS（Text-to-Speech）系统要求

  音质目标：MOS（Mean Opinion Score）≥ 4.0（5分制）
  延迟目标：首帧输出 < 100ms（流式合成）
  模型大小：≤ 50MB（压缩后，本地部署）

  主流技术方案：
  ├── VITS（端到端，自然度高，推理慢）
  ├── FastSpeech2 + HiFi-GAN（速度/质量平衡，推荐）
  └── Tacotron2（成熟稳定，部分OEM使用）

  情感化 TTS：
  ├── 根据驾驶状态调整语速/语调（导航提示 vs 告警）
  ├── 个性化音色（用户自选音色包）
  └── 压力情绪检测：配合DMS（驾驶员状态监测）调整TTS语气
```

## 14.3 触控与手势交互

### 14.3.1 触控显示设计

```
车规触摸屏技术规格

  屏幕类型：
  ├── 中控屏：10~17英寸，IPS/OLED，亮度 ≥ 1000nit（日光可视）
  ├── 仪表屏：12.3英寸，OLED，亮度 ≥ 2000nit（对比度 ≥ 1500:1）
  └── HUD：视觉等效 AR-HUD投影，虚拟尺寸 ≥ 70英寸（10m处）

  触控性能指标：
  ├── 触控延迟：< 35ms（ISO 16505要求：视觉反馈 < 100ms）
  │   └── 驱动扫描周期：1ms（1kHz采样），固件处理：5ms，渲染：29ms
  ├── 触控精度：误差 < 2mm
  ├── 多点触控：≥ 10点同时识别
  ├── 湿手/手套操作：防水等级 IP54，手套（4mm）可识别
  └── 温度范围：-40°C ~ +85°C（触控IC工作温度）

  触控IC架构（座舱SoC集成 vs 独立方案）：
  ├── 集成方案：SoC内置触控控制器（高通SA8295P集成方式）
  │   优点：降低BOM，减少SPI/I2C通信延迟
  │   缺点：触控IC随SoC换代，不可独立升级
  └── 独立方案：Synaptics / Atmel 车规触控IC + SPI接口
      优点：灵活选型，支持独立固件升级
```

### 14.3.2 手势识别

```
手势识别方案对比

  方案A：摄像头 + CV 算法（2D手势）
  ├── 传感器：RGB或红外摄像头（60fps，720P）
  ├── 算法：MediaPipe Hands / 自研轻量CNN（运行于NPU）
  ├── 识别手势：挥手切歌/音量调节/接听电话/滑动翻页
  └── 局限：强光/遮挡时误识别率上升

  方案B：ToF + 深度图（3D手势）
  ├── 传感器：ToF传感器（检测距离 0.2~1.5m）
  ├── 算法：PointNet / VoxelNet（3D点云处理，NPU加速）
  ├── 识别精度：±5mm 手部位置，优于2D方案
  └── 成本：高于纯摄像头方案（ToF模组约$15~30）

  手势分类（车规HMI典型手势库）：
  ├── 静态手势：OK手势（确认）/ 手掌张开（通话免提）
  ├── 动态手势：
  │   左右滑：切换曲目/页面
  │   上下滑：调节音量/空调温度
  │   旋转：调节旋钮（如空调风量）
  └── 抑制区域：驾驶时手势仅响应方向盘区域 2D 简单手势

盲操设计原则：
  ├── 物理旋钮/按键：驾驶时优先（不需要低头找按钮）
  ├── 触觉反馈：旋钮旋转有段落感，按键有清晰行程
  └── 语音优先级：驾驶状态下，语音 > 手势 > 触控
```

## 14.4 视觉显示规范

### 14.4.1 UI 设计与 ASPICE 流程

```
HMI ASPICE（汽车 SPICE）开发流程

  SWE.1 需求分析（HMI Requirements）：
  ├── OEM HMI Style Guide 解析（字体/颜色/布局规范）
  ├── 功能需求：每个操作场景的交互流程
  └── 非功能需求：延迟目标/帧率/亮度/对比度

  SWE.2 设计（HMI Architecture Design）：
  ├── 组件化设计：Widget库（Button/List/Dial/MapView等）
  ├── 状态机定义：各界面状态转换图（FSM）
  └── 多OS渲染架构：Android/QNX 各自渲染管线

  SWE.3 实现：
  ├── Android：Jetpack Compose / Flutter（推荐）
  ├── QNX RTOS：Qt Automotive Suite（实时仪表板）
  └── 渲染引擎：OpenGL ES 3.2 / Vulkan（GPU渲染）

  SWE.4 单元测试 & SWE.5 集成测试：
  ├── 自动化 UI 测试：Appium（Android）/ Squish（Qt）
  ├── 帧率测试：确保 60fps 不掉帧（jank < 1%）
  └── A11Y（无障碍）测试：颜色对比度 ≥ 4.5:1（WCAG AA）

  SWE.6 系统测试：
  └── 用户研究（驾驶模拟器中的操作任务测试）
```

### 14.4.2 WCAG 车载适配

```
WCAG（Web Content Accessibility Guidelines）车载适配规范

  色彩可读性（SC 1.4.3/1.4.6）：
  ├── 文字与背景对比度：≥ 4.5:1（正常文字）
  ├── 大字体（≥18pt）：≥ 3:1
  └── 图标/按钮：≥ 3:1

  字体规范（适应车载强光环境）：
  ├── 最小字体：24pt（仪表盘 / 10英寸屏）
  ├── 推荐字体：无衬线体（思源黑体/Noto Sans SC）
  ├── 行距：≥ 1.5× 字体大小
  └── 禁止全大写长文字（辨识度低）

  图标设计：
  ├── 触控目标区域：≥ 48×48dp（物理尺寸 ≥ 10×10mm）
  ├── 图标含义：图形 + 文字标签（不得仅靠颜色区分状态）
  └── 状态颜色：绿色=正常，黄色=警告，红色=危险（符合ISO 2575）

  夜间/白天模式自动切换：
  ├── 根据环境光传感器（ALS）自动切换
  ├── 夜间模式：背光 ≤ 30% 最大亮度，深色主题
  └── 日间模式：背光自适应 30%~100%（OLED直射日光场景）
```

## 14.5 驾驶安全限制（Driver Distraction Mitigation）

```
驾驶中 HMI 安全操作限制

  触发条件：车速 > 0 km/h（D/R 档）

  禁止操作（车速 > 10 km/h 时不可用）：
  ├── 文字输入（目的地输入/短信编辑）
  ├── 视频播放（娱乐视频，主副驾屏幕）
  ├── 网页浏览
  └── 复杂设置菜单（> 3层嵌套）

  可用操作（仅显示/简单控制）：
  ├── 导航地图浏览（禁止输入，接受语音）
  ├── 音乐/媒体播放控制（方向盘/语音操作）
  ├── 接/挂电话（手势/语音）
  └── 空调/座椅加热简单调节（1~2步操作）

  NCAP 分心驾驶评测（Euro NCAP 2025+）：
  ├── ESA（Emergency Stop Signal Assessment）：
  │   测试碰撞预警信息是否在正确时机打断当前HMI显示
  ├── ADSA（Automated Driving System Assessment）：
  │   测试 L2+ 辅助驾驶功能的 HMI 信息呈现质量
  └── 评分项目：
      视线离开路面时长（< 2s/次）
      操作步骤数（≤ 3步）
      操作总时间（< 12s）
      视觉复杂度（界面信息密度）
```

## 14.6 DMS 驾驶员状态监测 HMI

```
DMS（Driver Monitoring System）HMI 集成

  监测维度：
  ├── 注意力（Attention）：视线方向、头部姿态
  ├── 瞌睡（Drowsiness）：眨眼频率（PERCLOS > 0.15 为高风险）
  ├── 分心（Distraction）：手机操作检测
  └── 情绪（Emotion，可选）：压力/激动状态

  报警分级与 HMI 呈现：
  ┌───────────────────────────────────────────────────────┐
  │  等级  │ 触发条件        │ HMI 响应                     │
  ├────────┼────────────────┼──────────────────────────────┤
  │  Level1│ 疲劳初始征兆    │ 仪表盘黄色图标 + 轻微提示音    │
  │  Level2│ 持续疲劳5s      │ 全屏警告动画 + 明显提示音      │
  │  Level3│ 持续疲劳10s     │ 红色告警 + 强制语音 + 座椅振动 │
  │  Level4│ 视线完全偏离15s │ 触发紧急停车辅助（L2+功能）    │
  └───────────────────────────────────────────────────────┘

  OMS（Occupant Monitoring System）：
  ├── 检测儿童遗忘（在车内无人状态时儿童遗留）
  ├── 安全带未系提醒（逐座位）
  └── 后排乘客提示（自动调整内后视镜/开启后排娱乐屏）

  NPU 算法需求：
  ├── DMS推理延迟：< 50ms（实时性要求）
  ├── 算力需求：1~3 TOPS（INT8量化，NPU加速）
  └── 摄像头：近红外（940nm）+ RGB，适应夜间/强光
```

## 14.7 AR-HUD 人机交互设计

```
AR-HUD（增强现实抬头显示）HMI设计规范

  信息分区设计（视野分区）：
  ┌────────────────────────────────────────────────────────┐
  │              驾驶员视野（FOV 10°×5°）                   │
  │  ┌─────────────────────────────────────────────────┐   │
  │  │  Zone A（主驾视线中心区）：导航路径叠加 + 安全距离  │   │
  │  │  Zone B（左侧）：当前车道线 + 变道提示             │   │
  │  │  Zone C（底部）：车速 + 限速 + TBT 导航指示        │   │
  │  └─────────────────────────────────────────────────┘   │
  └────────────────────────────────────────────────────────┘

  AR-HUD 渲染要求（座舱SoC）：
  ├── 帧率：60fps（避免拖影），延迟 < 10ms（运动补偿要求）
  ├── 亮度：> 12000cd/m²（晴天户外直射日光可视）
  ├── 渲染方式：GPU 独立渲染通道（与其他屏幕并行）
  ├── 防抖（Image Stabilization）：补偿车身振动（IMU联动）
  └── 色域：> 100% sRGB（OLED/DMD 激光显示方案）

  安全相关显示（ASIL-B）：
  ├── 速度显示：安全岛直接驱动 HUD 控制器（绕过AP）
  ├── 碰撞预警（FCW）：红色叠加框，响应时间 < 50ms
  └── 限速标志识别（TSR）：实时叠加到 HUD 显示
```

---

> 📐 **设计提示**：HMI 设计需在 SoC 芯片评估阶段提前确认 GPU 渲染性能（多屏同时 60fps 无掉帧），并预留 10~15% GPU 算力余量用于未来功能扩展。驾驶分心限制须在 HMI 框架层强制执行，不可仅靠应用层自律。
