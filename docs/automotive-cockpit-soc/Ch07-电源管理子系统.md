# 第7章 电源管理子系统

## 7.1 整体电源架构

### 7.1.1 车辆供电环境

```
车载供电链路

  汽车电池（12V/48V/HV电池）
      │
      ▼
  车身BCM（Body Control Module）
      │ 主电源（VBAT，9V～16V for 12V系统）
      ▼
  座舱域控电源板（PMIC + LDO阵列）
      │
      ├── 1.8V → 核心逻辑（CPU/GPU/NPU接口）
      ├── 0.75V ～ 1.1V → CPU/GPU/NPU核心（可调DVFS）
      ├── 1.05V → LPDDR5 VDD
      ├── 1.8V → LPDDR5 VDDQ
      ├── 3.3V → I/O域、MIPI接口
      └── 5V → USB VBUS、外设供电
```

### 7.1.2 PMIC（电源管理IC）协同

高端座舱SoC通过片外**PMIC**（Power Management IC）提供精确可调的多路电源：

```
PMIC与SoC协同架构

  ┌──────────────────────────────────────────────┐
  │                座舱SoC内部                    │
  │                                              │
  │  PMU（片内电源管理单元）                       │
  │  ├── DVFS控制器（决策需要哪个电压/频率）        │
  │  ├── 电源序列控制器（上下电顺序）               │
  │  ├── 过温保护（TJMAX = 125℃）                 │
  │  └── SoC状态机（Normal/Sleep/DeepSleep）      │
  └───────────────┬──────────────────────────────┘
                  │ I2C / SPI（控制接口）
                  ▼
  ┌──────────────────────────────────────────────┐
  │              外部PMIC（如NXP PF5040）          │
  │  ├── Buck转换器 × 6（高效率，输出0.5V～3.3V）  │
  │  ├── LDO × 4（低噪声，模拟电路供电）           │
  │  ├── PGOOD监控（电源良好信号）                  │
  │  ├── 过压/欠压/过流保护                        │
  │  └── 功能安全（ASIL-B级PMIC认证）              │
  └──────────────────────────────────────────────┘

上电序列（示意）：
  1. VDD_IO (1.8V) 上电
  2. VDD_DDR (1.05V) 上电
  3. VDD_CPU (0.75V初始值) 上电
  4. VDD_GPU 上电
  5. CLK系统时钟使能
  6. CPU复位释放
  7. BootROM执行
```

## 7.2 DVFS（动态电压频率调节）

### 7.2.1 DVFS工作原理

**DVFS**（Dynamic Voltage and Frequency Scaling）根据当前工作负载动态调整CPU/GPU/NPU的工作电压和频率，是座舱SoC最重要的功耗优化手段：

```
DVFS工作循环

  负载监控（Performance Monitor）
      │ CPU利用率、GPU利用率、温度、功耗
      ▼
  性能需求决策（Governor）
      │ schedutil / performance / powersave / userspace
      ▼
  OPP（Operating Performance Point）查表
      │ 从OPP表中选择合适的{电压, 频率}对
      ▼
  DVFS调节动作
  ├── 升频：先升电压，再升频率（电压先行）
  └── 降频：先降频率，再降电压（频率先行）

典型OPP表（Cortex-A78AE示例）：
  ┌────────────┬──────────┬──────────┐
  │ 场景       │ 频率     │ 核心电压 │
  ├────────────┼──────────┼──────────┤
  │ 最高性能   │ 3.0 GHz  │ 1.05 V   │
  │ 性能模式   │ 2.5 GHz  │ 0.95 V   │
  │ 平衡模式   │ 2.0 GHz  │ 0.88 V   │
  │ 节能模式   │ 1.5 GHz  │ 0.82 V   │
  │ 超节能     │ 1.0 GHz  │ 0.75 V   │
  └────────────┴──────────┴──────────┘

功耗节省估算：
  动态功耗 P ∝ C × V² × f
  从最高性能降到节能模式：
  ├── 电压: 1.05V → 0.82V (×0.78)
  ├── 频率: 3.0GHz → 1.5GHz (×0.5)
  └── 功耗比: 0.78² × 0.5 ≈ 0.30（节省约70%动态功耗）
```

### 7.2.2 多域DVFS协同

```
座舱SoC多域DVFS（独立电源域，独立调节）

  CPU域 (Big Cluster)  ─► Buck0 (0.75V~1.05V, 0~3.0GHz)
  CPU域 (Little Cluster)─► Buck1 (0.6V~0.9V, 0~2.0GHz)
  GPU域               ─► Buck2 (0.65V~1.0V, 0~1.5GHz)
  NPU域               ─► Buck3 (0.7V~1.0V, 0~1.3GHz)
  DDR域               ─► Buck4 (1.05V固定)
  多媒体域（VPU/ISP）  ─► Buck5 (0.75V固定，低负载关断)

  各域独立调节优势：
  └── GPU高负载渲染时，CPU可以降频省电（互不影响）
```

## 7.3 低功耗状态机

### 7.3.1 功耗状态定义

```
座舱SoC功耗状态机

  ┌────────────────────────────────────────────────────┐
  │                    状态转换图                        │
  │                                                    │
  │         车辆上电ACC/ON                              │
  │         ─────────────►                             │
  │  OFF                  S0（正常运行）                 │
  │  （完全断电）◄─────────（全功耗，~20W）              │
  │         车辆熄火长时间    │                          │
  │                          │ 用户无交互/熄火            │
  │                          ▼                          │
  │                    S1（显示关闭）                    │
  │                    （屏幕关闭，CPU/后台维持，~8W）    │
  │                          │                          │
  │                          │ 继续空闲                  │
  │                          ▼                          │
  │                    S2（浅睡眠）                      │
  │                    （大部分IP关断，MCU+以太网维持，~2W）│
  │                          │                          │
  │                          │ 长时间无唤醒事件            │
  │                          ▼                          │
  │                    S3（深度睡眠）                    │
  │                    （仅RTC+安全岛维持，<0.5W）        │
  └────────────────────────────────────────────────────┘

唤醒源：
  ├── CAN总线唤醒（远程启动、报警信号）
  ├── 以太网唤醒（Wake-on-LAN，Magic Packet）
  ├── GPIO唤醒（车门开关、电源按键）
  ├── RTC定时唤醒（预约启动、定期健康检查）
  └── 数字钥匙BLE/UWB唤醒（检测到车主靠近）
```

### 7.3.2 冷启动与快速唤醒

```
启动时间要求（法规/用户体验）

  场景一：冷启动（完全断电重新上电）
  ├── 安全信号显示（仪表）：< 2s（FMVSS 111要求）
  ├── 倒车影像显示：< 2s（强制要求）
  └── 完整UI可交互：< 5s（用户体验目标）

  场景二：热唤醒（浅睡眠/深睡眠唤醒）
  ├── 仪表唤醒：< 500ms
  └── 完整系统恢复：< 2s

  快速启动优化技术：
  ├── Fastboot Path：安全岛先启动，先点仪表屏（绕过完整启动序列）
  ├── 多核并行启动：不同OS/固件并行加载
  ├── 预热策略：检测到BLE钥匙靠近时提前启动部分模块
  └── 休眠-恢复（Suspend-Resume）：S2/S3唤醒比冷启动快10x
```

## 7.4 热管理（Thermal Management）

### 7.4.1 热设计考量

座舱SoC工作在封闭的域控盒内，散热条件有限：

```
热管理策略

  温度监控层次：
  ├── 片内温度传感器（TJ传感器，精度±3℃）
  │   分布：CPU簇、GPU、NPU、DRAM控制器附近
  ├── 板级NTC热敏电阻（监控PCB和散热器温度）
  └── 环境温度传感器（监控舱内空气温度）

  热管理策略（分级降频）：
  ┌──────────────────────────────────────────────┐
  │  温度区间      │  热管理措施                   │
  ├──────────────────────────────────────────────┤
  │  < 85℃        │  无限制，正常运行              │
  │  85℃ ～ 100℃  │  降低GPU/NPU频率上限           │
  │  100℃ ～ 110℃ │  降低CPU频率，关闭部分IP        │
  │  > 110℃       │  紧急降频，仅维持安全功能运行   │
  │  > 125℃(TJMAX)│  关机保护                      │
  └──────────────────────────────────────────────┘

物理散热设计：
  ├── 域控盒：铝合金外壳直接散热（无风扇）
  ├── 芯片→铜垫→铝壳→空气对流
  ├── TDP设计目标：SoC+DRAM≤15W（典型负载），峰值≤25W
  └── 特殊场景（夏天高温车内）：考虑主动散热风扇
```

## 7.6 功能安全相关电源管理

⚠️ 功能安全对电源管理有特殊要求：

```
功能安全电源要求

  安全岛独立电源域
  ├── 与主处理器电源隔离，主处理器掉电不影响安全岛
  ├── 安全岛专用PMIC通道（单独监控）
  └── 安全岛供电失效 → 触发整车安全状态

  电源监控诊断
  ├── VMON（电压监控）：各轨道电压超差立即告警
  ├── IMON（电流监控）：异常电流检测，防止短路/过载
  └── PGOOD链：所有电源正常才允许CPU启动

  低电压保护
  └── 电池电压 < 6V（12V系统）→ 有序关机（保存关键数据）

  掉电保存
  └── 检测到电源失效 → DRAM关键数据刷回UFS（有序关机）
```

## 小结

本章介绍了座舱SoC电源管理子系统的完整设计：
- **供电架构**：PMIC多路精密供电，上下电序列严格管理
- **DVFS**：多域独立调节，动态节省功耗最高70%
- **低功耗状态机**：S0-S3多级休眠，多种快速唤醒源
- **热管理**：分级降频策略，TDP≤25W设计目标
- **功能安全**：安全岛独立电源，电源监控诊断完备
