# 第2章 计算子系统（CPU / GPU / NPU）

## 2.1 CPU子系统

### 2.1.1 CPU集群架构

高端座舱SoC通常采用**大小核（big.LITTLE / DynamIQ）**设计：

```
CPU子系统架构示例（高通SA8295P / SA8775P级别）

  Prime Cluster    Performance Cluster    Efficiency Cluster
  ┌──────────┐     ┌──────────────────┐   ┌──────────────────┐
  │ 1× A78AE │     │ 3× A78AE         │   │ 4× A55           │
  │ @ 3.0GHz │     │ @ 2.8GHz         │   │ @ 2.0GHz         │
  │ L2: 1MB  │     │ L2: 512KB each   │   │ L2: 256KB each   │
  └────┬─────┘     └────────┬─────────┘   └────────┬─────────┘
       │                    │                       │
       └──────────┬─────────┘───────────────────────┘
                  │
         ┌────────▼────────┐
         │  共享 L3 Cache   │
         │     8MB         │
         └────────┬────────┘
                  │
         ┌────────▼────────┐
         │  系统缓存（SLC）  │
         │    16MB         │
         └─────────────────┘

说明：
  - A78AE（Automotive Enhanced）：具备汽车级可靠性扩展
  - A55：低功耗核，处理后台任务、系统服务
  - A78AE支持Split-Lock模式：可配置为2×独立A78（用于隔离安全/非安全域）
```

### 2.1.2 CPU功能安全扩展（AE = Automotive Enhanced）

⚠️ 汽车场景要求CPU具备功能安全增强特性：

| 特性 | 普通CPU | AE扩展CPU |
|------|--------|----------|
| 核心锁步（Lockstep） | 无 | 可选 2out-of-2配置 |
| ECC内存保护 | 可选 | 必选（L1/L2/L3 Cache均有ECC） |
| 奇偶校验 | 无 | 寄存器堆奇偶校验 |
| 错误注入 | 无 | 支持FMEDA故障注入测试 |
| 诊断覆盖率 | < 60% | ≥ 90%（满足ASIL-B需求） |

### 2.1.3 CPU工作模式

```
正常运行模式
  └── 全核运行：最高性能，满足冷启动、3D导航渲染峰值

平衡模式
  └── Prime + Performance Cluster：日常驾驶，兼顾性能与功耗

节能模式
  └── Efficiency Cluster only：泊车、低速、屏幕熄灭后台服务

休眠唤醒模式
  └── 仅安全岛和MCU维持工作（<2W），唤醒响应时间 ≤ 200ms
```

## 2.2 GPU子系统

### 2.2.1 GPU架构特点

座舱SoC GPU承担**3D图形渲染**和**GPGPU通用计算**两类工作负载：

```
GPU 工作负载分类

  图形渲染管线（Graphics Pipeline）
  ├── 仪表3D指针/3D效果渲染（OpenGL ES 3.2）
  ├── AR-HUD增强现实叠加（OpenGL ES + EGL）
  ├── 导航3D地图实时渲染（OpenGL ES / Vulkan）
  └── 中控UI特效（Flutter/Qt GPU加速）

  通用并行计算（GPGPU / Compute Shader）
  ├── 360环视鱼眼校正与拼接
  ├── 图像后处理（HDR合并、色彩映射）
  └── 轻量AI推理（辅助NPU溢出场景）
```

### 2.2.2 GPU关键参数

| 参数 | 典型规格 | 说明 |
|------|---------|------|
| 着色器核心数 | 384～1024 个 | ALU并行单元 |
| FP32算力 | 1.5～4 TFLOPS | 浮点计算峰值 |
| FP16算力 | 3～8 TFLOPS | 半精度，AI辅助计算 |
| 纹理单元 | 32～64 TMU | 纹理采样 |
| 光栅化单元 | 8～16 ROP | 像素输出 |
| 像素填充率 | 10～20 Gpixel/s | 多屏同驱能力 |
| 内存接口 | 共享系统LPDDR5 | GPU专用带宽分配 |
| 支持API | OpenGL ES 3.2, Vulkan 1.3, OpenCL 3.0 | 跨平台图形标准 |

### 2.2.3 GPU虚拟化（GPU Virtualization）

在多OS共存场景（Android + QNX + Linux），GPU需要进行**虚拟化分时复用**：

```
GPU虚拟化架构

  ┌──────────────┐  ┌──────────────┐  ┌──────────────┐
  │  Android VM  │  │   QNX VM     │  │  Linux VM    │
  │（IVI娱乐）   │  │（仪表安全显示）│  │（ADAS可视化） │
  └──────┬───────┘  └──────┬───────┘  └──────┬───────┘
         │                 │                 │
  ┌──────▼─────────────────▼─────────────────▼───────┐
  │              GPU虚拟化层（Hypervisor驱动）           │
  │    分时调度 + 内存隔离 + 上下文切换 < 1ms           │
  └──────────────────────────┬───────────────────────┘
                             │
                    ┌────────▼────────┐
                    │   物理GPU Core   │
                    └─────────────────┘

⚠️ 安全显示路径（仪表车速等ASIL-B信号）通过独立的安全渲染通道绕过GPU虚拟化层
```

## 2.3 NPU/AI加速子系统

### 2.3.1 NPU架构概览

**NPU**（Neural Processing Unit）专为深度学习推理优化，采用脉动阵列（Systolic Array）或类脑计算架构，支持以下算子：

```
NPU支持的算子类型

  卷积族（Convolution Family）
  ├── Conv2D（标准卷积）
  ├── Depthwise Conv（深度可分离卷积）
  ├── Dilated Conv（空洞卷积）
  └── Transposed Conv（转置卷积）

  激活函数
  ├── ReLU / ReLU6 / Leaky ReLU
  ├── Sigmoid / Tanh
  └── GELU / SiLU（Transformer场景）

  矩阵运算
  ├── 全连接（FC / Dense）
  ├── Batch Normalization
  └── Multi-Head Attention（MHA，大模型场景）

  数据操作
  ├── Pooling（Max/Avg）
  ├── Reshape / Permute / Concat
  └── Element-wise Add/Mul
```

### 2.3.2 NPU性能规格

| 规格 | 低端座舱（TDA4VM级） | 中高端（SA8295P级） | 旗舰（DRIVE Orin级） |
|------|-------------------|------------------|-------------------|
| INT8算力 | 8 TOPS | 30 TOPS | 254 TOPS |
| FP16算力 | 4 TFLOPS | 15 TFLOPS | 127 TFLOPS |
| 内存带宽 | 34 GB/s | 68 GB/s | 204 GB/s |
| 典型模型延迟 | YOLOv5s: ~8ms | YOLOv5m: ~4ms | YOLOv8x: <2ms |
| 支持框架 | TFLite, ONNX | TFLite, ONNX, TensorRT | TensorRT 8.x |

### 2.3.3 座舱AI典型应用

```
座舱AI应用场景与算力需求

  场景一：驾驶员状态监控（DMS）
  ├── 输入：近红外摄像头 @ 30fps，分辨率 1280×720
  ├── 模型：人脸检测 + 关键点 + 眼部开合度 + 头部姿态
  ├── 目标延迟：< 100ms（实时监控）
  └── 算力需求：~2 TOPS

  场景二：乘员检测与分类（OMS）
  ├── 输入：车内多路摄像头
  ├── 模型：人体骨骼点检测 + 乘员计数 + 儿童识别
  ├── 目标延迟：< 200ms
  └── 算力需求：~3 TOPS

  场景三：语音唤醒与识别（KWS + ASR）
  ├── 输入：麦克风阵列（4~8路）
  ├── 模型：关键词唤醒（KWS）+ 连续语音识别（ASR）
  ├── 目标延迟：KWS < 5ms，ASR < 500ms
  └── 算力需求：~1 TOPS（KWS），~5 TOPS（端侧ASR）

  场景四：手势识别
  ├── 输入：TOF摄像头或普通RGB摄像头
  ├── 模型：手部检测 + 手势分类
  ├── 目标延迟：< 50ms
  └── 算力需求：~1 TOPS

  场景五：座舱大模型（LLM）
  ├── 输入：语音/文字
  ├── 模型：7B/13B参数量LLM（量化版INT4/INT8）
  ├── 目标延迟：首Token < 500ms，生成速度 ≥ 20 tokens/s
  └── 算力需求：~30 TOPS（INT8）
```

## 2.4 音频DSP子系统

### 2.4.1 功能模块

音频DSP专用于实时音频信号处理，延迟要求严格（< 20ms端到端）：

```
音频DSP功能模块

  输入处理
  ├── 麦克风阵列采集（PDM/TDM接口）
  ├── 波束成形（Beamforming）：聚焦声源方向
  ├── 噪声消除（ANC/ANR）：主动降噪
  ├── 回声消除（AEC）：消除扬声器回声
  └── 语音增强（SE）：提升语音清晰度

  输出处理
  ├── 均衡器（EQ）：频率响应调整
  ├── 动态范围压缩（DRC）：防止削波
  ├── 空间音效（3D/Surround Sound）
  ├── 主动降噪（Road Noise Cancellation, RNC）
  └── 多路音频混音（Navigation/Media/Alert优先级）

  互联
  ├── I2S / TDM 接口（连接功放芯片）
  ├── MOST（汽车多媒体总线，部分车型）
  └── A2B（汽车音频总线）
```

### 2.4.2 音频DSP规格

| 参数 | 规格 |
|------|------|
| 采样率 | 8kHz ～ 192kHz |
| 位深度 | 16bit / 24bit / 32bit |
| 通道数 | 最多16路输入 + 32路输出 |
| 算法延迟 | < 5ms（AEC/ANR） |
| 处理周期 | 256样本/帧 @ 48kHz = 5.3ms |

## 2.5 计算子系统互联与调度

```
计算任务调度策略

  任务类型              分配处理单元        调度策略
  ─────────────────────────────────────────────────
  OS内核/驱动           A55 Cluster         优先级抢占
  系统服务/守护进程      A55 Cluster         CFS调度
  3D仪表渲染            GPU                 GPU Command Queue
  IVI应用               A78 Cluster         SCHED_NORMAL
  AI推理（批量）         NPU                 离线异步提交
  AI推理（实时DMS）      NPU + A78           实时流水线
  音频处理              Audio DSP           硬件实时
  CAN报文处理           MCU Cluster         中断驱动
  安全监控              安全岛 Lockstep MCU  硬件看门狗

  跨单元通信机制：
  ├── CPU↔GPU：共享内存 + DMA（Zero-copy）
  ├── CPU↔NPU：ION Buffer / DMA-BUF
  ├── CPU↔MCU：片上邮箱（Mailbox）+ 共享内存
  └── CPU↔DSP：RPMsg（Remote Processor Messaging）
```

## 小结

本章介绍了座舱SoC计算子系统的四大核心组件：
- **CPU**：大小核异构，AE汽车安全扩展，多工作模式管理
- **GPU**：图形渲染+GPGPU，支持多OS虚拟化分时
- **NPU**：高效AI推理，覆盖DMS/OMS/语音/手势等座舱AI场景
- **音频DSP**：低延迟实时音频处理，支持AEC/ANC/空间音效
