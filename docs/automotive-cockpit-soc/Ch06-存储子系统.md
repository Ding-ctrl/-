# 第6章 存储子系统

## 6.1 存储层次结构

座舱SoC存储系统采用分层设计，从高速片上缓存到低速大容量持久存储：

```
存储层次金字塔（延迟 vs 容量）

  延迟↑  容量↓
  ──────────────────────────────────────────────
  片上寄存器     <1 ns     KB级
  L1 Cache       ~1 ns    32~64 KB/核
  L2 Cache       ~5 ns    512KB~1MB/核
  L3 Cache       ~15 ns   8~16 MB（共享）
  SLC（系统缓存） ~20 ns   16~64 MB（可选）
  ──────────────────────────────────────────────
  片外主存（DRAM）
  LPDDR5         ~50 ns   8~32 GB
  ──────────────────────────────────────────────
  持久化存储
  UFS 3.1/4.0    ~100 µs  64~256 GB
  eMMC 5.1       ~200 µs  32~128 GB
  NOR Flash      ~100 µs  64~256 MB（BootLoader/配置）
  ──────────────────────────────────────────────
  延迟↓  容量↑
```

## 6.2 主存储器（LPDDR5）

### 6.2.1 LPDDR5规格与配置

**LPDDR5**（Low Power Double Data Rate 5）是高端座舱SoC的主存储器标准：

| 参数 | LPDDR4X | LPDDR5 | LPDDR5X |
|------|---------|--------|---------|
| 数据速率 | 4266 MT/s | 6400 MT/s | 8533 MT/s |
| 总线位宽 | 64 bit | 64 bit | 64 bit |
| 峰值带宽（64bit） | 34 GB/s | 51 GB/s | 68 GB/s |
| 工作电压 | 1.1V | 1.05V | 1.05V |
| 功耗节省 | 基准 | -20% | -20% |
| ECC支持 | 可选（片内ECC） | 片内ECC（IBECC）| 片内ECC |

```
LPDDR5物理拓扑（典型高端配置）

  座舱SoC
  ├── Channel 0: 64bit × LPDDR5 @ 6400MT/s (12.8 GB/s) ─► 8GB Package
  ├── Channel 1: 64bit × LPDDR5 @ 6400MT/s (12.8 GB/s) ─► 8GB Package
  ├── Channel 2: 64bit × LPDDR5 @ 6400MT/s (12.8 GB/s) ─► 4GB Package
  └── Channel 3: 64bit × LPDDR5 @ 6400MT/s (12.8 GB/s) ─► 4GB Package

总配置：4通道 × 12.8 GB/s = 51.2 GB/s 峰值带宽
总容量：24 GB（典型高端座舱）

带宽分配策略（典型）：
  ├── GPU帧缓冲区：~20 GB/s
  ├── NPU推理数据：~10 GB/s
  ├── CPU/OS系统：~10 GB/s
  ├── VPU视频解码：~8 GB/s
  └── ISP图像处理：~3 GB/s

⚠️ ECC（IBECC）开启会减少~12%有效带宽，需在设计时预留余量
```

### 6.2.2 DRAM功能安全（针对ASIL-B场景）

```
DRAM错误检测与纠正

  片内ECC（In-Band ECC, IBECC）
  ├── 每64bit数据附加8bit ECC校验码
  ├── 单比特错误：自动纠正（SECDED）
  ├── 双比特错误：检测并上报
  └── ECC错误日志：MCU安全岛定期轮询

  内存刷新（Scrubbing）
  ├── 后台ECC Scrubbing：定期扫描所有内存，主动纠正积累的单bit错误
  └── 频率：典型每5分钟完整扫描一次

  内存分区保护
  ├── 安全岛SRAM：物理独立，主处理器无访问权限
  ├── 安全缓冲区：SMMU限制，只有安全固件可写
  └── 外设DMA隔离：SMMU防止外设越界访问
```

## 6.3 持久化存储

### 6.3.1 UFS（通用闪存存储）

**UFS**（Universal Flash Storage）是座舱SoC的主要存储介质：

| 参数 | UFS 2.2 | UFS 3.1 | UFS 4.0 |
|------|---------|---------|---------|
| 接口速率（每通道） | 11.6 Gbps | 23.2 Gbps | 46.4 Gbps |
| 顺序读取 | ~1.2 GB/s | ~2.1 GB/s | ~4.2 GB/s |
| 顺序写入 | ~0.5 GB/s | ~1.2 GB/s | ~2.8 GB/s |
| 随机读（4K IOPS） | 70K | 100K | 200K |
| 随机写（4K IOPS） | 50K | 70K | 100K |
| 工作电压 | 2.5V/1.8V | 2.5V/1.8V | 2.5V/1.8V |

```
UFS在座舱中的分区方案

  ┌──────────────────────────────────────────┐
  │              UFS 128GB 存储              │
  │                                          │
  │  ├── 启动分区（Boot Area LUN）8MB        │
  │  │   └── BootLoader（安全启动引导）       │
  │  │                                      │
  │  ├── 系统分区 A（~16GB）                 │
  │  │   ├── Hypervisor/Bootloader          │
  │  │   ├── Android OS System Image        │
  │  │   ├── QNX OS Image                   │
  │  │   └── Linux OS Image                 │
  │  │                                      │
  │  ├── 系统分区 B（~16GB）─ A/B OTA备份    │
  │  │                                      │
  │  ├── 用户数据分区（~60GB）               │
  │  │   ├── 应用数据（APP数据）             │
  │  │   ├── 地图数据（离线地图）            │
  │  │   ├── 媒体缓存（音乐/视频缓存）       │
  │  │   └── 行车记录仪（循环写入）          │
  │  │                                      │
  │  └── OTA更新缓存分区（~16GB）           │
  └──────────────────────────────────────────┘
```

### 6.3.2 NOR Flash（快速启动需求）

**NOR Flash** 用于存储BootLoader和关键配置数据，支持就地执行（XIP）：

| 参数 | 规格 |
|------|------|
| 接口 | QSPI / OPI（八线SPI） |
| 容量 | 64MB ～ 256MB |
| 读取速率 | 200 MB/s（QSPI），400 MB/s（OPI） |
| 延迟 | ~100 ns（随机读） |
| 主要用途 | BootROM辅助 / BIOS固件 / 安全岛固件 |

```
NOR Flash在安全启动中的作用

  NOR Flash存储内容：
  ├── 第一阶段BootLoader（XBL/SPL）
  ├── 安全岛固件（安全岛MCU程序）
  ├── 根证书/公钥哈希
  └── 关键配置参数（VIN、标定数据）

  优势：
  ├── 支持就地执行（XIP）：CPU直接从NOR运行代码，无需加载到DRAM
  ├── 随机读性能优于NAND
  └── 高可靠性：P/E寿命100K次，耐受-40℃～+125℃
```

## 6.4 缓存子系统设计

### 6.4.1 L1/L2 Cache设计要点

```
CPU核心缓存配置（以ARM Cortex-A78AE为例）

  Cortex-A78AE 核心
  ├── L1 指令Cache：64KB，4路组相联
  ├── L1 数据Cache：64KB，4路组相联，ECC保护
  ├── L2 统一Cache：512KB ～ 1MB，16路组相联，ECC保护
  └── 预取单元（Prefetch Unit）：硬件预取，减少Cache Miss

  Cache ECC策略：
  ├── L1 Cache：奇偶校验（检错，速度优先）
  └── L2 Cache：ECC（纠错，可靠性优先）
```

### 6.4.2 共享L3与系统缓存（SLC）

```
L3 Cache 和 SLC（System-Level Cache）

  L3 Cache（8MB ～ 16MB）
  ├── 所有CPU核共享
  ├── 统一指令+数据Cache
  └── ECC保护（SECDED）

  SLC（System-Level Cache，可选）（16MB ～ 64MB）
  ├── CPU、GPU、NPU均可使用
  ├── 减少对LPDDR5的访问次数
  ├── 关键作用：降低DRAM功耗，减少带宽压力
  └── 带宽效率提升：GPU/NPU热点数据Hit率 > 60%

  CACHE一致性协议：
  └── ACE（AXI Coherency Extensions）/ CHI（Coherent Hub Interface）
      保证CPU核间、CPU与GPU间的缓存一致性
```

## 6.6 存储子系统功能安全要求

```
存储相关功能安全措施

  DRAM（LPDDR5）
  ├── IBECC：单比特纠错，双比特检错
  ├── 定期Scrubbing：主动检查和纠正内存错误
  └── 内存隔离：SMMU防止越界访问

  NOR Flash（BootLoader存储）
  ├── CRC校验：上电时验证固件CRC
  ├── 双备份：关键固件保存两份，互为热备
  └── 读干扰检测（Read Disturb Detection）

  UFS（系统存储）
  ├── 写保护（Write Protect）：系统分区只读挂载
  ├── 健康监控（UFS Health Check）：监控P/E寿命
  └── A/B分区：OTA更新失败自动回滚
```

## 小结

本章介绍了座舱SoC存储子系统的完整架构：
- **LPDDR5**：高带宽主存，4通道51.2 GB/s，带IBECC功能安全保护
- **UFS 4.0**：高性能持久化存储，A/B分区支持安全OTA
- **NOR Flash**：XIP快速启动，安全岛固件存储
- **缓存层次**：L1/L2/L3/SLC多级缓存，ECC保护，降低DRAM访问压力
