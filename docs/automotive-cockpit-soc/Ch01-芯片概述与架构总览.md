# 第1章 芯片概述与架构总览

## 1.1 汽车座舱SoC的定义与演进

**座舱SoC**（Cockpit System-on-Chip）是将原本分散于多个ECU（Electronic Control Unit）中的座舱计算功能，集成到单一或少数几颗芯片上的高度集成处理器。其演进路径如下：

```
第一代（2010年前）：独立ECU
  仪表ECU ─ IVI主机 ─ 空调控制 ─ 车身控制
  （各自独立，总线互联，算力有限）

第二代（2010-2018）：IVI+仪表融合
  双核/四核 ARM + PowerVR GPU
  Android/QNX双系统，显示分离

第三代（2018-2022）：座舱域控制器（CDC）
  8核+ Cortex-A + 独立安全岛 + DSP
  仪表/IVI/HUD三合一，ASIL-B

第四代（2022-今）：智能座舱超算平台
  异构多核（CPU+GPU+NPU+DSP）
  ASIL-D安全岛，30~250+ TOPS
  5G+Wi-Fi 6E+蓝牙5.3，OTA全栈更新
  舱驾一体探索（座舱+ADAS融合）
```

---

## 1.2 座舱SoC的核心价值

| 价值维度 | 传统多ECU方案 | 座舱SoC方案 |
|----------|--------------|------------|
| 硬件成本 | 多块PCB、多颗MCU | 单片集成，BOM大幅降低 |
| 功耗 | 各ECU独立供电，总功耗高 | 统一电源管理，整体功耗降低30~50% |
| 重量/体积 | 线束复杂，重量大 | 线束简化，座舱域控体积缩小 |
| 软件升级 | 逐ECU刷写 | OTA一次性升级全座舱 |
| 功能扩展 | 硬件受限 | 软件定义，弹性扩展 |
| AI能力 | 基本无 | NPU内置，实时推理 |

## 1.4 异构计算组合原则

座舱SoC采用**异构计算**（Heterogeneous Computing）策略，核心原则为"合适的任务交给合适的处理单元"：

| 处理单元 | 擅长的任务 | 典型场景 |
|----------|-----------|---------|
| **CPU（Cortex-A）** | 操作系统调度、通用逻辑、高级驾驶辅助决策 | Android系统运行、应用框架 |
| **GPU** | 并行图形渲染、通用并行计算（GPGPU） | 3D仪表、导航地图、AR-HUD渲染 |
| **NPU/DSP-AI** | 张量计算、矩阵乘法、深度学习推理 | 人脸识别、语音识别、DMS驾驶员监控 |
| **音频DSP** | 实时音频处理、噪声消除、空间音效 | 主动降噪、3D音效、语音唤醒 |
| **实时MCU（Cortex-R/M）** | 硬实时控制、中断响应（µs级） | 仪表指针控制、CAN报文实时收发 |
| **安全岛** | 功能安全监控、密钥管理 | 车速显示安全路径、TPMS等安全信号 |
| **VPU** | 视频编解码（H.265/AV1） | 流媒体、行车记录仪、360环视 |
| **ISP** | 图像信号处理、HDR、去噪 | 摄像头输入处理、DMS摄像头 |

## 1.5 关键性能指标（KPI）

```
算力（Compute Performance）
  ├── CPU峰值：≥ 50,000 DMIPS（8核A78级）
  ├── GPU：≥ 1.5 TFLOPS（FP32）
  ├── NPU：≥ 30 TOPS（INT8）
  └── DSP：≥ 2 TOPS

存储带宽
  ├── LPDDR5 @ 6400 MT/s × 4通道 = 102.4 GB/s
  └── L3 Cache ≥ 8 MB

显示能力
  ├── 同时驱动显示屏数量：≥ 4
  ├── 单屏最高分辨率：4K（3840×2160）@ 60 fps
  └── 总像素填充率：≥ 10 Gpixel/s

摄像头接入
  └── 同时处理路数：≥ 8路 MIPI CSI（含环视+DMS+OMS）

网络
  ├── 车载以太网：100BASE-T1 / 1000BASE-T1
  ├── 无线：Wi-Fi 6E（802.11ax）+ BT 5.3
  └── 蜂窝：5G Sub-6GHz（通过外挂基带或集成）

功能安全
  ├── 应用处理器：ASIL-B（QM + 软件诊断）
  └── 安全岛：ASIL-D（ISO 26262 Part 5/6）

功耗
  └── TDP（热设计功耗）：10W~30W（视应用场景）
```
