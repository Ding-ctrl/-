# 第8章 软硬件划分与系统架构

## 8.1 软硬件划分原则

座舱SoC的软硬件划分基于以下原则：

```
划分判断矩阵

  倾向硬件实现的特征：
  ├── 实时性要求严格（< 1ms响应，软件调度无法保证）
  ├── 数据量大、算法固定（视频编解码、图像信号处理）
  ├── 功能安全等级高（ASIL-D，需要锁步/ECC硬件保证）
  ├── 功耗敏感（硬件加速比CPU实现省电5~10x）
  └── 高度并行（着色器、矩阵计算）

  倾向软件实现的特征：
  ├── 算法频繁迭代（AI模型升级、UI界面更新）
  ├── 逻辑复杂多变（业务规则、条件判断）
  ├── 用户交互逻辑（应用层功能）
  └── 差异化需求（不同车型软件定制）
```

## 8.2 硬件层划分

### 8.2.1 硬件固定功能模块（不可编程/不可配置）

```
不可编程硬件模块（RTL固化于芯片，不可通过软件修改逻辑）

  ┌────────────────────────────────────────────────────┐
  │  模块                │ 功能描述                     │
  ├────────────────────────────────────────────────────┤
  │  ISP流水线           │ 图像信号处理固定流水线          │
  │  VPU编解码核心       │ H.265/AV1硬件解码器           │
  │  JPU JPEG加速        │ JPEG/HEIF硬件编解码            │
  │  DRAM ECC引擎        │ 内存纠错码计算                 │
  │  安全启动ROM         │ BootROM，验证第一级BootLoader  │
  │  TRNG（真随机数）    │ 硬件熵源，不可软件模拟          │
  │  HSM加密引擎         │ AES/RSA/SHA硬件加速            │
  │  OTP/eFuse接口       │ 一次性可编程存储读取           │
  │  Lockstep比较器      │ 双核输出比较，硬件完成          │
  │  DMA引擎             │ 内存数据搬运，硬件并行          │
  │  SMMU                │ 系统内存管理单元，硬件隔离      │
  └────────────────────────────────────────────────────┘
```

### 8.2.2 硬件可配置模块（寄存器配置）

```
可通过寄存器配置的硬件模块

  ┌────────────────────────────────────────────────────┐
  │  模块                │ 软件可配置内容                │
  ├────────────────────────────────────────────────────┤
  │  显示控制器DC        │ 分辨率、刷新率、图层合成参数   │
  │  GPIO控制器          │ 引脚方向、上下拉、中断触发模式 │
  │  时钟生成器（PLL）   │ 输出频率（DVFS调节）           │
  │  ISP参数             │ AWB增益、AE目标、NR强度        │
  │  CAN-FD控制器        │ 波特率、报文过滤器             │
  │  MIPI控制器          │ 通道数、速率、时序参数         │
  │  PCIe控制器          │ 速率、通道数、电源状态         │
  │  音频CODEC控制        │ 采样率、位深度、音量           │
  └────────────────────────────────────────────────────┘
```

### 8.2.3 可编程硬件（RISC-V/Tensilica子核）

部分高端SoC集成了**专用可编程处理器**，兼具硬件效率和软件灵活性：

```
可编程硬件加速器示例

  Tensilica HiFi DSP（音频处理）
  ├── 用户可编程（Xtensa ISA）
  ├── 下载自定义音频算法（EQ、3D音效等）
  └── 比通用CPU低5~8x功耗

  RISC-V安全子核（安全岛内）
  ├── 用户可编程
  ├── 可更新安全固件（OTA）
  └── 执行AUTOSAR Classic安全服务

  Vision DSP（Cadence/ARC）
  ├── 图像处理扩展指令集
  ├── 可部署自定义CV算法
  └── 弥补固定ISP功能的不足
```

## 8.4 虚拟化架构

### 8.4.1 Hypervisor类型

```
Hypervisor在座舱中的应用

  Type-1 Hypervisor（裸机虚拟化，直接运行在硬件上）
  ├── 代表产品：QNX Hypervisor, ACRN, Green Hills INTEGRITY
  ├── 优势：更低延迟，更强隔离，满足功能安全
  └── 用于：安全关键VM（QNX仪表）+ 非安全VM（Android IVI）

  Type-2 Hypervisor（运行在宿主OS之上）
  ├── 代表：KVM（运行在Linux上）
  ├── 优势：开发简单，生态丰富
  └── 用于：非安全场景，测试环境

  典型高端座舱Hypervisor方案：
  ┌──────────────────────────────────────────────┐
  │          Type-1 Hypervisor                    │
  │                                              │
  │  ┌────────────┐  ┌────────────┐  ┌─────────┐│
  │  │  VM0       │  │  VM1       │  │  VM2    ││
  │  │  QNX RTOS  │  │  Android   │  │  Linux  ││
  │  │  仪表/安全  │  │  IVI娱乐   │  │  ADAS   ││
  │  │  ASIL-B    │  │  QM        │  │  可视化  ││
  │  └────────────┘  └────────────┘  └─────────┘│
  │                                              │
  │     硬件资源分配（CPU核/内存/设备直通）         │
  └──────────────────────────────────────────────┘
```

### 8.4.2 VM间通信（Inter-VM Communication）

```
VM间通信机制

  共享内存（Shared Memory）
  ├── 高带宽，低延迟（<1µs）
  ├── 用途：视频帧传递（Android → QNX仪表）
  └── 安全控制：Hypervisor管理共享内存访问权限

  虚拟总线（Virtual Bus）
  ├── Hypervisor提供虚拟以太网/虚拟CAN
  ├── VM间通过标准协议通信
  └── 用途：车辆信号共享、控制命令

  邮箱（Mailbox）+ 中断注入
  ├── 轻量事件通知（< 100B）
  ├── 用途：事件同步、状态通知
  └── 延迟：<10µs

  RPMsg框架（Remote Processor Messaging）
  └── CPU与MCU/DSP之间的轻量消息传递
```

## 8.6 AUTOSAR架构集成

```
AUTOSAR在座舱SoC中的角色

  AUTOSAR Classic Platform（用于安全岛/MCU）
  ├── BSW（基础软件）：OS/COM/Memory/Diagnostic堆栈
  ├── RTE（运行时环境）：SW-C之间的通信桥梁
  └── SW-C（软件组件）：仪表显示、CAN接收、安全监控

  AUTOSAR Adaptive Platform（用于主处理器）
  ├── ARA（自适应AUTOSAR运行时接口）
  ├── ara::com：基于SOME/IP的服务化通信
  ├── ara::exec：应用生命周期管理
  ├── ara::crypto：密码服务
  ├── ara::diag：诊断服务
  └── ara::log：日志服务

  Classic与Adaptive的互联
  └── 通过以太网SOME/IP协议通信
      MCU上的CLASSIC提供安全信号 → Adaptive消费
```

## 小结

本章介绍了座舱SoC软硬件划分的完整体系：
- **硬件层**：不可编程固化模块 + 寄存器配置模块 + 可编程子核三类
- **软件层**：固件→HAL→OS/Hypervisor→中间件→框架→应用六层架构
- **虚拟化**：Type-1 Hypervisor多VM隔离，QNX（安全）+ Android（娱乐）+ Linux并存
- **AUTOSAR**：Classic用于安全MCU，Adaptive用于主处理器，SOA服务化互联
