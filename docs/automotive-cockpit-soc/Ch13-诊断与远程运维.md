# 第13章 诊断与远程运维

## 13.1 车载诊断体系概述

```
车载诊断系统演进

  第一代（1996-2008）：OBD-II
  ├── 标准化诊断接口（16针 DLC 连接器）
  ├── 支持5种通信协议（ISO 9141/14230/15765 等）
  └── 主要用于发动机排放诊断（MIL故障灯）

  第二代（2008-2018）：UDS（ISO 14229）统一诊断服务
  ├── 覆盖全车 ECU（底盘/车身/座舱）
  ├── 统一 DoIP（ISO 13400）以太网通道
  └── AUTOSAR 诊断堆栈标准化

  第三代（2020-今）：SOVD + 远程诊断
  ├── SOVD（ISO/CD 22900-3）：服务化诊断
  ├── 云端诊断（RDE）：4G/5G实时故障上报
  └── 预测性维护（PHM）：AI驱动的故障预测

座舱SoC诊断职责范围：
  ├── 仪表/IVI/HUD 等座舱软硬件故障诊断
  ├── 通过 DoIP/CAN 转发其他 ECU 的诊断请求
  └── OTA 诊断：更新过程中的状态监控与回滚
```

## 13.2 UDS（统一诊断服务）

### 13.2.1 协议架构

```
UDS（ISO 14229-1）协议栈层次

  应用层（Application Layer）：
  └── UDS 服务（Service ID = 1字节，0x10~0xBE）

  会话层（Session Layer）：
  └── 诊断会话管理（默认/编程/扩展诊断会话）

  传输层（Transport Layer）：
  ├── ISO 15765-2（CAN TP，分段传输协议）
  └── DoIP（ISO 13400，以太网传输）

  数据链路层/物理层：
  ├── CAN / CAN-FD（诊断传统通道）
  └── Automotive Ethernet 100/1000BASE-T1（DoIP）

UDS 报文结构（以CAN TP为例）：
  [CAN ID] [SF/FF/CF/FC] [SID] [SubFunc/DataID] [Data...]
  ├── CAN ID：诊断请求（0x7DF广播/0x600~0x6FF物理）
  ├── SID（Service ID）：服务标识
  ├── 正响应：0x40 + SID
  └── 负响应：0x7F + SID + NRC（否定响应码）
```

### 13.2.2 常用诊断服务

```
UDS 核心服务列表（座舱SoC常用）

  ┌────────┬──────────────────────────────┬─────────────────────────┐
  │ SID    │ 服务名称                      │ 典型应用                  │
  ├────────┼──────────────────────────────┼─────────────────────────┤
  │ 0x10   │ DiagnosticSessionControl     │ 切换默认/编程/扩展诊断会话  │
  │ 0x11   │ ECUReset                     │ 远程复位（硬复位/软复位）   │
  │ 0x14   │ ClearDiagnosticInformation   │ 清除 DTC 故障码            │
  │ 0x19   │ ReadDTCInformation           │ 读取 DTC 状态/快照/扩展数据│
  │ 0x22   │ ReadDataByIdentifier         │ 读取 DID（车型/软件版本等）  │
  │ 0x27   │ SecurityAccess               │ 安全级别解锁（种子/密钥）    │
  │ 0x28   │ CommunicationControl         │ 禁止/允许网络通信            │
  │ 0x2E   │ WriteDataByIdentifier        │ 写入配置数据（VIN/ODX参数）  │
  │ 0x2F   │ InputOutputControlByIdentifier│ IO控制（强制输出/恢复正常）  │
  │ 0x31   │ RoutineControl               │ 执行诊断程序（BIST/校准）    │
  │ 0x34   │ RequestDownload              │ 请求数据下载（刷写开始）      │
  │ 0x36   │ TransferData                 │ 传输数据块（刷写数据）        │
  │ 0x37   │ RequestTransferExit          │ 请求传输结束                │
  │ 0x3E   │ TesterPresent                │ 保持诊断会话活跃（心跳）      │
  │ 0x85   │ ControlDTCSetting            │ 开启/关闭 DTC 存储           │
  └────────┴──────────────────────────────┴─────────────────────────┘

SecurityAccess（0x27）安全访问流程：
  Tester → [0x27 01] 请求种子 → ECU → [0x67 01 SEED(4B)]
  Tester → [0x27 02 KEY=F(SEED)] → ECU → [0x67 02] 解锁成功
  注：密钥算法（F函数）由 OEM 定义，需防逆向（建议 AES-based）
```

### 13.2.3 DTC 故障码管理

```
DTC（Diagnostic Trouble Code）结构

  DTC 编码格式（ISO 15031-6）：
  ├── 第1字节：故障类型（P/B/C/U）+ 区域代码
  │   P = 动力总成，B = 车身，C = 底盘，U = 网络通信
  ├── 第2字节：故障子系统
  └── 第3字节：具体故障代码

  DTC 状态字节（StatusByte，8个位标志）：
  ┌─────────────────────────────────────────────────────┐
  │ Bit7：warningIndicatorRequestedState                 │
  │ Bit6：testNotCompletedSinceLastClear                 │
  │ Bit5：testFailedSinceLastClear                       │
  │ Bit4：historyBit（历史故障）                          │
  │ Bit3：confirmedDTC（确认故障，连续2次点火循环触发）     │
  │ Bit2：pendingDTC（当前点火循环首次检测到）             │
  │ Bit1：testCompletedThisMnemonics                     │
  │ Bit0：testFailedThisOperation（当前运行周期测试失败）  │
  └─────────────────────────────────────────────────────┘

  DTC 快照数据（Freeze Frame）：
  └── 故障发生时刻的关键环境数据（车速/转速/温度/电压等）

  DTC 存储要求（座舱SoC）：
  ├── 非易失性存储（eMMC/UFS RPMB 分区）
  ├── 至少保存 20~50 条 DTC 历史记录
  └── 掉电保持：15年/15000次上电循环
```

## 13.3 DoIP 以太网诊断

### 13.3.1 DoIP 协议架构（ISO 13400）

```
DoIP（Diagnostics over IP）协议栈

  ┌─────────────────────────────────────────────────────────┐
  │  诊断工具（PC/VCI）              车辆网关（座舱SoC/ADAS）  │
  │                                                          │
  │  DoIP Client ───────────────────── DoIP Server           │
  │                                                          │
  │  传输层：TCP（诊断数据）/ UDP（发现/声明）                  │
  │  网络层：IPv4 / IPv6（支持 DHCP/AutoIP）                  │
  │  数据链路：Automotive Ethernet（100/1000BASE-T1）         │
  └─────────────────────────────────────────────────────────┘

DoIP 报文结构（通用头部）：
  [版本 1B][~版本 1B][载荷类型 2B][载荷长度 4B][载荷 xB]

关键载荷类型（Payload Type）：
  0x0001  UDP Vehicle Identification Request
  0x0004  UDP Vehicle Announcement / Identification Response
  0x0005  Routing Activation Request（建立诊断通道）
  0x0006  Routing Activation Response
  0x8001  Diagnostic Message（携带 UDS 请求/响应）
  0x8002  Diagnostic Message Positive ACK
  0x8003  Diagnostic Message Negative ACK

连接端口：
  ├── UDP：13400（车辆发现/广播）
  └── TCP：13400（诊断会话，可靠传输）

DoIP 建立诊断通道流程：
  1. 广播 UDP 发现请求 → 找到车辆 IP 和 EID
  2. 建立 TCP 连接到端口 13400
  3. 发送 Routing Activation Request（含源地址/逻辑地址）
  4. 收到 Routing Activation Response（0x10 成功）
  5. 通过 Diagnostic Message 发送 UDS 请求
```

## 13.4 SOVD（面向服务的车辆诊断）

```
SOVD（ISO/CD 22900-3）架构

  传统 UDS 诊断局限性：
  ├── 二进制协议，需要ODX（ASAM MCD-2D）配置文件
  ├── 诊断工具重，客户端软件复杂
  └── 不适合 OTA/云端集成

  SOVD 革新：
  ├── 基于 HTTP/REST API，JSON/CBOR 数据格式
  ├── 浏览器/App 均可直接访问车辆诊断接口
  ├── 无需ODX文件，自描述 API（OpenAPI Specification）
  └── 支持车内局域网和远程云端两种访问模式

  SOVD 核心接口（RESTful）：
  GET  /Nodes                      # 获取所有 ECU 节点
  GET  /Nodes/{nodeId}/Capabilities # 获取能力列表
  GET  /Nodes/{nodeId}/Faults       # 读取故障信息
  DEL  /Nodes/{nodeId}/Faults       # 清除故障
  GET  /Nodes/{nodeId}/Data/{dataId}# 读取数据项
  PUT  /Nodes/{nodeId}/Data/{dataId}# 写入数据项
  POST /Nodes/{nodeId}/Procedures/{procId} # 执行诊断程序

  SOVD ↔ UDS 网关：
  └── SOVD Server 内置 UDS 转换器，向后兼容现有 UDS ECU
```

## 13.5 远程诊断（RDE / 云端诊断）

### 13.5.1 远程诊断系统架构

```
远程诊断（Remote Diagnostics）端到端架构

  车端：
  ┌──────────────────────────────────────────────────────┐
  │  座舱SoC                                              │
  │  ├── 诊断代理（Diagnostic Agent）                     │
  │  │   ├── 定期上报：DTC状态、传感器健康度               │
  │  │   ├── 异常触发：实时故障推送（5G/4G）               │
  │  │   └── 接收远程指令：ECU Reset / 数据采集请求        │
  │  └── 安全通道：TLS 1.3 + 证书双向认证                  │
  └──────────────────────────────────────────────────────┘
           ↕  4G LTE / 5G NR（优先 MCX/MQTT/HTTPS）
  云端：
  ┌──────────────────────────────────────────────────────┐
  │  远程诊断平台（Cloud RDE Platform）                   │
  │  ├── 设备接入网关（Vehicle Gateway）                  │
  │  ├── 消息中间件（MQTT Broker / Kafka）                 │
  │  ├── 诊断数据仓库（DTC历史 / 传感器时序数据）           │
  │  ├── 故障分析引擎（AI/ML 故障聚类 + 根因分析）           │
  │  └── 诊断工程师工作台（Web UI + SOVD API）            │
  └──────────────────────────────────────────────────────┘

数据上报策略：
  ├── 实时模式（EVENT）：DTC触发后 30s 内上报
  ├── 周期模式（PERIODIC）：每次下电前批量上报
  └── 按需模式（ON_DEMAND）：云端主动发起数据采集请求
```

### 13.5.2 数据安全与合规

```
远程诊断数据安全要求

  UN R155 合规（网络安全法规）：
  ├── 远程诊断通道须经过 VSOC（Vehicle Security Operation Center）审计
  ├── 所有远程指令须经签名验证，防止中间人攻击
  └── 诊断会话日志须保留 ≥ 3年（溯源需求）

  数据隐私（GDPR/中国个保法）：
  ├── 位置数据、驾驶行为不得未授权上报
  ├── 匿名化处理：上报数据中 VIN 脱敏（哈希处理）
  └── 用户知情同意：远程诊断功能须在车机端明确提示

  通信安全：
  ├── TLS 1.3（禁止 TLS 1.0/1.1/SSL）
  ├── 证书：ECC P-256 或更高，OEM CA 体系颁发
  └── 防重放：每条指令带时间戳 + Nonce，有效期 30s
```

## 13.6 数据记录（黑匣子/EDR）

### 13.6.1 EDR 事件数据记录器

```
EDR（Event Data Recorder）法规要求

  法规背景：
  ├── 美国：49 CFR Part 563（NHTSA EDR 法规，2012年强制）
  ├── 中国：GB 39732-2020《汽车事件数据记录系统》（2022年强制）
  └── 欧盟：EU 2019/2144（2022年起新车强制要求）

  GB 39732-2020 记录内容（必选项）：
  ┌─────────────────────────────────────────────────────┐
  │  纵向加速度（-50g ~ +50g，100Hz）                    │
  │  车速（0~200km/h）                                   │
  │  制动状态（踩踏 / 未踩）                               │
  │  安全带状态（各座位）                                   │
  │  安全气囊展开状态                                      │
  │  发动机转速 / 油门位置                                  │
  │  转向盘转角（-720° ~ +720°）                           │
  └─────────────────────────────────────────────────────┘
  记录时间窗：碰撞前 5.0s ~ 碰撞后 0.3s（共 5.3s）

EDR 在座舱SoC中的实现：
  ├── 安全岛 MCU 直接读取传感器（最高实时性，ASIL-B）
  ├── 使用 ECC SRAM 缓冲 + NOR Flash 掉电保存
  ├── 数据格式：符合 GB 39732 或 SAE J1698 标准
  └── 数据接口：通过 UDS 0x22/0x19 服务读取（专用 DID）
```

### 13.6.2 扩展数据记录（DSSAD/行驶数据记录仪）

```
DSSAD（Data Storage System for Automated Driving）
  适用于 L3+ 自动驾驶，UN R157 要求

  记录触发条件：
  ├── 自动驾驶激活/停用事件
  ├── 驾驶员接管请求及响应时间
  ├── 系统故障导致降级事件
  └── 碰撞/险情事件

  保存时长：最少 5 秒（碰撞前3s + 碰撞后2s）

行驶数据记录仪（行车记录仪升级版）：
  ├── 支持 4K 60fps 前/后/内三路视频
  ├── 座舱SoC集成ISP处理，降低功耗（vs 独立模组）
  ├── 视频加密存储（AES-256，防篡改）
  └── 云端备份：通过 4G/5G 自动上传（如用户授权）
```

## 13.7 诊断子系统软件架构

```
座舱SoC 诊断软件分层架构

  ┌─────────────────────────────────────────────────────────┐
  │  诊断应用层                                               │
  │  ├── OEM 诊断应用（DTC监控/主动诊断任务）                  │
  │  └── SOVD Server（HTTP REST API，暴露诊断能力）            │
  ├─────────────────────────────────────────────────────────┤
  │  AUTOSAR Adaptive DCM（诊断通信管理）                     │
  │  ├── UDS 服务分发（SID路由 → 各功能模块）                  │
  │  ├── DoIP Transport Plugin                               │
  │  └── DEM（诊断事件管理器）：DTC存储/状态管理               │
  ├─────────────────────────────────────────────────────────┤
  │  AUTOSAR Classic（安全岛/实时MCU）                        │
  │  ├── COM（通信栈）：CAN TP / Lin TP                       │
  │  ├── DCM：UDS 服务处理                                    │
  │  └── DEM：ASIL-B 安全相关 DTC 管理                        │
  ├─────────────────────────────────────────────────────────┤
  │  传输层                                                   │
  │  ├── DoIP（以太网，主要通道）                               │
  │  ├── ISO 15765-2（CAN TP，兼容传统工具）                   │
  │  └── K-Line（仅旧车型兼容，新设计不使用）                   │
  └─────────────────────────────────────────────────────────┘
```

---

> ⚠️ **安全提示**：SecurityAccess（0x27）密钥算法须由OEM保密管理，禁止硬编码于固件中。远程诊断通道需通过 UN R155 威胁分析（TARA）评审，确保不被攻击者利用作为入侵入口。
